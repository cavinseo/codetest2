# AI를 위한 소프트웨어 공학적 사전 정의 가이드라인

AI가 단순히 동작하는 코드를 넘어, 안정적이고 효율적이며 유지보수가 쉬운 코드를 작성하게 하려면 다음과 같은 항목들을 사전에 명확히 "계약(Contract)"하듯이 정의해 주어야 합니다.

## 1. 아키텍처 및 디자인 패턴 (Architecture & Patterns)
AI에게 코드의 구조적 틀을 제시하면 스파게티 코드를 방지할 수 있습니다.
- **아키텍처 모델**: (예: Clean Architecture, Layered Architecture)
- **디자인 패턴**: (예: Singleton, Factory, Repository 패턴 사용 여부)
- **폴더 구조**: 각 기능별 파일의 물리적 위치 정의

## 2. 코딩 표준 및 스타일 (Coding Standards)
코드의 가독성과 일관성을 보장합니다.
- **네이밍 컨벤션**: (예: 변수는 camelCase, 클래스는 PascalCase)
- **버전 명시**: (예: Python 3.12, Node.js 20, Library X v5.1)
- **타입 정의**: (예: TypeScript의 경우 `any` 사용 금지, Interface 우선 사용)

## 3. 기술 스택 및 라이브러리 (Tech Stack & Utils)
불필요한 중복 구현을 방지하고 표준화를 유도합니다.
- **핵심 라이브러리**: 사용해야 할 라이브러리와 지양해야 할 라이브러리 명시
- **공통 유틸리티**: 프로젝트 내 이미 구현된 공통 함수 리스트 공유

## 4. 에러 핸들링 및 로깅 정책 (Error & Logging)
문제 발생 시 디버깅 효율을 극대화합니다.
- **예외 처리 규칙**: 특정 에러 상황에서 던질 에러 클래스와 catch 방식
- **로깅 표준**: 로그 레벨(Debug, Info, Warn, Error)과 출력 형식(JSON 등)

## 5. 테스트 및 검증 전략 (Testing & Quality)
코드의 안정성을 담보하는 최소한의 안전장치입니다.
- **테스트 환경**: (예: Jest, Pytest 사용법)
- **작성 기준**: "모든 Public 메서드에 대해 유닛 테스트 작성"과 같은 구체적 지시

## 6. 보안 및 성능 제약 (Security & Performance)
최적화된 코드를 위한 가이드입니다.
- **보안 수칙**: 하드코딩 금지(환경변수 사용), SQL Injection 방지 패턴
- **성능 목표**: (예: "API 응답은 200ms 이내", "루프 내 불필요한 연산 제거")

## 7. 문서화 및 주석 (Documentation)
지식 전수와 재사용을 용이하게 합니다.
- **주석 문법**: (예: JSDoc, Docstring 포맷 준수)
- **변경 관리**: 코드 수정 시 README 또는 기술 문서 업데이트 절차
