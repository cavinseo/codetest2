## 역할별 읽는 순서

| 역할 | 순서 |
| --- | --- |
| 관리자 | 1부 → 2부 → 3부 → 12부 → 부록 |
| 프로그램 매니저 | 1부 → 2부 → 4부 → 7부 → 12부 |
| 멘티 | 2부 → 5부 → 7부 → 8부 → 9부 |
| 멘토 | 2부 → 6부 → 7부 → 8부 |

처음 도입하는 조직이라면 1부와 3부를 먼저 읽고, 프로그램 개설과 멘티 초대까지
마친 뒤 5부를 멘티에게 배포하는 순서를 권한다.

## 표기 규칙

- 화면에 보이는 버튼·탭·라벨은 `굵게` 대신 큰따옴표로 감싼다. 예를 들어 "승인 신청"
  버튼을 누른다고 적는다.
- 화면 주소는 `/admin`, `/project/{프로젝트ID}/qfd` 처럼 적는다. 중괄호 부분은 실제
  값으로 바뀐다.
- 워크시트는 화면 메뉴와 같은 번호로 부른다. 예를 들어 WS-9 QFD 라고 적는다.
  WS-8 은 결번이며 그 이유는 1부에 적었다.
- 오류 문구는 화면에 뜨는 그대로 인용한다. 문구가 바뀌면 이 문서도 함께 고쳐야 한다.
- "관리자"는 시스템 역할 ADMIN 을 말한다. 프로젝트 안의 역할과는 다르며 둘의 구분은
  1부에 정리했다.

## 이 문서의 한계

- 화면 캡처는 넣지 않았다. 캡처가 필요한 자리에는 `> 화면 캡처 자리` 표시를 두었다.
- 운영 환경의 실제 데이터로 화면을 띄워 확인한 문서가 아니다. 저장소의 화면 코드와
  API 코드를 근거로 작성했다.
- 화면 문구가 코드와 달라 보이면 코드가 바뀐 것이다. 부록 E 의 문서 이력에 갱신
  기록을 남기고 본문을 고친다.
