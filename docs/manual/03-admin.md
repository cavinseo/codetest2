# 3부. 관리자 매뉴얼

관리자는 회원과 프로그램, 프로젝트 전체를 다룬다. 이 부는 `/admin` 화면과 `/settings`
서비스 설정 화면을 다룬다.

## 3.1 관리자 화면에 들어가기

관리자 모드는 별도 계정이 아니라 일반 계정에 붙는 권한이다. `/admin` 으로 들어가면
화면이 스스로 권한을 확인하고 세 가지 중 하나를 보여 준다.

| 상태 | 화면 |
| --- | --- |
| 로그인하지 않았다 | 주소를 바꾸지 않은 채 관리자 로그인 폼을 그 자리에 띄운다 |
| 로그인했지만 관리자가 아니다 | "관리자 권한이 없습니다" 차단 화면 |
| 관리자다 | 관리자 화면 |

차단 화면에는 "지금 로그인한 계정은 관리자로 지정되어 있지 않습니다." 와 "관리자
계정으로 다시 로그인하거나 일반 화면으로 돌아가세요." 가 뜨고, "관리자 계정으로
로그인" 과 "일반 화면으로 돌아가기" 버튼이 있다.

### 관리자 로그인 폼

제목은 "관리자 모드", 부제는 "관리자 권한이 있는 계정으로 로그인하세요" 다. 위쪽에
경고가 하나 붙는다.

> 관리자 모드에서는 사용자와 프로젝트를 영구 삭제할 수 있습니다. 신중히 사용하세요.

"관리자 ID" 와 "비밀번호" 를 넣고 "관리자 모드 입장" 을 누른다. 로그인에 성공하면
화면이 권한을 한 번 더 확인한다. 이때 권한이 없으면 "이 계정에는 관리자 권한이
없습니다. 관리자 계정으로 로그인하세요." 가 뜨고, 확인 자체가 실패하면 "관리자
권한을 확인하지 못했습니다. 잠시 후 다시 시도하세요." 가 뜬다.

`/admin/login` 도 같은 폼이며 성공하면 `/admin` 으로 옮겨 준다. 예전 링크를 위해
남겨 둔 경로다.

> 로그인은 되는데 관리자 화면만 열리지 않는다면 권한 값이 아니라 온보딩 관문에 걸린
> 것일 수 있다. [12.3](12-troubleshooting.md#123-관리자-계정비밀번호-복구)을 본다.

### 화면 상단

왼쪽에 "대시보드" 링크, 가운데에 "관리자모드" 와 "시스템 관리 및 분석", 오른쪽에
마지막 갱신 시각과 "새로고침" 버튼, 주간·야간 전환 버튼이 있다. 화면의 수치가
오래됐다 싶으면 "새로고침" 을 누른다.

### 탭 구성

| 탭 | 보이는 조건 |
| --- | --- |
| 개요 | 항상 |
| 회원 관리 (N) | 항상 |
| 초대 관리 | 관리자와 프로그램 매니저 |
| 프로그램 관리 | 관리자와 프로그램 매니저 |
| 프로젝트 관리 (N) | 항상 |
| 비밀번호 변경 | 항상 |

괄호 안 숫자는 각각 회원 수와 프로젝트 수다.

## 3.2 개요 탭

### 통계 카드

"총 프로젝트", "총 사용자", "총 요구사항", "총 설문 응답" 네 장이 보인다.

### Kano 카테고리 분포

전체 설문 응답을 6 분류로 집계해 보여 준다. "M · Must-be", "O · One-Dim",
"A · Attractive", "I · Indifferent", "R · Reverse", "Q · Question" 순이며, 아래에
"분석: 전체 N개의 응답이 수집되었습니다." 가 붙는다. 분류의 뜻은
[부록 D](13-appendix.md)에 있다.

### 최근 프로젝트

최근 5 건이 보이고 누르면 그 프로젝트로 이동한다. 없으면 "프로젝트가 없습니다" 다.

### 시스템 정보

"저장소", "버전", "환경", "상태" 네 줄이 보인다. **이 네 값은 화면에 고정된 표시이며
실제 서버 상태를 검사한 결과가 아니다.** 장애 판단의 근거로 쓰지 않는다.

### 빠른 이동

"회원 관리" 와 "프로젝트 관리" 카드를 누르면 해당 탭으로 넘어간다.

## 3.3 회원 관리 탭

### 목록 보기

검색창에 이름이나 이메일 일부를 넣어 거를 수 있다. 위쪽 역할 필터는 "전체",
"관리자", "프로그램 매니저", "멘토", "멘티" 이며 각각 건수가 함께 나온다.

표의 열은 다음과 같다.

| 열 | 내용 |
| --- | --- |
| 사용자 | 이름과 이메일. 이름이 없으면 "이름 미등록", 관리자면 "관리자" 배지, 임시 비밀번호 상태면 "비밀번호 변경 필요" 배지 |
| 역할 | 멘토와 매니저는 바꿀 수 있는 선택 상자. 멘티와 관리자는 "변경 불가" 로만 표시 |
| 프로그램 | 멘티만 해당. 선택 상자로 배정한다. 멘티가 아니면 `—` |
| 승인 상태 | "승인됨" 또는 "승인 대기" |
| 이용 만료 | 만료일 또는 "무기한" |
| 가입일 | 가입 날짜 |

### 승인과 승인 취소

승인 대기 계정의 행에는 "승인" 버튼이 있다. 승인된 계정에는 "승인 취소" 가 있다.
관리자 계정에는 승인 취소 버튼이 없다.

**승인 취소는 로그인뿐 아니라 이미 로그인해 둔 기기까지 즉시 끊는다.** 접근을 막는
것이 목적이라면 계정 삭제가 아니라 승인 취소를 쓴다. 데이터는 한 줄도 건드리지
않는다.

### 역할 변경

역할 선택 상자는 **멘토와 프로그램 매니저 사이에서만** 열린다. 매니저는 멘토 중에서
고르는 자리이고 물러나면 다시 멘토로 돌아가기 때문이다. 관리자와 멘티는 "변경 불가"
로 표시되며 이 화면에서 바꿀 수 없다.

역할을 낮추는 변경도 기존 세션을 끊는다.

### 이용 기간 연장

이용 만료가 있는 계정에만 "90일 연장" 버튼이 보인다. 무기한 계정에는 나오지 않는다.
누르면 현재 기한(이미 지났으면 오늘)부터 90 일을 더한다. 연장 결과가 오히려 짧아지는
경우에는 세션을 끊는다.

초대 관리 화면에서 같은 사람의 기한을 동시에 바꿨다면 "이용 기한이 변경되었습니다.
새로고침 후 다시 시도하세요." 가 뜬다. 목록을 새로 고친 뒤 다시 한다.

### 멘토의 프로젝트 개설 허용

멘토 행에만 버튼이 하나 더 있다. 현재 상태에 따라 "프로젝트 생성 사용중지 · 활성화"
또는 "프로젝트 생성 허용 중 · 비활성화" 로 보인다. 허용하면 그 멘토가 배정 멘티의
과제를 대신 열 수 있다. 기본값은 사용중지다.

### 프로그램 배정

멘티 행의 프로그램 선택 상자로 배정한다. 그 멘티가 이미 다른 프로그램에 속해 있으면
확인 창이 한 번 더 뜬다.

> {이름} 님은 이미 "{현재 프로그램}" 프로그램에 속해 있습니다. 그래도 이 프로그램으로
> 옮기시겠습니까?

배정을 옮기면 그 멘티에게 연결된 초대 코드의 프로그램도 함께 바뀐다.

### 멘토·멘티 계정 직접 만들기

"계정 생성" 을 누르면 폼이 열린다. 만들 수 있는 역할은 **멘티와 멘토 둘뿐이다.**
관리자와 매니저는 이 폼으로 만들지 않는다.

| 입력 | 설명 |
| --- | --- |
| 이름 | 필수 |
| ID | 이메일 주소 |
| 역할 | 멘티 또는 멘토 |
| 프로그램 (선택) | 역할이 멘티일 때만 나온다. "지정 안 함" 으로 둘 수 있다 |

이어서 프로필을 받는다. 공통으로 소속기관명(멘티는 담당기관명)과 휴대폰이 필수이며,
멘토는 전문분야와 경력 연수가, 멘티는 기업명과 업종이 추가로 필수다.

마지막에 "본인에게 개인정보 수집·이용 동의를 받았습니다." 체크가 있다. 이름과 ID,
이 체크 중 하나라도 비면 "계정 만들기" 버튼이 눌리지 않는다.

**임시 비밀번호 처리에서 반드시 알아 둘 것이 있다.**

- 서버가 임시 비밀번호를 만들어 **본인 이메일로만** 보낸다. 화면에도 로그에도 남지
  않으므로 관리자가 볼 수 없다.
- 만들어진 계정은 승인된 상태로 시작하고 목록에 "비밀번호 변경 필요" 배지가 붙는다.
  본인이 첫 로그인에서 비밀번호를 바꿔야 다음 화면으로 넘어간다.
- 이 폼으로 만든 계정은 **이용 기간이 무기한**이다. 따라서 "90일 연장" 버튼도 보이지
  않는다. 기한을 두려면 초대 코드로 받는 편이 맞다.
- **메일 발송이 실패하면 임시 비밀번호를 다시 보낼 방법이 없다.** 이때는 "계정은
  생성되었지만 임시 비밀번호 메일 발송에 실패했습니다. 이 계정을 삭제하고 다시 만들어
  주세요." 가 뜬다. 안내 그대로 지우고 다시 만든다. 그 전에 SMTP 설정부터 고친다.

### 계정 삭제

삭제는 되돌릴 수 없다. **접근 차단이 목적이면 쓰지 않는다.** 절차와 판단 기준은
[12.4](12-troubleshooting.md#124-멘티-계정-삭제-운영-지침)에 자세히 적었다.

요약하면 이렇다. "삭제" 를 누르면 1 차 확인이 뜨고, 여기서 한 번 더 누르면 서버가
무슨 일이 벌어질지 계산해 "마지막 확인" 창에 보여 준다. 멘티라면 어느 프로젝트가
누구에게 넘어가는지, 이력 몇 건의 주인이 비워지는지, 초대 코드 몇 건이 지워지는지가
나온다. 삭제 사유를 고르기 전에는 확정 버튼이 눌리지 않는다. "뒤로" 로 되돌아갈 수
있다.

- **멘티**를 지우면 소유하던 프로젝트는 지워지지 않고 그 프로그램의 매니저에게
  넘어간다.
- **멘토와 매니저**를 지우면 소유한 프로젝트가 함께 삭제된다. 다른 참여자의 작업물도
  사라지므로 확인 문구를 끝까지 읽는다.
- **프로그램 담당자**는 지울 수 없다. "담당 중인 프로그램이 있어 삭제할 수 없습니다.
  프로그램 담당자를 먼저 다른 사람으로 옮기세요." 가 뜬다.
- **마지막 관리자 계정**은 지울 수 없다.
- 본인 계정도 지울 수 없다.

## 3.4 초대 관리 탭

멘티를 초대 코드로 모집하는 화면이다. 관리자와 프로그램 매니저가 쓴다.

### 초대 코드 발행

"멘티 초대 코드 발행" 폼에 세 가지를 넣는다.

| 입력 | 설명 |
| --- | --- |
| 초대할 이메일 | 여러 줄로 여러 명을 한 번에 넣는다 |
| 프로그램 | 이 코드로 들어올 멘티가 참여할 프로그램 |
| 이용 기한 (필수) | 날짜를 고른다. 오늘 이후, 프로그램 종료일 이내만 고를 수 있다 |

이메일은 **줄바꿈, 공백, 쉼표, 세미콜론 아무 것으로나 구분해 최대 100 명까지** 넣을
수 있다. 소문자로 맞춰지고 중복은 자동으로 걸러진다. 잘못된 주소가 섞여 있으면 폼
아래에 "잘못된 이메일은 발급에서 제외됩니다." 와 함께 목록이 뜨고, 중복이 있으면
"중복 이메일 N개를 제외했습니다." 가 뜬다.

버튼에는 실제 발급될 인원이 "초대 코드 발급·발송 (N명)" 으로 표시된다.

이용 기한을 잘못 고르면 다음 중 하나가 뜬다.

| 문구 | 뜻 |
| --- | --- |
| 이용 기한을 입력하세요. | 비워 두었다 |
| 올바른 이용 기한 날짜를 입력하세요. | 날짜 형식이 아니다 |
| 한국 시간 오늘 이후 날짜를 선택하세요. | 과거 날짜다 |
| 프로그램 종료일 이내 날짜를 선택하세요. | 프로그램이 먼저 끝난다 |

기한은 **한국 시간 기준으로 선택한 날짜의 끝까지**이며, 프로그램이 먼저 끝나면 그
종료 시각까지다. 이 코드로 가입한 멘티는 선택한 프로그램에만 참여할 수 있다.

프로그램이 하나도 없으면 "초대 코드를 발행하려면 먼저 프로그램을 개설하세요." 가
뜬다. 프로그램 개설이 먼저다.

### 일괄 발급의 진행과 결과 읽기

이메일 하나씩 차례로 처리하며, 결과가 나올 때마다 "처리 결과 (N/총)" 에 한 줄씩
쌓인다. 줄마다 다음 중 하나가 붙는다.

| 결과 문구 | 뜻과 조치 |
| --- | --- |
| 코드 발급 및 메일 발송 완료. | 정상이다 |
| 코드 발급 완료 · 메일 발송 실패. 코드를 직접 전달하세요. | 코드는 만들어졌다. 목록에서 코드를 확인해 직접 알려 준다 |
| 코드 발급 완료 · 메일 발송 실패. 목록에서 메일을 재발송하거나 관리자에게 문의하세요. | 매니저에게는 코드가 보이지 않으므로 재발송을 쓴다 |
| 처리 결과를 확인하지 못했습니다. 목록을 새로고침해 확인하세요. | 서버 응답을 읽지 못했다. 목록에서 실제 상태를 본다 |
| 처리 결과를 확인하지 못했습니다. 연결 상태와 초대 목록을 확인하세요. | 통신이 끊겼다. 자동으로 다시 시도하지 않는다 |

끝나면 실패한 주소와 잘못된 주소만 입력창에 되돌아온다. 그대로 고쳐서 다시 실행하면
된다. 마지막에 "메일 발송 N건 · 코드 발급 완료, 메일 미발송 N건 · 실패 N건. 이메일별
결과를 확인하세요." 요약이 뜬다.

발급이 막히는 대표적인 경우는 다음과 같다.

| 문구 | 원인 |
| --- | --- |
| 이미 가입된 이메일입니다. | 그 주소로 이미 회원이 있다 |
| 이미 발행된 유효한 초대 코드가 있습니다. | 아직 살아 있는 코드가 있다. 새로 내지 말고 재발송을 쓴다 |
| 종료된 프로그램의 초대 기한은 지정할 수 없습니다. | 프로그램이 이미 끝났다 |

### 목록과 상태

표의 열은 이메일, 초대코드, 프로그램, 기한, 상태다. 최근 발급 순으로 정렬된다.

- **초대코드 열은 관리자에게만 실제 코드가 보인다.** 프로그램 매니저에게는 "관리자만
  열람 가능" 으로 표시된다. 매니저는 코드를 직접 읽을 수 없으므로 전달이 필요하면
  메일 재발송을 쓴다.
- 상태는 "사용됨", "만료", "대기" 셋 중 하나다.

### 이용 기한 연장

기한 날짜를 누르면 그 자리가 날짜 입력으로 바뀐다. 날짜를 고르고 "저장" 을 누르거나
"취소" 로 되돌린다. 성공하면 "이용 기한을 연장했습니다." 가 뜬다.

연장에는 규칙이 있다.

- **현재 기한보다 늦은 날짜만** 저장된다. 앞당길 수 없다.
- 프로그램 종료일을 넘길 수 없다.
- 이미 사용된 코드라면 연결된 멘티 계정의 이용 기한도 같은 작업에서 함께 늘어난다.
- 아직 쓰지 않은 코드인데 그 이메일로 이미 승인된 멘티가 있고 다른 코드에 연결되지
  않았다면, 저장하면서 그 계정을 이 코드에 연결하고 기한을 함께 기록한다. 직접 가입한
  멘티를 초대에 이어 붙이는 통로이며 자세한 절차는
  [12.1](12-troubleshooting.md#121-로그인가입-오류-사례집)에 있다.
- 멘티에게 이미 더 긴 기한이 있으면 줄이지 않는다. "현재 멘티 이용 기한보다 이른
  날짜로 변경할 수 없습니다." 가 뜬다.

### 메일 재발송

만료되지 않은 행에만 "메일 재발송" 이 보인다. 기존 코드를 다시 보내는 것이며
**기한을 늘리지 않는다.** 메일 본문에도 "메일 재발송으로 기존 이용 기한이 연장되지는
않습니다." 라고 적혀 나간다.

실패하면 "메일 발송에 실패했습니다. SMTP 설정을 확인하고 다시 시도하세요." 가 뜬다.

### 회수

아직 쓰지 않았고 만료되지도 않은 코드에만 "회수" 가 보인다. 확인 창은 "이 코드를
회수하시겠습니까? 기록은 남습니다." 다.

**회수는 삭제가 아니라 즉시 만료 처리다.** 목록에서 사라지지 않고 "만료" 상태로
남는다. 이미 사용된 코드는 회수할 수 없다.

## 3.5 프로그램 관리 탭

### 프로그램 개설

"프로그램 개설" 을 누르면 폼이 열린다. **프로그램 개설은 관리자만 할 수 있다.**

| 입력 | 설명 |
| --- | --- |
| 담당 프로그램 매니저 | 개설할 때만 고른다. "관리자 본인이 담당" 으로 둘 수 있다 |
| 프로그램명 | 예를 들어 2026 하반기 스타트업 육성 |
| 주관기관명 | 예를 들어 가나기술원 |
| 시작일 · 종료일 | 운영 기간 |

네 칸이 모두 차야 "개설하기" 가 눌린다. 종료일은 시작일보다 뒤여야 한다.

**담당자는 개설할 때만 정할 수 있다.** 나중에 "내용 수정" 으로 들어가면 담당자 칸이
나오지 않으며 이름·기관·기간만 고칠 수 있다.

### 프로그램 수정

카드의 "내용 수정" 을 누르면 폼에 현재 값이 채워진다. 운영 기간을 바꿀 때 주의할
점이 화면에도 적혀 있다.

> 운영 기간을 바꾸면 연결된 멘티와 초대코드의 이용 기한에도 적용됩니다.

프로그램 종료일은 모든 이용 기한의 상한이므로, 종료일을 앞당기면 그 뒤로 잡혀 있던
멘티의 접근이 함께 끊긴다.

### 멘티 배정

카드의 "멘티 배정" 을 열면 배정할 수 있는 멘티 목록이 나온다. **승인된 멘티만**
후보에 나오므로, 승인 대기 계정은 회원 관리에서 먼저 승인해야 한다. 이미 다른
프로그램에 속한 멘티를 고르면 확인 창이 한 번 더 뜬다.

### 프로젝트 불러오기

다른 프로그램에 있는 프로젝트를 이 프로그램으로 옮긴다. 이미 이 프로그램에 속한
프로젝트는 후보에서 빠져 있다. 다른 프로그램 소속이면 확인 창을 거친다.

### 프로그램 삭제

**삭제는 관리자만 할 수 있고 복구할 수 없다.** "프로그램 삭제" 를 누르면 서버가 연결
상태를 확인해 보여 준다.

- 요약으로 "연결된 프로젝트 N개 · 멘티 N명" 이 나온다.
- 지울 수 있으면 "초대코드 N개와 추가 프로젝트 신청 이력 N건도 함께 삭제됩니다." 가
  붙는다.
- 지울 수 없으면 이유가 노란 글씨로 나온다.

지울 수 없는 이유는 두 가지다.

| 문구 | 조치 |
| --- | --- |
| 프로젝트 N개와 멘티 N명을 다른 프로그램으로 먼저 옮겨 주세요. | 프로젝트 불러오기와 멘티 배정으로 옮긴다 |
| 사용된 초대코드 N개가 연결되어 있습니다. 멘티의 로그인과 이용 기한을 보존하기 위해 삭제할 수 없습니다. | 이 프로그램은 지울 수 없다. 종료일을 지난 상태로 두고 남긴다 |

확인 창을 열어 둔 사이에 건수가 바뀌면 "삭제할 초대코드 또는 신청 이력이
변경되었습니다. 변경된 건수를 확인한 뒤 다시 삭제해 주세요." 가 뜬다. 다시 확인한다.

## 3.6 프로젝트 관리 탭

전체 프로젝트를 목록으로 본다. 이름이나 소유자로 검색할 수 있고 "전체 프로그램"
선택 상자로 프로그램별로 거를 수 있다.

카드마다 이름과 설명, 소유자, 요구사항·응답·멤버 수, 생성일이 나오고 버튼이 붙는다.

| 버튼 | 설명 |
| --- | --- |
| 보기 | 그 프로젝트를 연다 |
| 멘토 배정 | 이 프로젝트 멘티의 담당 멘토를 지정한다. 3.7 참고 |
| 멘티 변경 | 소유권을 다른 멘티에게 넘긴다. 관리자만 |
| 삭제 | 프로젝트와 모든 데이터를 지운다 |

### 프로젝트 삭제

2 단계 확인을 거친다. 마지막 확인에서 함께 지워지는 것을 보여 준다.

> 요구사항 N개 · Kano 응답 N개 · 참여 멤버 N명의 접근 권한 · QFD 행렬·기술특성·설문
> 초대 전체

되돌릴 수 없다. 작업물을 남기고 싶으면 먼저 [9부](09-data-import-export.md)의
내보내기를 쓴다.

### 소유권 이전(멘티 변경)

"멘티 변경" 은 프로젝트를 다른 멘티에게 통째로 넘기는 기능이다. 관리자만 쓸 수 있다.

순서는 이렇다.

1. "새 소유자 멘티" 를 고른다. 승인되고 이용 기간이 남았으며 프로그램에 소속된
   멘티만 후보에 나온다.
2. "이관 영향 확인" 을 눌러 미리보기를 받는다. 소유자 변경, 프로젝트의 프로그램 변경
   여부, 양쪽 멘티의 담당 멘토가 어떻게 되는지가 나온다.
3. 영향을 읽고 동의 체크를 한 뒤 "최종 이관 실행" 을 누른다.

미리보기에서 꼭 읽어야 할 것이 있다.

- **대상 멘티의 다른 프로젝트에도 변경된 담당 멘토가 적용될 수 있다.** 이 프로젝트만
  바뀌는 것이 아니다.
- 원래 소유자는 이 프로젝트의 소유자·팀원 접근 권한을 잃는다.
- 프로젝트 ID, 워크시트, 보고서, 의견, 개설 승인 정보는 보존된다.

미리보기를 받은 뒤 상황이 바뀌면 "이관 영향을 다시 확인하세요." 가 뜬다. 다시
확인하고 진행한다.

## 3.7 멘토 배정

배정하는 자리가 두 곳이다. 어느 쪽이든 **멘티 한 명의 담당 멘토는 한 명이고, 배정은
그 멘티의 모든 프로젝트에 적용된다.** 한 멘토가 여러 멘티를 맡을 수는 있다.

### 프로그램 단위 일괄 배정

프로그램 관리 탭의 각 프로그램 카드에서 "멘토 배정 관리" 를 연다. 매니저 화면에서는
"멘토 배정" 탭에서 프로그램을 고른 뒤 같은 화면을 쓴다.

1. 위쪽에서 멘토를 고른다. 후보는 승인되고 이용 기간이 남은 멘토와 프로그램
   매니저다.
2. 멘티를 체크한다. "멘티 전체 선택" 으로 한 번에 고를 수 있다.
3. "선택한 N명에게 배정" 을 누른다. 이미 같은 멘토가 배정된 멘티는 N 에서 빠진다.

기존 멘토가 있는 멘티가 섞여 있으면 "{이름 목록}의 기존 멘토를 교체하시겠습니까?
선택하지 않은 멘티의 배정은 유지됩니다." 확인을 한 번 더 받는다.

멘티 줄의 "해제" 로 개별 배정을 풀 수 있다. 계정은 지워지지 않는다.

일부만 실패하면 "처리하지 못한 항목을 확인한 후 다시 시도하세요." 와 함께 실패한
멘티와 사유가 나온다. 성공한 배정은 그대로 남으므로 실패분만 다시 하면 된다.

### 프로젝트 카드에서 배정

프로젝트 관리 탭에서 "멘토 배정" 을 열면 그 프로젝트 소유 멘티의 담당 멘토를 바로
지정할 수 있다. 기존 멘토가 있으면 "기존 멘토를 교체하시겠습니까? 이 멘티에 대한
기존 멘토 배정이 해제됩니다." 를 거친다.

배정 권한이 없으면 "멘토 배정 권한이 없습니다." 가 뜬다. 매니저가 담당 밖 멘티를
배정하려 하면 "담당 프로그램의 멘티만 배정할 수 있습니다." 가 뜬다.

## 3.8 추가 프로젝트 개설 승인

멘티는 프로젝트를 1 개까지 직접 열 수 있고, 그 이상은 승인을 받아야 한다. 신청은
프로그램 관리 탭 맨 위의 "추가 프로젝트 개설 승인 관리" 에서 처리한다.

신청 줄에는 "{멘티 이름} · {프로그램명} — {신청 사유}" 와 상태가 나온다. 상태는
"승인 대기", "승인됨", "반려됨", "사용 완료" 중 하나다. 심사 의견을 남겼으면 상태
뒤에 함께 표시된다.

- **승인**을 누르면 바로 처리된다. 사유를 적는 칸이 없다.
- **반려**를 누르면 "반려 사유를 입력하세요." 입력 창이 뜬다. 여기서 취소하면 아무
  것도 보내지 않는다. 사유는 신청자에게 그대로 보인다.

승인된 권한은 멘티가 프로젝트를 한 번 열면 "사용 완료" 가 된다. 한 번 승인에 한 번
개설이다.

담당 프로그램의 신청만 처리할 수 있다. 다른 프로그램의 신청을 처리하려 하면 "담당
프로그램의 신청만 처리할 수 있습니다." 가 뜬다.

## 3.9 비밀번호 변경 탭

지금 로그인한 계정의 비밀번호만 바꾼다. "현재 비밀번호", "새 비밀번호", "새 비밀번호
확인" 세 칸을 채운다. 새 비밀번호는 **최소 8 자**이며 현재 비밀번호와 같으면 안 된다.

바꾸면 "비밀번호를 변경했습니다. 다른 기기의 로그인은 해제됩니다." 가 뜬다. 지금 쓰고
있는 창의 로그인은 유지되고 다른 기기만 끊긴다.

## 3.10 서비스 설정 화면

`/settings` 는 관리자 전용이다. 대시보드 헤더의 "🔗 서비스 설정" 으로 들어간다.
관리자가 아닌 계정이 주소로 접근하면 "권한이 없습니다" 화면과 함께 "서비스 설정은
관리자만 볼 수 있습니다. 내 AI 연결은 프로필 화면에서 설정할 수 있습니다." 가 뜬다.

왼쪽에 탭이 세 개 있다.

| 탭 | 부제 | 내용 |
| --- | --- | --- |
| 🔗 Google 연동 | OAuth, Forms | Google 로그인과 Google Forms 연동에 쓰는 자격증명 |
| 📧 이메일 (SMTP) | 설문 초대 발송 | 메일 발송 설정 |
| ⚡ AI 엔진 | 멘토링 기능 | 내 AI 연결 카드 |

설정이 끝난 탭에는 초록 점이 붙는다.

### Google 연동

상태 카드에 "연동됨" 또는 "미설정" 이 나오고, 연동됐으면 클라이언트 ID 가 일부만
가려진 형태로 보인다. **클라이언트 시크릿은 어떤 경우에도 화면으로 돌아오지 않는다.**

설정 폼에는 "📋 설정 방법" 안내가 여섯 단계로 들어 있다. Google Cloud Console 에서
프로젝트를 만들고, Google Forms API 를 켜고, OAuth 2.0 클라이언트 ID 를 만든 뒤,
**승인된 리디렉션 URI 에 화면이 보여 주는 주소를 그대로 등록**하고, 발급된 두 값을
아래 칸에 넣는 순서다. 리디렉션 주소는 지금 접속한 주소를 기준으로 표시되므로 화면에
나온 값을 복사해 쓴다.

"Client ID" 와 "Client Secret" 둘 다 채워져야 설정된 것으로 본다. 하나라도 비면
로그인 화면에서 Google 버튼을 눌렀을 때 "Google 로그인이 아직 설정되지 않았습니다.
관리자에게 문의하세요." 가 뜬다.

입력란을 **비워 둔 채 저장하면 그 값은 바뀌지 않는다.** 시크릿만 교체할 때 ID 를 다시
넣지 않아도 되도록 한 것이며, 반대로 값을 지우는 용도로는 쓸 수 없다.

### 이메일 (SMTP)

초대 코드, 설문 초대, 임시 비밀번호가 모두 이 설정으로 나간다.

| 항목 | 설명 |
| --- | --- |
| SMTP 호스트 | 메일 서버 주소 |
| 포트 | 기본값 587. **465 를 넣으면 보안 연결로 처리된다** |
| 이메일 주소 (계정) | 계정 주소. 발신자 표시에도 이 값을 쓴다 |
| 비밀번호 (앱 비밀번호) | 계정 비밀번호 또는 앱 전용 비밀번호 |

화면에 자주 쓰는 설정이 예시로 나와 있다.

| 서비스 | 호스트와 포트 | 비고 |
| --- | --- | --- |
| Gmail | smtp.gmail.com / 587 | 앱 비밀번호 필요 |
| Naver | smtp.naver.com / 587 | POP3/SMTP 사용 설정 필요 |
| Outlook | smtp.office365.com / 587 | 계정 비밀번호 사용 |
| Daum/Kakao | smtp.daum.net / 465 | SSL 사용 |

네 값 중 호스트·계정·비밀번호가 모두 있어야 설정된 것으로 본다. 하나라도 비면 서버는
메일을 보내지 않고 실패로 응답한다. Google 설정과 마찬가지로 빈 칸은 "바꾸지 않음"
으로 처리되며, 저장 후에는 비밀번호 칸만 비워진다.

아래 "📬 이메일 발송 기능" 카드에 SMTP 가 없을 때의 대안이 적혀 있다. 설문 초대는
메일 대신 링크가 만들어지므로 직접 복사해 전달할 수 있다.

메일이 나가지 않을 때의 점검 순서는 [12.2](12-troubleshooting.md#122-메일이-오지-않을-때)에 있다.

### AI 엔진

이 탭에는 **"내 AI 연결" 카드 하나만 있다.** 지금 로그인한 관리자 본인의 AI 연결을
설정하는 자리이며 서비스 전체에 걸리는 설정이 아니다. 같은 카드가 `/profile` 에도
있고 둘은 같은 값을 본다. 내용은 [10부](10-ai-features.md)에서 다룬다.

### 알아 둘 화면 문구 차이

Google 과 SMTP 설정 폼 아래에 "⚠️ 서버 메모리에만 저장되며, 재시작 시 다시 입력해야
합니다." 라는 경고가 붙어 있다. **이 문구는 지금 동작과 다르다.** 설정은
데이터베이스에 암호화해 저장되므로 서버를 다시 시작해도 남는다. 예전 구현의 문구가
그대로 남은 것이므로 이 경고를 보고 설정을 다시 입력할 필요는 없다.

## 3.11 운영을 시작하는 순서

새로 도입한다면 이 순서가 막히지 않는다.

1. `/settings` 에서 SMTP 를 설정한다. 메일이 나가야 초대가 의미가 있다.
2. 프로그램 관리에서 프로그램을 개설한다. 담당 매니저와 운영 기간을 정한다.
3. 멘토를 받는다. 멘토는 초대 코드로 모집하지 않으므로, 본인이 `/signup` 에서
   가입하게 한 뒤 회원 관리에서 승인하거나 계정 생성 폼으로 직접 만든다.
4. 초대 관리에서 멘티 이메일을 모아 초대 코드를 일괄 발급한다.
5. 멘티가 로그인해 계정이 생기면 프로그램 관리에서 멘토를 배정한다.
6. 멘티가 프로젝트를 열고 워크시트를 시작한다.
