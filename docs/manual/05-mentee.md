# 5부. 멘티 매뉴얼

멘티는 프로젝트를 만들고 워크시트를 작성한다. 이 부는 계정을 받는 것부터 프로젝트
설정까지를 다룬다. 워크시트 작성법은 [7부](07-worksheets.md)에 있다.

## 5.1 초대 메일부터 첫 로그인까지

### 메일로 받는 것

관리자나 프로그램 매니저가 초대하면 "[KS-QFD] 멘티 초대 코드 안내" 메일이 온다.
본문에는 초대 코드, 이용 기한, 로그인 링크가 들어 있다.

메일에는 이렇게 적혀 있다.

> 이메일과 초대 코드로 로그인해 주세요. 처음 로그인하면 계정이 생성되며, 이후에도
> 같은 코드로 로그인할 수 있습니다.

**회원가입을 따로 하지 않는다.** 로그인만 하면 계정이 만들어진다.

### 로그인하는 법

1. 메일의 링크를 누르거나 `/login` 으로 간다.
2. 위쪽 역할 버튼에서 **"멘티"** 를 고른다. 자동으로 "초대 코드 로그인" 방식이 된다.
   메일의 링크로 들어왔다면 이미 그렇게 맞춰져 있다.
3. 초대받은 **이메일 주소**와 **초대 코드**를 넣는다.
4. "초대 코드로 로그인" 을 누른다.
5. 처음이라면 이름을 묻는 칸이 나타난다. 이름을 넣고 "이름 등록하고 시작하기" 를
   누르면 계정이 만들어지면서 로그인된다.

코드는 대소문자와 하이픈 차이를 알아서 맞춘다. 메일에서 복사해 붙여 넣으면 된다.

**이용 기간 동안 같은 코드로 계속 로그인한다.** 코드는 한 번 쓰고 없어지는 것이
아니다.

### 하지 말아야 할 것

**초대 메일을 받았다면 회원가입 화면으로 가지 않는다.** 코드 없이 먼저 가입해 버리면
나중에 초대 코드 로그인이 막히고 "이메일과 초대 코드를 확인하세요. 이용 기한이
만료되었거나 사용할 수 없는 코드입니다." 가 뜬다. 코드에는 아무 문제가 없는데도
그렇게 보인다.

이미 그렇게 됐다면 관리자에게 [12.1](12-troubleshooting.md#121-로그인가입-오류-사례집)의
절차를 요청한다. 스스로 풀 수는 없다.

### 비밀번호 정하기

초대 코드로 만들어진 계정에는 사용자가 알 수 없는 임의의 비밀번호가 들어 있다.
비밀번호로도 로그인하고 싶으면 사용자 정보 화면에서 직접 정한다.

`/profile` 아래쪽 "비밀번호 설정·변경" 에서 본인 확인 방식을 **"초대 코드로 확인"**
으로 두고, 초대 코드와 새 비밀번호를 넣으면 된다. 최소 8 자다. 바꾸면 다른 기기의
로그인이 끊긴다.

## 5.2 대시보드

로그인하면 대시보드가 보인다.

- 위쪽에 전체 프로젝트, 팀 멤버, Kano 설문, QFD 매트릭스 수가 나온다. **화면에 보이는
  프로젝트만 합산한 값이다.**
- 아래 "내 프로젝트" 에 프로젝트 카드가 최근 수정 순으로 늘어선다. 카드에는 프로젝트
  이름, 프로그램 이름, 설명, 참여 인원, 마지막 수정일이 나온다.
- 카드를 누르면 프로젝트가 열린다.

프로젝트가 없으면 "프로젝트가 없습니다" 와 "새 프로젝트를 만들어 품질 개선을
시작하세요" 가 뜨고 "첫 프로젝트 만들기" 버튼이 나온다.

> 방금 만든 프로젝트는 목록 맨 뒤에 붙는다. 새로 고치면 최근 수정 순 자리로 돌아간다.

## 5.3 프로젝트 개설

### 직접 열 수 있는 것은 1 개

**멘티는 프로젝트를 1 개까지 직접 만들 수 있다.** 두 번째부터는 담당 프로그램
매니저의 승인이 필요하다.

"+ 새 프로젝트" 를 누르면 폼이 열린다.

| 입력 | 필수 | 설명 |
| --- | --- | --- |
| 프로젝트 이름 | 필수 | 예를 들어 스마트 IoT 센서 개발 |
| 설명 (선택) | 선택 | 한두 줄 요약 |
| 상세 설명 (선택) | 선택 | 목적, 대상 사용자, 주요 기능. 자동 스펙 생성에 쓰인다 |
| 사업계획서 (선택) | 선택 | 최대 10MB |

프로그램과 소유자를 고르는 칸은 없다. **자신이 속한 프로그램에 자기 소유로 만들어진다.**

소속 프로그램이 없으면 만들 수 없고 이렇게 뜬다.

> 소속된 프로그램이 없어 프로젝트를 만들 수 없습니다. 프로그램 매니저에게 배정을
> 요청하세요.

> **파일 형식 안내에 차이가 있다.** 화면에는 "PDF, DOC, DOCX, TXT (최대 10MB)" 로
> 적혀 있지만 실제로는 XLSX 와 XLS 도 받는다. 엑셀 사업계획 양식을 올리면 개요가
> 자동으로 채워지므로 [9.3](09-data-import-export.md#93-사업계획-양식으로-개요-채우기)을
> 함께 본다.

### 추가 개설 신청

이미 프로젝트가 있으면 대시보드 위쪽에 "추가 프로젝트 개설 신청" 카드가 나온다.

> 프로젝트는 1개까지 직접 개설할 수 있으며, 추가 개설마다 승인이 필요합니다. 현재
> N개를 소유하고 있습니다.

"추가 개설 사유" 를 적고 "승인 신청" 을 누른다. 최대 2,000 자다. **이미 대기 중인
신청이 있으면 새로 낼 수 없다.**

상태는 이렇게 바뀐다.

| 표시 | 뜻 |
| --- | --- |
| 승인 대기 | 매니저가 아직 보지 않았다 |
| 승인됨 | 승인됐다. 아직 쓰지 않았다 |
| 반려됨 | 거절됐다. 옆에 사유가 함께 나온다 |
| 사용 완료 | 이 승인으로 프로젝트를 이미 만들었다 |

승인되면 그 줄에 "승인으로 프로젝트 개설" 버튼이 생긴다. 누르면 새 프로젝트 폼이
열리고, 만들면 그 승인은 "사용 완료" 가 된다. **한 번 승인에 한 번 개설이다.**

승인 없이 두 번째 프로젝트를 만들려 하면 "추가 프로젝트는 프로그램 매니저의 승인이
필요합니다." 가 뜬다.

## 5.4 프로젝트 설정과 팀원

프로젝트 개요 화면 오른쪽 위의 "설정" 으로 들어간다. 안내에 "이 페이지의 설정은
현재 선택한 프로젝트에만 적용됩니다." 라고 적혀 있다.

탭은 "팀원 관리" 와 "데이터 관리" 둘이다. 데이터 관리는
[9부](09-data-import-export.md)에서 다룬다.

### 프로젝트 역할

시스템 역할(멘티·멘토 등)과는 별개다. 화면의 "역할 안내" 카드에 이렇게 적혀 있다.

| 역할 | 안내 문구 |
| --- | --- |
| 👑 OWNER | 모든 권한 (삭제, 멤버 관리) |
| ✏️ EDITOR | 데이터 편집 및 수정 |
| 💬 COACH | 코멘트 및 피드백만 가능 |
| ⚙️ ADMIN | 설정 및 멤버 관리 |

실제로 워크시트를 고칠 수 있는 역할은 OWNER, EDITOR, ADMIN 이다. COACH 는 읽기만
한다.

배정된 멘토는 팀원 목록에 없어도 편집자로 동작한다. 프로그램 매니저는 배정 멘토가
아니면 읽기까지만 된다.

### 팀원 초대

"+ 팀원 초대" 를 누르고 이메일과 역할을 고른다. 안내대로 **초대할 사람은 먼저
회원가입이 되어 있어야 한다.**

> **주의. 역할에서 "Coach" 를 고르면 초대가 반드시 실패한다.** 화면에는 Editor 와
> Coach 두 가지가 나오지만 서버는 Editor 만 받는다. Coach 를 고르면 "Only EDITOR
> can be invited." 라는 영문 오류가 뜬다. **팀원 초대는 Editor 로만 한다.** 멘토를
> 붙이는 것은 초대가 아니라 관리자·매니저의 멘토 배정으로 한다.

초대가 막히는 다른 경우는 이렇다.

| 문구 | 원인 |
| --- | --- |
| 프로젝트 소유자만 팀원을 초대할 수 있습니다. | 소유자가 아니다 |
| 해당 이메일의 사용자를 찾을 수 없습니다. 먼저 회원가입이 필요합니다. | 그 주소로 가입한 계정이 없다 |
| 프로젝트 소유자는 초대할 수 없습니다. | 자기 자신이다 |
| 이미 프로젝트 멤버입니다. | 이미 들어와 있다 |

### 팀원 제외

팀원 줄 오른쪽의 휴지통 버튼으로 뺀다. **소유자만 뺄 수 있다.** 확인 창이 한 번 뜬다.

> {이름} 님을 팀원에서 제외할까요? 이 프로젝트에 더 이상 접근할 수 없습니다. 작성한
> 내용은 그대로 남습니다.

알아 둘 것이 셋이다.

- **제외는 즉시 반영된다.** 그 사람이 로그인한 상태여도 이 프로젝트를 더는 열 수 없다.
- **작성한 내용은 남는다.** 워크시트와 코멘트는 프로젝트에 속하므로 지워지지 않는다.
- **담당 멘토는 여기서 빠지지 않는다.** 멘토는 팀원이 아니라 멘토 배정으로 연결되므로
  관리자나 프로그램 매니저가 배정을 해제해야 한다.

소유자는 자기 자신을 뺄 수 없다. 뺐다가 다시 넣으려면 같은 주소로 다시 초대한다.

## 5.5 이용 기한과 연장

초대 코드로 들어온 계정에는 이용 기한이 있다. 기한은 다음 중 가장 이른 시점에 끝난다.

1. 프로그램 종료 시각
2. 초대 코드에 지정된 이용 기한
3. 기한이 지정되지 않은 코드라면 첫 로그인부터 90 일

기한이 지나면 로그인이 막히고 이렇게 뜬다.

> 이용 기간이 만료되었습니다. 관리자에게 연장을 요청하세요.

연장은 스스로 할 수 없다. 관리자나 담당 프로그램 매니저에게 요청한다. 연장되면 다시
같은 코드로 로그인하면 된다.

**메일 재발송으로는 기한이 늘어나지 않는다.** 코드를 다시 받는 것과 기한 연장은 다른
일이다.

## 5.6 작업 순서 제안

워크시트는 앞에서 뒤로 값이 흐르므로 순서대로 채우는 편이 빠르다. 프로젝트 개요
화면의 "워크시트 완성도" 카드가 다음에 할 일을 알려 준다.

1. 개요 화면에서 **제품개요**를 채운다. 결과보고서의 제품 정보가 여기서 나온다.
2. **WS-1** 자사매출추정표. 미래 매출 합계가 WS-16 으로 넘어간다.
3. **WS-2** AS-IS 스펙표. 뒤의 여러 워크시트가 이 표를 참조하므로 공들여 쓴다.
4. **WS-3** 제품속성서 → **WS-4** 제품속성적합도.
5. **WS-5** 고객요구사항도출표. Kano 설문의 기반이다.
6. **WS-6** Kano 질문지에서 질문을 저장하고 응답자를 초대한다. **응답이 모이는 데
   시간이 걸리므로 여기까지 일찍 해 두는 것이 좋다.**
7. 응답이 모이면 **WS-7** 에서 집계와 가중치를 확인한다.
8. **WS-9** QFD → **WS-10** 기능기술체계도 → **WS-11** 개선포인트.
9. **WS-12** 최종목표스펙 → **WS-13** 향후목표고객.
10. **WS-14** 개발계획서, **WS-15** 자산, **WS-16·17** 자금계획.
11. 멘토가 분석을 쓰고 결과보고서를 완료한다.

**한 가지만 기억한다면 이것이다.** WS-5 고객요구사항을 나중에 통째로 바꾸면 이미
모은 Kano 설문 응답이 함께 지워지고 되돌릴 수 없다. 설문을 보내기 전에 요구사항을
확정한다.
