# 2부. 시작하기

계정을 만들고 처음 로그인할 때까지를 다룬다. 모든 역할에 해당한다.

## 2.1 접속과 화면 전환

주소로 접속하면 소개 화면이 뜬다. 이미 로그인한 상태라면 소개 화면을 거치지 않고
대시보드로 바로 넘어간다.

오른쪽 위의 해·달 버튼으로 주간·야간 화면을 바꾼다. 버튼의 설명은 **지금 모드가
아니라 누르면 바뀔 모드**를 말한다. 야간 화면일 때는 "주간 모드로 전환" 이라고 나온다.
고른 값은 쓰는 브라우저에 저장되므로 다음에 열어도 유지된다. 기본은 야간 화면이다.

## 2.2 계정을 얻는 네 가지 길

| 길 | 누가 | 결과 |
| --- | --- | --- |
| 멘티 초대 코드 | 관리자·매니저가 초대한 멘티 | 첫 로그인에서 계정이 만들어지고 바로 쓸 수 있다 |
| 회원가입 화면에서 직접 가입 | 멘토, 초대 코드가 없는 사람 | 승인 대기 상태로 만들어진다. 관리자 승인이 필요하다 |
| 회원가입 화면에서 초대 코드를 넣어 가입 | 코드를 받은 멘티 | 승인 없이 바로 쓸 수 있다 |
| 관리자가 직접 계정 생성 | 멘토·멘티 | 임시 비밀번호를 메일로 받는다 |

**멘티라면 초대 코드 로그인이 가장 단순하다.** 회원가입을 거치지 않고 로그인 화면에서
바로 계정이 만들어진다.

> 주의. 초대 메일을 받은 멘티가 회원가입 화면에서 **코드 없이 먼저 가입하면** 나중에
> 초대 코드 로그인이 막힌다. 이 경우의 증상과 해결은
> [12.1](12-troubleshooting.md#121-로그인가입-오류-사례집)에 있다. 초대를 받았다면
> 회원가입 화면이 아니라 로그인 화면으로 간다.

## 2.3 회원가입

`/signup` 에서 다음을 넣는다.

| 입력 | 설명 |
| --- | --- |
| 이름 | 필수 |
| ID | 이메일 주소 |
| 비밀번호 | 최소 8 자 |
| 비밀번호 확인 | 위와 같아야 한다 |
| 초대 코드 | 선택. 있으면 넣는다 |
| 가입할 역할 | 멘티 또는 멘토. 기본은 멘티 |

비밀번호 칸 아래에 강도 막대가 나온다. 6 자 미만이면 "약함", 8 자 미만이면 "보통",
8 자 이상이면서 대문자와 숫자를 함께 쓰면 "강함" 이다. 강도는 안내일 뿐이고 가입을
막는 기준은 8 자 길이 하나다.

### 역할에 따라 달라지는 프로필

역할을 고르면 그에 맞는 프로필 칸이 나온다. 별표가 붙은 것이 필수다.

| 항목 | 멘티 | 멘토 |
| --- | --- | --- |
| 기관명 | 담당기관명 (필수) | 소속기관명 (필수) |
| 직책·직위 | 선택 | 선택 |
| 휴대폰 | 필수 | 필수 |
| 전문분야 | — | 필수 |
| 경력 연수 | — | 필수 |
| 주요이력·보유자격 | — | 선택 |
| 기업명 | 필수 | — |
| 업종 | 필수 | — |
| 창업 연차 | 선택 | — |

마지막에 "개인정보 수집·이용에 동의합니다. 소속·연락처는 프로그램 운영에만 씁니다."
체크가 있고, 이 동의 없이는 가입할 수 없다.

### 가입 결과

- **초대 코드 없이 가입**하면 승인 대기 상태가 되고 로그인 화면으로 이동해 "가입이
  접수되었습니다. 관리자 승인 후 로그인할 수 있습니다." 가 뜬다. 관리자가 승인해야
  로그인된다.
- **초대 코드를 넣어 가입**하면 바로 로그인된 상태로 대시보드에 들어간다. 코드를
  발급한 행위 자체가 승인이기 때문이다. 역할은 코드에 정해진 역할이 되며, 가입 화면에서
  고른 역할은 무시된다.

### 자주 보는 오류

| 문구 | 원인 |
| --- | --- |
| 이미 사용 중인 이메일입니다. | 그 주소로 계정이 이미 있다 |
| 유효하지 않은 초대 코드입니다. | 없는 코드다 |
| 이미 사용된 초대 코드입니다. | 누군가 이미 쓴 코드다 |
| 기한이 지난 초대 코드입니다. 재발급을 요청하세요. | 코드 기한이 끝났다 |
| 초대 코드를 받은 이메일로만 가입할 수 있습니다. | 코드에 등록된 주소와 다르다 |
| 가입 시도가 너무 많습니다. N초 후 다시 시도하세요. | 한 시간에 3 번까지만 시도할 수 있다 |

## 2.4 로그인

`/login` 은 위쪽에서 **역할을 먼저 고르는 구조**다. "프로그램 매니저", "멘토", "멘티"
세 버튼이 있고 기본은 멘토다.

**고른 역할은 안내가 아니라 검사 조건이다.** 계정 역할과 다르면 비밀번호가 맞아도
로그인되지 않는다. 자기 역할에 맞는 버튼을 골라야 한다.

### 멘티의 두 가지 방식

멘티를 고르면 방식 버튼이 하나 더 나온다.

- **초대 코드 로그인** (기본). 초대받은 이메일과 코드를 넣는다. 최초 등록에는 이름
  입력이 필수이며, 이후에는 같은 코드로 계속 로그인한다.
- **비밀번호 로그인**. 기존 계정의 ID 와 비밀번호를 쓴다.

초대 코드 방식일 때는 **Google 로그인 버튼과 회원가입 링크가 보이지 않는다.** 그
방식에는 해당하지 않기 때문이다.

### 초대 코드 첫 로그인

이메일과 코드를 넣고 "초대 코드로 로그인" 을 누른다. 처음이라면 이름을 묻는 칸이
나타나고 버튼이 "이름 등록하고 시작하기" 로 바뀐다. 이름을 넣고 다시 누르면 계정이
만들어지면서 로그인된다.

코드는 대소문자와 하이픈 차이를 알아서 맞춰 주므로 메일에서 복사해 붙여 넣으면 된다.

### Google 로그인

역할 버튼을 고른 뒤 "Google 계정으로 로그인" 을 누른다. **Google 로그인은 자동으로
가입시키지 않는다.** 같은 주소로 이미 가입된 계정이 있어야 한다. 없으면 "이 Google
계정으로 가입된 회원이 없습니다. 먼저 회원가입을 해주세요." 가 뜬다.

Google 로그인 시도는 5 분 안에 마쳐야 한다. 오래 두면 "로그인 시도가 만료되었습니다.
다시 시도하세요." 가 뜨므로 로그인 화면부터 다시 시작한다.

### 로그인이 막힐 때

문구별 원인과 조치는 [12.1](12-troubleshooting.md#121-로그인가입-오류-사례집)에
표로 정리했다. 대표적인 것만 적으면 이렇다.

- 승인 대기라면 관리자가 승인해야 한다.
- 이용 기간이 끝났다면 연장을 요청한다.
- 역할 버튼을 잘못 골랐다면 바꿔서 다시 한다.
- 로그인 실패가 이어지면 **15 분 안에 5 번**까지만 시도할 수 있다. 제한에 걸리면
  남은 시간이 안내된다.

## 2.5 첫 로그인 온보딩

다음 둘 중 하나라도 해당하면 대시보드가 아니라 `/onboarding` 으로 간다.

1. 임시 비밀번호를 아직 바꾸지 않았다.
2. 역할에 필요한 프로필 항목이 비어 있다.

화면 제목은 "계정 설정을 마무리해 주세요." 이며 해당하는 단계만 보여 준다.

- **비밀번호 변경.** 메일로 받은 임시 비밀번호를 넣고 새 비밀번호를 정한다. 최소 8 자,
  현재 비밀번호와 달라야 한다.
- **회원 정보.** 가입 때와 같은 프로필 칸이다. 역할에 필요한 필수 항목을 채운다.

**온보딩은 주소를 직접 입력해 건너뛸 수 없다.** 끝나기 전에는 다른 화면의 기능이
모두 막히고, 어디로 가든 이 화면으로 되돌아온다. 두 단계가 다 끝나면 대시보드로 간다.

> 관리자 계정도 예외가 아니다. 관리자 화면이 열리지 않을 때 이 관문에 걸린 경우가
> 있으며, 그때 화면에는 권한 문제처럼 보이는 문구가 뜬다.
> [12.3](12-troubleshooting.md#123-관리자-계정비밀번호-복구)을 본다.

## 2.6 사용자 정보 화면

대시보드 헤더의 이름을 누르면 `/profile` 로 간다. 네 부분으로 되어 있다.

### 기본 정보

이름만 고칠 수 있다. ID 와 역할은 "ID 와 역할은 바꿀 수 없습니다. 변경이 필요하면
관리자에게 문의하세요." 안내와 함께 읽기 전용으로 나온다.

### 내 소속

역할에 따라 보이는 것이 다르다.

| 역할 | 보이는 내용 |
| --- | --- |
| 멘티 | 참여 프로그램 하나와 담당 멘토. 멘토 밑에 담당 프로젝트 이름이 붙는다 |
| 멘토 | 배정된 프로젝트를 프로그램별로 묶어서 |
| 프로그램 매니저 | 담당 프로그램과 그 안의 프로젝트. 프로젝트마다 소유자 이름이 붙는다 |
| 관리자 | 이 절이 보이지 않는다. 관리자는 프로그램에 소속되지 않는다 |

**여기서 소속을 바꿀 수는 없다.** 프로그램 배정과 멘토 배정은 관리자와 매니저가 한다.
비어 있으면 멘티에게는 "아직 어느 프로그램에도 속해 있지 않습니다. 프로그램 매니저에게
배정을 요청하세요." 가 뜬다.

### 회원 정보 수정

가입·온보딩과 같은 프로필 칸이다. 역할에 맞는 항목만 나온다. 고치고 "저장" 을 누른다.
최초 개인정보 동의 시각은 수정해도 그대로 남는다.

### 비밀번호 설정·변경

제목은 "비밀번호 설정·변경" 이고 설명은 "본인 확인 후 새 비밀번호를 저장합니다.
변경하면 다른 기기의 로그인은 해제됩니다." 다.

본인 확인 방식이 둘이다.

- **초대 코드로 확인.** 유효한 초대 코드를 가진 멘티에게만 보인다. 기본 선택이다.
  초대 코드는 이용 기간 동안 로그인과 비밀번호 재설정에 계속 쓸 수 있다.
- **현재 비밀번호로 확인.** 기존 비밀번호를 아는 경우다.

초대 코드 로그인으로 만들어진 계정은 사용자가 알 수 없는 임의의 비밀번호를 갖고
시작한다. 그래서 멘티가 비밀번호를 처음 정할 때는 초대 코드로 확인하는 쪽을 쓴다.

새 비밀번호는 최소 8 자다. 바꾸면 **다른 기기의 로그인이 모두 끊기고** 지금 쓰는
창만 유지된다.

## 2.7 이용 기간과 세션

- 로그인 상태는 **7 일** 유지된다. 그 뒤에는 다시 로그인해야 한다.
- 로그아웃하면 그 계정의 **모든 기기 로그인이 함께 끊긴다.**
- 관리자가 승인을 취소하거나 역할을 낮추거나 이용 기간을 줄이면 이미 로그인해 둔
  기기도 즉시 끊긴다.
- 이용 기간이 끝나면 로그인 자체가 막히고 "이용 기간이 만료되었습니다. 관리자에게
  연장을 요청하세요." 가 뜬다.

이용 기간은 계정에 저장된 만료일, 초대 코드의 기한, 프로그램 종료일 가운데 가장 이른
시점에 끝난다. 자세한 구조는 [1.5](01-overview.md#15-이용-기한의-구조)에 있다.
