# 7부. 프로젝트 워크시트 사용법

WS-1 부터 WS-17 까지 각 화면을 다룬다. 멘티가 작성하고 멘토가 검토하는 부분이다.

## 7.0 워크시트를 여는 두 가지 방법과 공통 동작

### 두 가지 입구

워크시트는 두 곳에서 열린다.

1. **프로젝트 개요 화면(`/project/{프로젝트ID}`)의 탭.** 한 화면 안에서 탭만 바꾼다.
2. **워크시트 주소(`/project/{프로젝트ID}/{경로}`).** 상단 메뉴바의 링크로 이동한다.

대부분은 같은 화면이지만 **WS-4 만 두 입구의 화면이 완전히 다르다.** 7.4 에서 따로
설명한다. 메뉴바는 개요, 가져오기, 설정 화면에서는 보이지 않는다.

### 저장 방식

**대부분의 워크시트는 "저장" 버튼을 눌러야 저장된다.** 자동으로 저장되는 곳은 WS-9
QFD 의 관계 강도 칸 하나뿐이다. 화면을 옮기기 전에 저장했는지 확인한다.

저장은 대체로 **그 워크시트의 기존 내용을 지우고 화면 내용으로 통째로 바꾸는**
방식이다. 그래서 다른 워크시트의 값까지 함께 지워지는 경우에는 저장 전에 확인 창이
한 번 더 뜬다. WS-3 과 WS-5 가 그렇다.

"초기화" 버튼이 있는 워크시트는 WS-1, WS-2, WS-3, WS-9, WS-10, WS-11, WS-14 다.
누르면 확인 안내가 먼저 뜨고, 확정하면 저장된 내용까지 지워진다.

### 읽기 전용

편집 권한이 없으면 워크시트 위에 "읽기 전용입니다. 워크시트 내용은 수정할 수
없습니다." 가 뜨고 모든 입력이 잠긴다. 누가 편집할 수 있는지는
[5.4](05-mentee.md#54-프로젝트-설정과-팀원)에 있다.

### 멘토 의견

개요 화면의 탭 아래에 "멘토 의견" 절이 붙는다. **워크시트 주소로 직접 연 화면에는
이 절이 없다.**

- 쓸 수 있는 사람은 **그 프로젝트 소유 멘티에게 배정된 멘토 본인과 관리자**뿐이다.
  나머지는 읽기만 한다.
- 본인이 쓴 의견만 고치고 지울 수 있다. 최대 5,000 자다.
- 작성자 계정이 지워졌으면 "탈퇴한 회원" 으로 보인다.

### 멘토 분석(보고)

여덟 개 워크시트에는 "멘토 분석(보고)" 절이 더 붙는다. 이것은 개요 탭과 워크시트
주소 양쪽에 모두 나온다. 대상과 입력 항목은 [6.2](06-mentor.md#62-멘토-분석보고-작성)에
정리했다.

## 7.0.1 프로젝트 개요 화면

프로젝트를 열면 처음 보이는 화면이다.

### 상단

왼쪽에 대시보드로 가는 링크, 가운데에 프로젝트 이름과 설명, 오른쪽에 버튼이 있다.

| 버튼 | 보이는 조건 |
| --- | --- |
| 결과보고서 | 항상 |
| 팀원 초대 | 소유자와 프로젝트 관리자 |
| 설정 | 소유자, 편집자, 프로젝트 관리자 |

### 제품개요 카드

편집 권한자에게 "수정" 버튼이 보인다. 입력 항목은 다음과 같다.

| 항목 | 형식 |
| --- | --- |
| 제품(서비스) 명 | 최대 300 자 |
| 시장정의 | 여러 줄 |
| 목표 고객 | 여러 줄 |
| 제품 이미지 | PNG 또는 JPEG. 원본 20MB 이하이며 저장 전에 자동으로 줄인다 |
| 프로젝트명 | 한 줄 |
| 사업계획 파일 | PDF, DOC, DOCX, TXT, XLSX, XLS. 최대 10MB |
| 간단 설명 | 여러 줄 |
| 상세 제품개요 | 여러 줄 |

**사업계획 파일로 엑셀 양식을 올리면 개요 칸이 자동으로 채워진다.** 편집 모드에서
"양식 다운로드" 를 눌러 양식을 받고, 내용을 적어 올리면 프로젝트명·간단 설명·상세
제품개요가 채워지며 "양식에서 ... 항목을 불러왔습니다. 확인 후 저장하세요." 가 뜬다.
**불러오기만 한 상태이므로 저장을 눌러야 반영된다.** 자세한 내용은
[9.3](09-data-import-export.md#93-사업계획-양식으로-개요-채우기)에 있다.

여기서 넣은 제품 정보는 결과보고서의 제품 개요 절로 그대로 넘어간다.

### 워크시트 완성도 카드

필수 워크시트가 몇 개 끝났는지 백분율로 보여 준다. 준비가 되면 제목이 "보고서 초안
생성 준비 완료" 로 바뀌고 배지가 READY 가 된다.

- **필수 10 종.** 제품개요, 매출추정, AS-IS 스펙, 제품속성, 제품속성 적합도,
  고객요구사항, Kano 분석, QFD, 개선포인트, 최종 목표스펙.
- **선택 5 종.** 기능기술체계, 향후 목표고객, 개발계획, 핵심·보완자산, 자금계획.

전체 백분율은 15 개 항목의 평균이다. "다음 작업" 버튼을 누르면 해야 할 워크시트로
바로 이동한다.

### 통계와 빠른 시작

AS-IS 스펙, 고객 요구사항, Kano 응답, 팀원 수가 카드로 나온다. 아래 "빠른 시작"
카드는 엑셀 가져오기부터 Kano 설문 생성까지 여섯 단계를 순서대로 눌러 갈 수 있게
해 둔 것이다.

### 접근이 막힐 때

> 이 프로젝트에 접근할 권한이 없습니다. 멘토는 현재 배정된 멘티의 프로젝트만
> 열람·수정할 수 있습니다.

멘토가 배정에서 빠지면 그 순간부터 이 문구가 뜬다. 배정을 확인한다.

## 7.1 WS-1 자사매출추정표

주소는 `sales` 다. 표가 **두 개**이며 서로 독립이다.

| 표 | 내용 |
| --- | --- |
| 현재(Y) 매출 | 현재 기준 매출처별 매출 현황 |
| 미래(Y+1차) 매출 | 1 년 후 목표 매출처별 매출 추정 |

두 표 모두 열은 같다. 번호, 매출처, 매출액, 경쟁사명이다. 단위는 백만원이다.
매출처와 경쟁사명은 이미 넣은 값이 자동완성 후보로 뜬다.

**표 맨 아래 합계 행은 자동 계산이며 입력할 수 없다.** 그 표의 매출액을 더한 값이다.

저장하면 1 초 뒤 자동으로 WS-2 로 넘어간다. 개요 탭에서 작업할 때 그렇다.

**WS-16 과 연결된다.** 미래(Y+1차) 표의 합계가 WS-16 자금소요계획표의 1 차년도
매출액 칸에 자동으로 들어간다. Y+1 행이 하나도 없으면 전체 합계를 쓴다.

## 7.2 WS-2 AS-IS 스펙표

주소는 `spec` 이다. 제품의 현재 기능을 세 단계로 분해한다.

열은 번호, 핵심기술, 세부기술, 세세부기술, 적용기술이다. 모든 칸에 자동완성이 붙는다.

**같은 값이 연속되면 칸이 위아래로 합쳐진다.** 합쳐진 칸을 고치면 그 묶음 전체가
함께 바뀐다. 행 끝의 버튼 세 개는 각각 이 핵심기술에 세부기술 추가, 이 세부기술에
세세부기술 추가, 행 삭제다.

**저장할 때 평평한 표가 3 단 구조로 정리된다.** 같은 핵심기술은 하나로 묶이고,
핵심기술이 완전히 빈 행은 버려진다.

### 엑셀 업로드

"양식 다운로드" 로 양식을 받아 채운 뒤 올린다. 파일을 고르면 **기존 데이터에 추가할지
지우고 올릴지 묻는 안내가 뜬다.** `.xlsx` 와 `.xls` 만 받는다.

### FAST 작성 지원

화면 위쪽의 "AI 에이전트" 로 전환하면 쓸 수 있다. 팝업 이름은 "WS-2 FAST 작성 지원"
이며 네 단계다.

1. **안내.** 무엇을 하는지 설명한다.
2. **입력.** "세부설명" 과 "원하는 기능" 두 칸을 채운다. "제품개요 불러오기" 로
   개요에 적은 내용을 끌어올 수 있다. 둘 다 채워야 진행된다.
3. **검토.** 만들어진 내용을 본다.
4. **FAST 결과표.** 핵심기술·세부기술·세세부기술·적용기술 네 열로 결과가 나온다.
   행을 고치거나 지울 수 있고, "확정 후 표에 반영" 을 누르면 본 표로 들어온다.

**반영은 저장이 아니다.** 반영한 뒤 "저장" 을 눌러야 확정된다.

결과에는 어떤 엔진으로 만들었는지 배지가 붙는다. AI 연결이 실패해도 규칙 기반으로
바뀌어 결과가 나오므로 작업이 멈추지 않는다. 자세한 내용은
[10부](10-ai-features.md)에 있다.

### 기능분석 작성 도우미

"기능분석 작성 도우미" 버튼은 편집 권한자에게만 보인다. 질문에 답하면 **외부 AI 에
붙여 넣을 프롬프트를 만들어 준다.** 이 기능 자체는 AI 를 호출하지 않는다.

질문은 네 단계에 여덟 개다. 제품·서비스명, 설명, 사용자와 역할이 필수이고, 현재 처리
방법과 고객이 원하는 결과도 필수다. 현재 기능과 보유 기술, 제약, 시험·상용 범위는
선택이다. "현재 WS-2 내용 포함" 을 켜면 지금 표를 참고 자료로 넣는다.

만들어진 프롬프트를 복사해 Claude 나 OpenAI 에 붙여 넣고, 받은 결과를 표에 옮긴다.

> 이 도우미는 이름과 달리 **WS-2 화면에 있다.** WS-10 이 아니다.

## 7.3 WS-3 제품속성서

주소는 `attributes` 다. 세분시장별로 고객과 니즈, 혜택, 제품속성을 정리한다.

표 위에 제품명 칸이 하나 있고 처음에는 프로젝트명이 자동으로 들어간다.

열은 번호, 세분시장, 고객명, 고객 니즈, 제공혜택, 제품속성이다. 세분시장과 고객명은
같은 값끼리 칸이 합쳐지며, 합쳐진 칸 안의 "+ 항목" 과 "+ 니즈" 버튼으로 그 묶음에
행을 더한다.

### 기술 역량은 표 밖에 있다

표 아래 "기술 역량" 카드는 **행별이 아니라 표 전체에 하나**다. 여러 개면 줄을 나눠
적는다. 저장하면 모든 행에 같은 값이 기록된다. "스펙에서 추가" 를 누르면 WS-2 의
적용기술을 한 줄씩 가져온다.

### AS-IS 스펙에서 가져오기

제품속성 열 헤더의 안내대로 가져오기 버튼을 누르면 WS-2 목록이 뜬다. **세세부기능
행을 누르면 적용기술까지 함께 들어오고, 세부기능 칸을 누르면 제품속성만 들어온다.**

### AI 멘토링 마법사

"AI 멘토링" 버튼으로 연다. 네 단계다.

1. **문진.** 질문에 답한다. 세분시장은 반드시 답해야 초안을 만든다.
2. **초안 검토.** 세분시장·고객명·고객 니즈·제공혜택이 표로 나온다. 필요 없는 행은
   체크를 풀고 문구는 직접 고친다.
3. **기능 선택.** 행마다 WS-2 기능을 연결한다. 목록에 없으면 직접 추가한다.
4. **기술 확인.** 선택한 기능에 연결된 WS-2 적용기술을 확인한다. 기술 역량 칸에
   들어간다.

**"표에 적용" 은 기존 행을 지우지 않고 뒤에 덧붙인다.** 적용 뒤 저장해야 반영된다.

### 저장할 때 나오는 확인

저장은 기존 속성을 모두 지우고 다시 쓰는 방식이라 WS-4 적합도가 함께 사라질 수 있다.
그런 경우 확인 창이 뜬다.

> 제품 속성을 모두 지우면 적합도 N건이 함께 삭제됩니다.

내용을 읽고 판단한다. 취소하면 아무것도 바뀌지 않는다.

## 7.4 WS-4 제품속성적합도

**이 워크시트는 입구에 따라 화면이 다르다.** 둘은 저장되는 곳도 다르므로 한쪽에 적은
내용이 다른 쪽에 나타나지 않는다. 어느 쪽을 쓸지 팀에서 미리 정해 두는 편이 좋다.

### (가) 주소로 연 화면 — 슬라이더 방식

`attributes/fitness` 주소다. WS-3 의 제품속성이 자동으로 목록이 된다. 속성마다
슬라이더 세 개를 1 부터 10 까지 조절한다.

| 슬라이더 | 뜻 | 기본값 |
| --- | --- | --- |
| 중요도 | 고객에게 얼마나 중요한지 | 5 |
| 현 수준 | 현재 제품의 달성 수준 | 3 |
| 목표 | 도달해야 할 목표 | 7 |

**목표 갭은 자동 계산이다.** 목표에서 현 수준을 뺀 값이며 양수면 주황색 상승,
음수면 초록색 하강으로 보인다. 그 밖에 비고 칸이 있다.

저장하면 손대지 않은 속성도 기본값으로 함께 저장된다.

### (나) 개요 탭 화면 — 매트릭스 방식

개요 화면의 "[WS-4] 제품속성적합도" 탭이다. 행은 제품속성, 열은 시장과 그 아래
세분화다. 시장과 세분화는 WS-3 의 세분시장·고객명에서 자동으로 만들어지며 직접
이름을 고치고 더할 수 있다.

**셀을 왼쪽 클릭하면 H → M → L → L\* 순으로 바뀌고, 오른쪽 클릭하면 지워진다.**
H 는 높음, M 은 중간, L 은 낮음, L\* 는 최저다.

자동으로 계산되는 것이 둘이다.

- **개수.** 세분화마다 H·M·L·L\* 가 몇 개인지 센다.
- **세분시장 순위.** L\* 가 하나라도 있으면 "부적합" 이다. 없으면 H 개수가 많은 순,
  같으면 M 개수로 순위를 매긴다. 같으면 "N순위 (동률)" 로 표시한다.

저장을 누르면 **컨설턴트 진단이 자동으로 만들어진다.** 최우선 진입 세분시장, 1 순위
시장의 속성 분포, 부적합 시장, 속성 분석, 권고사항이 글로 나온다. 저장 전에는 "저장
버튼을 누르면 분석 결과가 생성됩니다" 만 보인다.

아래 "담당자 의견" 칸은 자유롭게 적고 같은 저장 버튼으로 함께 보관한다.

## 7.5 WS-5 고객요구사항도출표

주소는 `requirements` 다. **Kano 설문의 기반**이 되는 표다.

열은 번호, 항목, 1차 그룹, 2차 그룹이다. 2 차 그룹은 선택이다. 항목을 클릭하면 그
자리에서 고칠 수 있고, 새 줄에서 Enter 를 누르면 바로 추가된다.

행 순서는 저장한 순서를 그대로 지킨다. 그룹으로 다시 정렬하지 않는다.

아래에 "Kano 질문 세트 N개 생성 가능" 과 카테고리별 건수가 표시된다.

### AI 자동생성

WS-3 제품속성을 읽어 요구사항 문장을 만든다. **외부 AI 를 쓰지 않는 규칙 기반**
기능이다. 문장은 "{고객니즈}을(를) 통해 {제공혜택}을(를) 얻고자 함" 꼴이 되고,
1 차 그룹에 세분시장, 2 차 그룹에 제품속성이 들어간다.

"기존 항목에 추가" 와 "전체 교체 (기존 삭제)" 중에서 고른다. 이미 같은 항목이 있으면
추가하지 않는다.

### 저장할 때 나오는 확인

기존 요구사항이 지워지는 저장이면 확인 창이 뜬다.

> 고객요구사항을 덮어쓰면 Kano 설문 응답 N건, 벤치마크 N건, QFD 관계 N건이 함께
> 삭제됩니다. 설문 응답은 다시 모을 수 없습니다.

**설문 응답은 되돌릴 수 없다.** 응답을 모은 뒤에는 요구사항을 통째로 바꾸지 않는다.

### 엑셀 업로드

이 화면만 업로드 방식을 작은 입력 창으로 묻는다. 1 은 기존 데이터에 추가, 2 는
지우고 새로 올리기다. 1 이나 2 가 아니면 "업로드 방식은 1 또는 2로 선택해주세요."
가 뜬다.

## 7.6 WS-6 Kano 질문지

주소는 `kano` 다. WS-5 의 요구사항 하나가 질문 한 세트가 된다. 한 세트는 긍정 질문과
부정 질문 두 개다.

요구사항이 없으면 "고객 요구사항이 없습니다" 와 함께 입력하러 가는 버튼만 나온다.

### 상단 통계 카드

| 카드 | 뜻 |
| --- | --- |
| 설문 질문 | 요구사항 개수. 긍정·부정 2 문항이 1 세트 |
| 초대 발송 | 초대한 사람 수 |
| 응답 완료 | 응답을 마친 사람 수 |
| 응답률 | 완료 나누기 발송 |

### 질문 구성

요구사항마다 카드가 하나씩 나온다. 요구사항 문장에서 **설문 주제가 자동으로
뽑힌다.** 어미와 조사를 떼어 낸 것이다.

기본 질문은 이렇게 만들어진다.

- 긍정. `{주제}(이)라면 어떻게 생각하십니까?`
- 부정. `{주제}(이)가 아니라면 어떻게 생각하십니까?`

두 칸 모두 직접 고칠 수 있다. 고친 뒤에는 반드시 "질문 저장" 을 누른다. 화면에도
같은 안내가 있다.

> 저장된 질문이 미리보기, Google Forms, Word 설문지에 반영됩니다. 저장하지 않은
> 수정은 인쇄물에 나가지 않습니다.

> **알아 둘 것.** 온라인 응답 화면은 질문을 저장하지 않았을 때 다른 기본 문장을
> 쓴다. "만약 {요구사항} 기능이 있다면 어떻게 느끼시겠습니까?" 꼴이다. 질문을
> 저장하면 모든 경로가 저장된 문장으로 통일되므로, **설문을 보내기 전에 한 번
> 저장해 두는 것이 좋다.**

### 응답자 초대

"응답자 초대" 를 누르면 방식을 고른다.

**한 명 초대.** 이메일 하나를 넣는다. 초대 링크는 **7 일** 유효하다. SMTP 가
설정돼 있으면 메일이 나가고, 아니면 "초대가 생성되었습니다. 질문지 링크를 직접
공유하세요." 가 뜬다.

**여러 명 한번에.** 두 가지로 넣는다.

- "양식 다운로드" 로 명단 양식을 받아 이메일을 채워 올린다. 이메일 열만 채우면 된다.
- 또는 이메일을 직접 붙여 넣는다. 줄바꿈·쉼표·세미콜론으로 구분한다. 중복과 잘못된
  주소는 자동으로 걸러진다.

**한 번에 200 명까지** 보낼 수 있다. 결과는 초대·건너뜀·실패로 나뉘어 줄마다
표시된다. 이미 초대한 주소는 건너뛴다.

### 초대 내역과 링크

아래 "초대 내역" 에 사람별 상태가 나온다. 응답을 마쳤으면 응답 일시가, 아니면 만료
날짜가 붙는다. 줄에 마우스를 올리면 "링크 복사" 가 나타난다. **읽기 권한만 있는
사람에게는 이 버튼이 보이지 않는다.** 링크는 곧 응답 권한이기 때문이다.

### 리셋 두 가지

| 버튼 | 지워지는 것 |
| --- | --- |
| 응답 데이터 리셋 | 응답만 지우고 초대는 남긴다. **같은 링크로 다시 응답할 수 있다** |
| 초대 내역 리셋 | 응답과 초대를 모두 지운다. 링크가 무효가 된다 |

둘 다 되돌릴 수 없다.

### 종이와 파일로 응답 받기

인터넷 설문 말고도 길이 네 가지 더 있다.

| 방법 | 언제 쓰나 | 파일 |
| --- | --- | --- |
| 설문지 Word 내려받기 | 종이로 돌려 받을 때 | `.docx` |
| 오프라인 HTML 응답지 | 인터넷 없이 파일 하나로 받을 때 | `.html` |
| 응답 파일 업로드 | 여러 명 답을 한 파일에 정리해 한 번에 넣을 때 | `.xlsx`, `.xls` |
| Apps Script 받기 | Google 설문지를 직접 만들 때 | `.gs` |

**설문지 Word 내려받기.** 저장된 질문으로 종이 설문지를 만든다. **저장하지 않은
수정은 반영되지 않는다.** 요구사항이 없어도 막지 않으므로 빈 표가 나올 수 있다.

**오프라인 HTML 응답지.** "오프라인 HTML 받기" 로 파일을 받아 응답자에게 준다.
응답자는 브라우저로 열어 답하고 "응답 저장" 을 누른다. 답이 박힌 새 HTML 파일이
만들어지며, 그 파일들을 모아 다시 올린다. **한 번에 100 장까지**, 한 장은 2MB
까지다.

**응답 파일 업로드.** 형식을 "전용 양식" 과 "Google Forms 형식" 중에 고르고
"양식 받기" 로 받는다. 올릴 때 기존 데이터에 추가할지 지우고 올릴지 묻는다.
답변은 1 부터 5 까지의 점수나 보기 문구로 적는다.

**Apps Script.** Google 연동 없이 Google 설문지를 만드는 스크립트다. 받은 파일의
내용을 Google Apps Script 에 붙여 넣고 실행한다.

> 화면의 "Google Forms 연동" 3 단계 카드는 **개발 중이라 동작하지 않는다.** 눌러도
> "Google Forms 연동은 개발 중입니다. 응답 파일 업로드 또는 오프라인 응답파일
> 업로드를 사용해 주세요." 가 나온다.

업로드로 들어온 응답은 초대 목록에도 응답 완료로 잡힌다. 그래서 업로드 뒤에는 초대
발송·응답 완료·응답률 숫자가 함께 올라간다.

## 7.7 WS-7 Kano 분석 집계표와 그래프

**주소 `kano/analysis` 에는 표가 없다.** 안내와 이동 버튼만 있다. 실제 화면은 개요
화면의 "[WS-7] TIMKO/만족계수 그래프" 탭이다.

응답이 하나도 없으면 "Kano 분석 데이터가 없습니다." 만 보인다.

### Kano 6 분류

응답자 한 명의 긍정·부정 답 조합으로 그 사람의 분류가 정해진다. 항목의 분류는
응답자들의 분류 중 **가장 많이 나온 것**이다.

| 코드 | 뜻 | 읽는 법 |
| --- | --- | --- |
| M | 당연적 (Must-be) | 있어도 티가 안 나고 없으면 불만이다 |
| O | 일원적 (One-dimensional) | 잘할수록 만족이 올라간다 |
| A | 매력적 (Attractive) | 없어도 불만은 아니지만 있으면 크게 만족한다 |
| I | 무관심 (Indifferent) | 있으나 없으나 반응이 없다 |
| R | 역품질 (Reverse) | 오히려 없는 쪽을 원한다 |
| Q | 회의적 (Questionable) | 답이 앞뒤가 맞지 않는다. 질문을 의심한다 |

> **화면마다 한글 이름이 조금씩 다르다.** R 은 "역품질" 또는 "역" 으로, Q 는
> "회의적", "의심", "의문" 으로 나온다. 같은 것을 가리킨다.

### 집계표

열은 번호, 설문항목, 6 분류별 개수와 합계, 만족계수, 불만족계수, 가중치, KANO
분석결과, TIMKO 분석결과다. 개수가 0 인 칸은 비워 둔다.

### 만족계수와 불만족계수

계산식은 이렇다. R 과 Q 는 분모에서 빠진다.

```
분모     = A + O + M + I
만족계수  = (A + O) / 분모          0 ~ 1
불만족계수 = -((O + M) / 분모)       -1 ~ 0
```

분모가 0 이면 둘 다 0 이다.

### 그래프 읽는 법

가로축은 불만족 계수이며 왼쪽 -1.0 에서 오른쪽 0.0 으로 간다. 세로축은 만족 계수이며
위가 1.0 이다. 0.5 를 기준으로 네 구역이 나뉜다.

| 구역 | 조건 | 품질 |
| --- | --- | --- |
| 오른쪽 위 | 만족 0.5 이상, 불만족 0.5 미만 | 매력적 |
| 왼쪽 위 | 만족 0.5 이상, 불만족 0.5 이상 | 일원적 |
| 왼쪽 아래 | 만족 0.5 미만, 불만족 0.5 이상 | 당연적 |
| 오른쪽 아래 | 나머지 | 무관심 |

배경 격자는 워크시트의 색표를 그대로 옮긴 것이고, 격자 위쪽 눈금이 가중치다.
**점이 놓인 칸이 곧 가중치**이므로 점의 위치를 옮기지 않는다.

점이 겹치면 번호를 가운뎃점으로 이어 하나로 묶어 보여 준다. 예를 들어 `4·7` 이다.

> 점을 눌러 항목을 고르는 기능은 아직 연결되어 있지 않다. 눌러도 아무 일도 일어나지
> 않는다.

### 가중치

가중치는 자동으로 계산되지만 직접 고칠 수 있다.

| 자동 가중치 | 범위 |
| --- | --- |
| 당연적 | 3 |
| 무관심 | 2 |
| 매력적 | 4.2 ~ 5.0 |
| 일원적 | 3.2 ~ 4.0 |

가중치 칸에 0 부터 5 사이 숫자를 넣고 "저장" 을 누른다. 범위를 벗어나면 "가중치는
0부터 5 사이의 숫자로 입력해주세요." 가 뜬다. **칸을 비우면 자동값으로 되돌아간다.**

**이 가중치가 WS-9 QFD 의 요구사항 중요도가 된다.** 직접 넣은 값이 있으면 그것을,
없으면 자동값을 쓴다.

### 응답자별 보기

"응답자별 보기" 로 전환하면 사람마다 어떤 답을 했는지 표로 볼 수 있다. 이메일, 응답
일시, 문항별 긍정·부정 답과 그 사람의 분류가 나온다.

## 7.8 WS-9 QFD

주소는 `qfd` 다. 고객 요구사항을 기술 특성에 연결하고 우선순위를 계산한다.

### 표 구조

- **행**은 WS-5 고객요구사항이다. **읽기 전용이며 여기서 추가할 수 없다.**
- **열**은 기술특성(세부기능)이며 그룹으로 묶인다. 그룹 제목은 **WS-10 에서 그
  세부스펙이 속한 핵심기능** 이름이다. 연결이 없으면 "핵심기능 미연결" 로 나온다.
- 오른쪽에 중요도와 경쟁 비교, 기획품질 열이 붙는다.

### 입력하는 칸

| 칸 | 고르는 값 |
| --- | --- |
| 세부기능 열 머리 | WS-10 의 세부스펙 목록에서 고른다 |
| 관계 강도 | `-` 없음, `1` 약함, `3` 보통, `9` 강함 |
| 자사·경쟁사 점수 | 0 부터 5 |
| 표 아래 Spec 칸 | 측정단위, 자사, 경쟁사, 설계 목표치를 글로 적는다 |

### 자동으로 계산되는 칸

| 칸 | 계산 |
| --- | --- |
| 가중치 | WS-7 의 Kano 가중치 |
| 가중치 백분율 | 가중치 ÷ 가중치 합계 × 100 |
| 기획품질 | 자사 점수와 경쟁사 최고 점수 중 큰 값 |
| 수준향상률 | 기획품질 ÷ 자사 점수 |
| 절대중요도 | 가중치 × 수준향상률 |
| 요구품질 중요도 | 절대중요도 ÷ 절대중요도 합계 × 100 |
| RANK (행) | 절대중요도가 높은 순. 1~5 위는 빨간 굵은 글씨 |
| 품질중요도 (열) | 관계 강도 × 요구사항 가중치를 열마다 더한 값 |
| RANK (열) | 품질중요도가 높은 순 |

### 저장이 세 갈래다

이 화면만 저장 방식이 셋이다.

1. **관계 강도는 고르는 즉시 저장된다.** 화면에 "관계 강도 저장 중..." 이 뜬다.
   실패하면 "관계 강도 N개 저장 실패." 와 다시 저장하는 링크가 나온다.
2. **"저장" 버튼**은 표 아래 Spec 칸과 아직 저장하지 않은 비교 점수를 함께 보낸다.
3. **"비교 점수 저장 (N)" 버튼**은 대기 중인 자사·경쟁사 점수만 보낸다.

저장하지 못한 관계 강도가 있는 채로 화면을 떠나려 하면 확인 창이 뜬다.

### 열 관리

- "+ 그룹" 으로 그룹을 만들고, 그룹 안에서 "+ 세부기능" 으로 열을 더한다. 세부기능은
  WS-10 목록에서 고르거나 직접 적는다.
- 열이나 그룹을 지우면 **관계 강도와 상관관계, 기술 벤치마크가 함께 지워진다.** 확인
  안내에 몇 개가 사라지는지 나온다.
- 경쟁사 열은 이름을 넣고 "+ 경쟁사" 로 더한다. "자사" 는 경쟁사 이름으로 쓸 수 없다.
- 그룹 접기 상태는 브라우저에 프로젝트별로 기억된다.

### WS-10 과의 관계

처음 한 번은 WS-10 의 세부스펙으로 기술특성이 자동으로 만들어진다. **그 뒤에 사용자가
지운 열은 다시 만들어지지 않는다.**

## 7.9 WS-10 기능기술체계도

주소는 `tech-tree` 다. 고객의 소리에서 핵심스펙, 세부스펙, 기술적 특성으로 이어지는
체계를 만든다.

열은 고객의 소리, 핵심스펙(기능), 세부스펙(기능), 기술적 특성이다. 위 계층의 값이
같으면 칸이 합쳐지고, 합쳐진 칸을 고치면 묶음 전체가 바뀐다. **핵심스펙을 바꾸면 그
묶음의 세부스펙과 기술적 특성이 비워지고 다시 고르라는 안내가 뜬다.**

### 행을 채우는 세 가지 방법

- **QFD TOP5 반영.** WS-9 의 RANK 1~5 위 요구사항으로 행을 만든다.
- **자동 생성.** QFD 순위가 없으면 WS-5 요구사항 전체로 만든다.
- **직접 입력.**

### 세부스펙 선택

세부스펙 칸의 "선택" 을 누르면 WS-2 목록이 뜬다. **그 행의 핵심스펙 아래 항목만**
후보로 나오며, 고르면 기술적 특성까지 함께 들어온다. 핵심스펙을 먼저 골라야 한다.

이 워크시트의 세부스펙이 **WS-9 의 세부기능 열 선택지가 된다.**

## 7.10 WS-11 개선포인트도출

주소는 `improvements` 다. 표가 두 개다.

### 표 1. 고객니즈 우선순위

순위, 고객니즈, 경쟁사대비 수준향상율, 개발향상비중이다. 고객니즈를 QFD 가 제안한
값과 같게 적으면 **수준향상율과 개발향상비중이 자동으로 채워진다.**

### 표 2. 개선 기능 및 성능 List

순위, 개선포인트 우선순위(고객니즈), 추가 기능, 성능향상이다. 고객니즈 칸은 **읽기
전용**이며 표 1 의 니즈가 자동으로 붙는다.

표 2 는 항상 다섯 줄 이상을 유지한다. 표 1 에서 니즈를 지워도 이미 적은 기능이 밀려
올라가지 않도록 빈 줄에만 니즈를 채운다.

### QFD TOP5 반영

버튼을 누르면 QFD 분석 결과에서 상위 다섯 개를 뽑아 **표 1 을 통째로 바꾼다.**
데이터가 없으면 "QFD TOP5 데이터가 없습니다." 가 뜬다.

이 워크시트의 결과는 WS-12 의 신규 기능 후보와 WS-13 의 행으로 이어진다.

## 7.11 WS-12 최종목표스펙도출

주소는 `target-spec` 이다. **메뉴 이름과 화면 제목이 다르다.** 화면 제목은
"[WS-12] 최종 제품/서비스 제공 스펙 List" 다.

열은 스펙분류, 세부항목, 기술적 특성, 개선여부 넷이다.

**저장된 행이 없으면 WS-2 AS-IS 스펙이 그대로 채워지고 개선여부에 "유지" 가 들어간다.**

### 신규 기능 추가

표 위에 별도 입력 영역이 있다.

| 입력 | 설명 |
| --- | --- |
| 추가할 신규 기능 | **WS-11 의 개선 기능 목록**에서 고른다 |
| 스펙분류(핵심스펙) | 어느 분류에 넣을지 |
| 상위 세부항목 | 비워 두면 핵심스펙 바로 아래에 들어간다 |

고르면 아래에 고객니즈와 성능향상이 미리 보인다. "신규 기능 추가" 를 누르면 같은
분류 묶음의 끝에 끼워 넣고 **개선여부에 "신규" 가 자동으로 적힌다.** 이미 있는
기능이면 "이미 추가된 기능입니다." 가 뜬다.

## 7.12 WS-13 향후목표고객LIST

주소는 `tech-roadmap` 이다. 이 화면도 **메뉴 이름과 화면 제목이 다르다.** 화면

중복돼 짝을 찾지 못한 기존 행은 지우지 않고 목록 아래에 남기며 안내가 뜬다.

## 7.13 WS-14 개발계획서

주소는 `dev-plan` 이다. 단계별 일정과 담당을 적는다.

열은 번호, 단계, 과제/항목, 내용, 시작, 종료, 담당, 상태다. 시작과 종료는 날짜

## 7.14 WS-15 핵심자산 및 보완자산 도출표

주소는 `assets` 다. 표가 두 개다.

- **핵심자산 도출표.** 번호와 핵심자산.
- **보완자산 도출표.** 필요 항목과 해결방안.

> **주의.** 이 화면만 저장 결과가 브라우저 알림 창으로 뜬다. 그리고 **저장에
> 실패하면 화면에 아무 표시가 없다.** 저장 뒤 알림이 뜨지 않았다면 화면을 새로 고쳐
> 내용이 남았는지 확인한다.

## 7.15 WS-16 자금소요계획표

주소는 `funding-plan` 이다. 단위는 백만원이다.

**행은 고정이며 추가하거나 지울 수 없다.** 프로젝트를 처음 열 때 일곱 줄이
만들어진다.

| 구분 | 항목 |
| --- | --- |
| 매출액 | 매출액 |
| 소요자금 | 생산비용 |
| 소요자금 | 운영관리비 |
| 소요자금 | 설비투자금 |
| 소요자금 | 연구개발 및 기술이전 등 |
| 소요자금 | 기타 등 |
| 소요자금 | 소요자금 합계 |

열은 구분, 항목, 1차년도(Y+1), 2차년도(Y+2), 3차년도(Y+3)다.

**매출액 행의 1 차년도는 입력할 수 없다. WS-1 의 미래 매출 합계가 자동으로 들어온다.**
2·3 차년도는 직접 넣는다.

오른쪽에 연차별 소요자금 막대그래프가 나오고, 아래 "핵심 요약" 에 연차별 값과 3 개년
총 소요자금이 나온다. "소요자금 합계" 행은 강조만 될 뿐 직접 입력하는 칸이다.

"AI 초안 (사용 중지)" 버튼은 **항상 비활성**이다.

## 7.16 WS-17 자금조달계획표

주소는 `funding-source` 다. WS-16 과 같은 화면 틀을 쓴다.

**행은 고정 여섯 개**이며 추가하거나 지울 수 없다. 정부자금, 엔젤투자금, 연구개발
지원금(R&D), 민간투자주도형 기술창업지원(TIPS), 벤처캐피털(VC), 기타다.

**연차 칸 하나가 출처와 금액 두 칸으로 나뉜다.** 출처는 글로 적고 금액은 숫자다.
맨 아래 "자금조달 합계" 행은 연차별 금액을 더한 자동 계산이다.
