# 4부. 프로그램 매니저 매뉴얼

프로그램 매니저는 자기가 담당하는 프로그램을 운영한다. 화면은 `/manage` 다.

## 4.1 매니저 화면의 범위

대시보드 헤더의 "🧭 프로그램 관리" 로 들어간다. 제목은 "프로그램 관리", 부제는
"담당 프로그램 관리, 초대 코드 발행, 멘토 배정" 이다.

탭이 셋이다.

| 탭 | 내용 |
| --- | --- |
| 프로그램 | 담당 프로그램 목록과 멘티 배정, 프로젝트 불러오기, 추가 개설 승인 |
| 초대 | 멘티 초대 코드 발행과 관리 |
| 멘토 배정 | 프로그램을 고른 뒤 멘토를 일괄 배정 |

관리자도 매니저도 아닌 계정이 들어오면 "권한이 없습니다" 화면과 함께 "이 화면은
관리자와 프로그램 매니저만 볼 수 있습니다." 가 뜬다.

### 관리자 화면과 무엇이 다른가

관리자 화면(`/admin`)과 나눈 이유가 있다. 관리자 화면에는 회원 삭제와 역할 변경이
있어서, 같은 화면을 열어 주고 탭만 숨기면 권한 경계가 화면 조건문에 기대게 된다.
그래서 매니저 전용 화면을 따로 두었다.

| 기능 | 관리자 화면 | 매니저 화면 |
| --- | --- | --- |
| 통계와 시스템 정보 | 있다 | 없다 |
| 회원 승인·역할 변경·계정 생성·삭제 | 있다 | **없다** |
| 프로젝트 목록과 삭제, 소유권 이전 | 있다 | 없다 |
| 프로그램 개설·삭제 버튼 | 관리자만 | **항상 숨겨진다** |
| 프로그램 수정, 멘티 배정, 프로젝트 불러오기 | 있다 | 있다 |
| 초대 관리 | 있다 | 있다 |
| 멘토 배정 | 있다 | 있다 |
| 보이는 데이터 범위 | 전체 | **담당 프로그램만** |

**매니저는 프로그램을 새로 만들거나 지울 수 없다.** 관리자에게 요청한다.

**매니저에게는 초대 코드 값이 보이지 않는다.** 목록의 초대코드 열에 "관리자만 열람
가능" 으로 나온다. 코드를 전달해야 하면 메일 재발송을 쓰거나 관리자에게 요청한다.

## 4.2 담당 프로그램 운영

프로그램 탭에서 담당 프로그램이 카드로 나온다. 카드마다 이름, 주관기관, 운영 기간,
담당자, 멘티 수와 프로젝트 수가 보인다.

### 프로그램 내용 수정

"내용 수정" 으로 이름, 주관기관, 시작일, 종료일을 고친다. 담당자는 바꿀 수 없다.

운영 기간을 바꿀 때 화면의 안내를 반드시 읽는다.

> 운영 기간을 바꾸면 연결된 멘티와 초대코드의 이용 기한에도 적용됩니다.

**프로그램 종료일은 모든 이용 기한의 상한이다.** 종료일을 앞당기면 그 뒤로 잡아 둔
멘티의 접근이 함께 끊긴다.

### 멘티 배정

"멘티 배정" 을 열어 이 프로그램에 넣을 멘티를 고른다. **승인된 멘티만 후보에 나온다.**
승인 대기 계정은 관리자가 먼저 승인해야 한다.

이미 다른 프로그램에 속한 멘티를 고르면 확인 창이 한 번 더 뜬다. 옮기면 그 멘티에게
연결된 초대 코드의 프로그램도 함께 바뀐다.

### 프로젝트 불러오기

다른 프로그램에 있는 프로젝트를 이 프로그램으로 옮긴다. 이미 이 프로그램 소속인
프로젝트는 후보에서 빠져 있다.

## 4.3 초대 코드 발행

초대 탭의 화면은 관리자 화면과 같다. 발급 폼, 일괄 발급, 기한 연장, 재발송, 회수가
모두 같으므로 [3.4](03-admin.md#34-초대-관리-탭)를 본다.

매니저에게만 해당하는 점은 두 가지다.

- **담당 프로그램에만 발급할 수 있다.** 다른 프로그램을 고르면 "이 프로그램에 초대
  코드를 발행할 권한이 없습니다." 가 뜬다.
- **코드 값이 보이지 않는다.** 메일 발송이 실패하면 "코드 발급 완료 · 메일 발송 실패.
  목록에서 메일을 재발송하거나 관리자에게 문의하세요." 가 나온다. 안내대로 재발송을
  쓴다.

## 4.4 멘토 배정

"멘토 배정" 탭에서 프로그램을 먼저 고른다. 고르지 않으면 "멘토를 배정할 프로그램을
먼저 선택하세요." 만 보인다.

배정 방법은 관리자 화면과 같다. 멘토를 고르고 멘티를 체크한 뒤 "선택한 N명에게 배정"
을 누른다. 자세한 동작과 확인 문구는 [3.7](03-admin.md#37-멘토-배정)에 있다.

기억할 규칙은 이렇다.

- **멘티 한 명의 담당 멘토는 한 명이다.** 새로 배정하면 기존 배정이 교체된다.
- **배정은 그 멘티의 모든 프로젝트에 적용된다.** 프로젝트별로 다른 멘토를 둘 수 없다.
- 한 멘토가 여러 멘티를 맡는 것은 된다.
- 담당 프로그램의 멘티만 배정할 수 있다. 아니면 "담당 프로그램의 멘티만 배정할 수
  있습니다." 가 뜬다.

## 4.5 프로젝트 개설 대행

매니저는 **멘티를 소유자로 지정해 프로젝트를 대신 열 수 있다.** 대시보드의 "+ 새
프로젝트" 를 누르면 폼에 프로그램과 소유할 멘티를 고르는 칸이 나온다.

고른 프로그램에 멘티가 없으면 "이 프로그램에 속한 멘티가 아직 없습니다. 먼저 멘티를
초대하세요." 가 뜬다. 멘티 배정이나 초대가 먼저다.

담당이 아닌 프로그램을 고르면 "이 프로그램에 프로젝트를 만들 권한이 없습니다." 가
뜬다.

## 4.6 추가 프로젝트 개설 승인

멘티는 프로젝트를 1 개까지 직접 열 수 있고 그 이상은 승인을 받아야 한다. 신청은
프로그램 탭 맨 위의 "추가 프로젝트 개설 승인 관리" 에서 처리한다.

- **승인**은 바로 처리된다. 사유를 적는 칸이 없다.
- **반려**를 누르면 사유를 묻는 입력 창이 뜬다. 여기서 취소하면 아무것도 보내지
  않는다. 적은 사유는 신청자에게 그대로 보인다.

승인된 권한은 멘티가 프로젝트를 한 번 열면 "사용 완료" 가 된다. **한 번 승인에 한 번
개설이다.**

담당 프로그램의 신청만 처리할 수 있다.

## 4.7 멘토를 겸할 때

프로그램 매니저는 멘토를 겸할 수 있다. 어떤 프로젝트에 멘토로 배정되면 그 프로젝트의
워크시트를 편집할 수 있고 멘토 분석도 쓸 수 있다.

배정되지 않은 프로젝트는 **내용을 볼 수는 있지만 고칠 수 없다.** 매니저의 전체 열람
권한은 읽기까지이며, 편집은 관리자와 배정 멘토만 할 수 있다.

## 4.8 운영 순서 요약

1. 관리자에게 프로그램 개설을 요청하고 담당자로 지정받는다.
2. 초대 탭에서 멘티 이메일을 모아 초대 코드를 일괄 발급한다.
3. 멘티가 로그인해 계정이 생기면 프로그램 탭에서 소속을 확인한다.
4. 멘토 배정 탭에서 멘티마다 담당 멘토를 지정한다.
5. 멘티가 프로젝트를 열고 워크시트를 시작한다. 필요하면 대신 열어 준다.
6. 추가 개설 신청이 오면 검토해 승인하거나 반려한다.
7. 이용 기한이 다가오면 초대 탭에서 기한을 연장한다.
