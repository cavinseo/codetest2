# 6부. 멘토 매뉴얼

멘토는 배정된 멘티의 프로젝트를 검토하고 의견과 분석을 남긴다. 결과보고서를 완성하는
것도 멘토의 몫이다.

## 6.1 멘토가 할 수 있는 일과 없는 일

멘토는 초대 코드로 모집하지 않는다. 회원가입 화면에서 직접 가입해 관리자 승인을
받거나, 관리자가 계정을 만들어 준다. 여러 프로그램의 프로젝트에 배정될 수 있기
때문에 프로그램 하나에 묶는 초대 코드 모델과 맞지 않아서다.

| 할 수 있다 | 할 수 없다 |
| --- | --- |
| 배정된 멘티의 프로젝트 열람·편집 | 배정되지 않은 프로젝트 열람 |
| 워크시트 의견 작성 | 회원 승인, 역할 변경 |
| 멘토 분석 작성과 결과보고서 완성 | 초대 코드 발행 |
| 허용받은 경우 배정 멘티의 프로젝트 대리 개설 | 멘토 배정 |

**배정에서 빠지면 그 순간부터 그 프로젝트가 보이지 않는다.** 화면에는 이렇게 뜬다.

> 이 프로젝트에 접근할 권한이 없습니다. 멘토는 현재 배정된 멘티의 프로젝트만
> 열람·수정할 수 있습니다.

배정은 관리자나 프로그램 매니저가 한다. 멘티 한 명에게 멘토는 한 명이며, 배정은 그
멘티의 모든 프로젝트에 적용된다.

## 6.2 멘토 분석(보고) 작성

워크시트 아래에 "멘토 분석(보고)" 절이 있다. 여기 적은 내용이 **결과보고서로 그대로
들어간다.** 워크시트 코멘트와는 다른 기능이다.

### 누가 쓸 수 있나

| 사람 | 할 수 있는 일 |
| --- | --- |
| 배정된 멘토 본인 | 작성, 저장 |
| 관리자 | 초안 열람만. "관리자 열람 전용입니다. 작성·저장·완료는 배정 멘토만 가능합니다." 가 뜬다 |
| 멘티와 그 밖 | 이 절 자체가 보이지 않는다 |

### 대상 워크시트 여덟 개

| 워크시트 | 입력 항목 |
| --- | --- |
| WS-2 AS-IS 스펙표 | 분석 내용 |
| WS-3 제품속성서 | 분석 내용 |
| WS-4 제품속성적합도 | 분석 내용 |
| WS-12 최종목표스펙 | 항목별 이름과 설명. 최대 500 개 |
| WS-13 개선 제품(서비스) | 개선 제품(서비스)명, 개선 제품 설명 |
| WS-15 핵심자산 및 보완자산 | 핵심자산 분석, 보완자산 분석 |
| WS-16 자금소요계획 | 분석 내용 |
| WS-17 자금조달계획 | 분석 내용 |

나머지 워크시트에는 이 절이 나오지 않는다.

### WS-12 는 항목별로 쓴다

WS-12 만 형태가 다르다. "WS-12 항목 불러오기" 를 누르면 최종 목표 스펙의 행을
"분류 / 세부항목 / 기술적 특성" 꼴로 가져와 항목 목록을 만든다. 항목마다 설명을
적는다.

불러오기는 **중복 없이 뒤에 덧붙인다.** 기존 설명은 그대로 남는다. 다만 이름이
바뀌거나 지워진 항목은 알아서 정리해 주지 않으므로 직접 확인해야 한다. 화면에도 같은
안내가 뜬다.

> 최신 스펙 항목을 추가했습니다. 기존 설명은 유지되며, 변경되거나 삭제된 항목은 직접
> 확인해 주세요.

**WS-12 를 먼저 저장한 뒤에 불러와야** 최신 항목이 들어온다.

### 저장과 주의점

"멘토 분석 저장" 을 누른다. 성공하면 이렇게 뜬다.

> 분석을 저장했습니다. 결과보고서에서 미리보기를 다시 만들면 반영됩니다.

**저장만으로 보고서에 들어가지 않는다.** 결과보고서 화면에서 미리보기를 다시 만들어야
반영된다.

다른 화면에서 같은 내용을 동시에 고치면 충돌 안내가 뜬다.

> 다른 화면에서 분석 또는 보고서를 변경했습니다. 현재 입력은 유지됩니다. 필요한
> 내용을 복사한 후 저장본을 다시 불러와 주세요.

**현재 입력은 사라지지 않는다.** 필요한 부분을 복사해 두고 "저장본 다시 불러오기" 를
누른 뒤 다시 붙여 넣는다.

저장하지 않은 채 화면을 옮기려 하면 확인 창이 뜬다. 뒤로가기에서도 마찬가지다.

## 6.3 워크시트 의견

개요 화면의 탭 아래 "멘토 의견" 절이다. **워크시트 주소로 직접 연 화면에는 이 절이
없으므로**, 의견을 남기려면 프로젝트 개요 화면에서 탭으로 이동한다.

- 배정 멘토 본인과 관리자만 쓸 수 있다. 다른 사람은 읽기만 한다.
- 최대 5,000 자다.
- 본인이 쓴 의견만 고치고 지울 수 있다.
- 의견을 달 수 있는 화면은 개요와 16 개 워크시트다.

멘토 분석과 무엇이 다른지 정리하면 이렇다.

| | 멘토 의견 | 멘토 분석(보고) |
| --- | --- | --- |
| 어디에 | 개요 화면 탭 아래만 | 워크시트 주소와 개요 탭 양쪽 |
| 어느 워크시트 | 개요 포함 17 개 | 여덟 개 |
| 누가 읽나 | 프로젝트를 볼 수 있는 모두 | 배정 멘토와 관리자 |
| 결과보고서 반영 | 안 된다 | 된다 |
| 쓰임 | 멘티에게 주는 피드백 | 보고서에 들어갈 정식 분석 |

## 6.4 결과보고서 작성

**결과보고서를 만들고 완료하는 것은 배정 멘토만 할 수 있다.** 관리자는 초안을 볼 수
있고, 멘티는 멘토가 완료한 뒤에야 열람한다.

작성 절차 전체는 [8부](08-final-report.md)에 있다. 순서만 적으면 이렇다.

1. 여덟 개 워크시트에 멘토 분석을 쓴다.
2. 결과보고서 화면에서 "미리보기 만들기" 를 누른다.
3. 문서 내용을 확인하고 필요하면 그 자리에서 고친다.
4. "초안 저장" 으로 저장한다.
5. "완료" 를 눌러 멘티에게 공개한다.

## 6.5 프로젝트 대리 개설

관리자가 허용한 멘토만 쓸 수 있다. 허용 전에는 대시보드의 버튼이 "새 프로젝트
(사용중지)" 로 비활성이고, 마우스를 올리면 "관리자가 멘토별로 프로젝트 생성을
활성화할 수 있습니다." 가 나온다.

허용되면 "+ 새 프로젝트" 폼에 "소유할 배정 멘티" 칸이 생긴다. 고른 멘티 소유로
프로젝트가 만들어진다. 화면의 안내는 이렇다.

> 프로젝트는 선택한 멘티 소유로 개설됩니다. 두 번째부터는 프로그램 매니저의 개별
> 승인이 필요합니다.

**고른 멘티가 이미 프로젝트를 갖고 있으면 "추가 프로젝트 개설 승인" 칸이 하나 더
생긴다.** 그 멘티가 신청하고 매니저가 승인한 건을 골라야 한다. 승인이 없으면 이렇게
뜬다.

> 사용 가능한 승인이 없습니다. 멘티가 추가 개설을 신청하고 프로그램 매니저의 승인을
> 받은 뒤 다시 열어 주세요.

후보 멘티가 없으면 "개설 가능한 배정 멘티가 없습니다. 관리자 또는 프로그램 매니저에게
배정을 요청하세요." 가 뜬다.

**멘토가 만든 프로젝트에서 멘토의 역할은 편집자다.** 소유자는 멘티다.

## 6.6 멘토가 자주 겪는 상황

| 상황 | 원인과 조치 |
| --- | --- |
| 프로젝트가 대시보드에 안 보인다 | 배정이 아직 안 됐거나 해제됐다. 매니저에게 확인한다 |
| 워크시트가 잠겨 있다 | 배정이 해제됐다. 배정 상태를 확인한다 |
| 멘토 분석 절이 안 보인다 | 그 워크시트가 여덟 개 대상이 아니거나 배정 멘토가 아니다 |
| 멘토 의견을 쓸 칸이 없다 | 워크시트 주소로 열었다. 개요 화면의 탭에서 연다 |
| 보고서에 분석이 안 들어간다 | 저장 뒤 미리보기를 다시 만들지 않았다 |
| WS-12 항목이 안 나온다 | WS-12 를 먼저 저장한다 |
| 결과보고서 버튼이 눌리지 않는다 | 배정 멘토가 아니다. 관리자는 열람만 된다 |
