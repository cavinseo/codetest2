# 10부. AI 지원 기능

몇몇 워크시트에는 초안을 만들어 주는 도우미가 붙어 있다. 어떤 엔진으로 만들지는
회원마다 정한다.

## 10.1 먼저 알아야 할 원칙

**AI 연결이 실패해도 작업은 멈추지 않는다.** 연결이 안 되면 규칙 기반으로 자동
전환되어 초안이 계속 만들어진다. 결과에 붙는 엔진 배지에 "(폴백)" 이 붙어 어느
쪽으로 만들어졌는지 알 수 있다.

그래서 "AI 가 안 붙는다" 는 대개 오류가 아니라 결과 품질의 문제다.

**개인 API 키를 쓰면 요금은 본인 벤더 계정에 청구된다.** 서비스가 대신 내지 않는다.

**키는 저장 뒤 화면으로 돌아오지 않는다.** 암호화되어 보관되고 다른 회원과 공유되지
않는다.

## 10.2 내 AI 연결

`/profile` 사용자 정보 화면과 `/settings` 서비스 설정의 "AI 엔진" 탭에 같은 카드가
있다. 둘은 같은 값을 본다.

카드 설명은 이렇다.

> 규칙 기반 또는 본인의 API·원격 MCP·로컬 AI를 선택할 수 있습니다. 인증 키는
> 암호화되어 저장되고 다시 표시되지 않으며 다른 회원과 공유되지 않습니다.

### 연결 방식 네 가지

| 방식 | 화면 설명 |
| --- | --- |
| 규칙 기반 | 설정 없이 바로 씁니다. 프로젝트 문맥으로 초안을 조립합니다. |
| API 연결 (OpenAI · Claude · Gemini) | 본인의 벤더 API 키로 호출합니다. 요금은 본인 벤더 계정에 청구됩니다. |
| 원격 MCP (Remote/HTTP) | 본인이 운영하는 원격 OpenAI 호환 엔드포인트(https)로 호출합니다. |
| 로컬 AI (Ollama · LM Studio) | 내 PC의 로컬 LLM을 씁니다. 온라인 서버에서는 연결되지 않을 수 있으며, 그 경우 규칙 기반으로 자동 전환됩니다. |

방식을 바꾸면 키 입력칸이 비워진다. 다른 방식의 키가 섞이지 않게 하기 위해서다.

### API 연결 설정

벤더와 모델, API 키를 넣는다.

| 벤더 | 화면 표기 | 키 형태 안내 | 기본 모델 |
| --- | --- | --- | --- |
| OpenAI | OpenAI (ChatGPT) | `sk-...` | gpt-4o-mini |
| Claude | Claude (Anthropic) | `sk-ant-...` | claude-haiku-4-5 |
| Gemini | Gemini (Google) | `AIza...` | gemini-2.0-flash |

모델 칸은 비워 두면 기본 모델을 쓴다. **기본 모델은 각 벤더의 저가 라인으로 잡혀
있다.** 요금이 본인에게 청구되기 때문이다. 필요하면 바꾼다.

주소를 직접 넣을 수 없고 벤더를 고르는 방식이다. 사용자가 내부망 주소를 넣어 서버가
대신 두드리게 만드는 일을 막기 위해서다.

이미 같은 벤더로 키가 저장돼 있으면 키 칸 옆에 "(비워 두면 저장된 키 유지)" 가
나온다. 모델만 바꾸고 싶을 때 키를 다시 넣지 않아도 된다.

### 원격 MCP 설정

본인이 운영하는 OpenAI 호환 주소를 쓴다. 주소에 제한이 있다.

| 조건 | 어길 때 문구 |
| --- | --- |
| https 여야 한다 | 원격 엔드포인트는 https 만 허용됩니다. |
| 주소에 아이디·비밀번호를 넣을 수 없다 | URL 에 인증 정보를 넣을 수 없습니다. 키 칸을 쓰세요. |
| IP 가 아니라 도메인이어야 한다 | IP 주소가 아닌 도메인 주소를 입력하세요. |
| 내부망 주소는 안 된다 | 내부망 주소는 사용할 수 없습니다. |

실제로 호출할 때도 공인 주소인지 다시 확인하고, 다른 주소로 넘기는 것을 허용하지
않는다. 최종 주소를 정확히 넣어야 한다.

### 로컬 AI 설정

주소를 비워 두면 흔한 주소를 차례로 찾는다. Ollama(11434), LM Studio(1234),
vLLM(8000) 순이다.

화면에 경고가 붙어 있다.

> 온라인 접속 시에는 서버가 내 PC 에 닿지 못해 규칙 기반으로 자동 전환될 수 있습니다.

인터넷에 올린 서버에서는 서버의 로컬이 내 PC 가 아니기 때문이다. 이 경우를 위해
**브라우저가 내 PC 의 로컬 AI 를 직접 부르는 경로**가 준비되어 있다. WS-2 의 FAST
작성 지원이 그 경로를 쓰며 진행 문구가 순서대로 나온다.

> 내 PC에서 로컬 AI를 찾는 중... → {모델} 모델로 생성 중... (최대 90초) → 결과를
> 검증하는 중...

찾지 못하면 이렇게 안내하고 기본 엔진 결과를 쓴다.

> 로컬 AI를 찾지 못해 기본 엔진으로 만들었습니다. Ollama·LM Studio 실행 여부와 CORS
> 설정을 확인하세요.

### 저장과 연결 확인

- **저장.** 규칙 기반과 로컬은 언제나 저장되고, 원격 MCP 는 주소가 있어야, API 는 키를
  넣었거나 같은 벤더 키가 이미 저장돼 있어야 저장된다. 규칙 기반이 아니면 저장 뒤
  "저장했습니다. [연결 확인]으로 연결 상태를 점검해 보세요." 가 뜬다.
- **연결 확인.** 규칙 기반이 아닐 때만 보인다. 짧은 요청을 한 번 보내 본다.
- **삭제.** 저장된 연결이 있을 때만 보인다. "저장된 AI 연결 설정을 삭제하시겠습니까?"
  확인을 거친다.

### 연결 확인 결과 읽기

| 문구 | 뜻과 조치 |
| --- | --- |
| 연결에 성공했습니다. | 정상이다 |
| 규칙 기반은 별도 연결이 필요 없습니다. | 확인할 것이 없다 |
| API 키가 유효하지 않습니다. 키를 다시 확인하세요. | 키를 새로 발급해 저장한다 |
| 모델을 찾을 수 없습니다. 모델 이름을 확인하세요. | 모델 이름을 고친다 |
| 요청 한도를 초과했습니다. 벤더 계정의 한도를 확인하세요. | 벤더 계정에서 한도와 결제를 본다 |
| 벤더 응답 오류 (HTTP N) | 벤더 쪽 문제다. 잠시 뒤 다시 한다 |
| 벤더에 연결하지 못했습니다. 네트워크를 확인하세요. | 네트워크를 확인한다 |
| 서버에서 로컬 엔진에 연결하지 못했습니다. 온라인 환경에서는 정상이며, 규칙 기반으로 자동 전환됩니다. | 배포 환경에서는 정상 동작이다 |

**Gemini 는 실패 이유를 나누어 안내한다.**

| 문구 | 조치 |
| --- | --- |
| Gemini API 키가 유효하지 않습니다. Google AI Studio에서 새 키를 저장하세요. | 새 키를 발급받는다 |
| Gemini API 사용이 제한되어 있습니다. Google AI Studio에서 키 제한을 확인하거나 새 키를 저장하세요. | 키에 걸린 제한을 푼다 |
| Gemini API 이용 조건을 확인하세요. 지원 지역 또는 결제 설정이 필요할 수 있습니다. | 지역과 결제 설정을 본다 |
| Gemini가 요청을 거부했습니다. API 키와 모델을 확인하세요. | 키와 모델 이름을 다시 본다 |

**벤더가 보낸 원문은 화면에 그대로 나오지 않는다.** 정해진 문구로 바꿔 보여 준다.
키 값과 응답 본문은 화면에도 로그에도 남지 않는다.

## 10.3 AI 가 붙는 자리

| 자리 | 하는 일 | 외부 AI 호출 |
| --- | --- | --- |
| WS-2 FAST 작성 지원 | 세부설명과 원하는 기능으로 4 단 스펙표 초안을 만든다 | 한다 |
| WS-3 AI 멘토링 마법사 | 문진에 답하면 세분시장·고객·니즈 초안을 만들고 WS-2 기능을 연결한다 | 한다 |
| WS-2 기능분석 작성 도우미 | 외부 AI 에 붙여 넣을 **프롬프트를 만들어 준다** | **하지 않는다** |
| WS-5 AI 자동생성 | WS-3 제품속성으로 요구사항 문장을 만든다 | **하지 않는다** |

뒤의 두 가지는 이름에 AI 가 들어 있지만 규칙으로 문장을 조립하거나 프롬프트만 만드는
기능이다. 키가 없어도 그대로 쓸 수 있다.

**기능분석 작성 도우미는 WS-10 이 아니라 WS-2 화면에 있다.**

각 도우미의 사용법은 [7부](07-worksheets.md)의 해당 절에 있다.

## 10.4 프로젝트별 AI 모드

프로젝트마다 AI 연결 방식을 따로 두는 구조가 준비돼 있다. 값은 세 가지다.

| 값 | 라벨 | 설명 |
| --- | --- | --- |
| rule | 규칙 기반만 사용 | 설치나 설정 없이 바로 씁니다. 프로젝트 문맥으로 초안을 조립합니다. |
| local | 로컬 AI 연결 (Ollama · LM Studio) | 내 PC의 로컬 LLM을 씁니다. 찾지 못하면 규칙 기반으로 자동 전환됩니다. |
| personal | 내 AI (개인 키) | 사용자 정보에서 등록한 본인의 키를 씁니다. 실패하면 규칙 기반으로 자동 전환됩니다. |

기본값은 규칙 기반이다.

> **지금은 이 값을 고르는 화면이 없다.** 설정은 준비돼 있지만 화면에 선택 자리가
> 나오지 않는다. 실제로는 회원 본인의 "내 AI 연결" 설정이 쓰인다. 개인 연결이 규칙
> 기반이 아니면 그 연결로, 아니면 규칙 기반으로 동작한다.

따라서 **AI 를 붙이려면 프로젝트가 아니라 사용자 정보 화면에서 설정한다.**

## 10.5 문제가 생겼을 때

| 상황 | 확인할 것 |
| --- | --- |
| 결과 배지에 "(폴백)" 이 붙는다 | 연결이 실패해 규칙 기반으로 돌았다. 연결 확인을 눌러 원인을 본다 |
| 키를 넣었는데 계속 규칙 기반이다 | 저장이 됐는지, 연결 확인이 성공하는지 본다 |
| 로컬 AI 가 안 잡힌다 | Ollama 나 LM Studio 가 켜져 있는지, 브라우저에서 접근이 막히지 않는지 본다 |
| 원격 MCP 주소가 저장되지 않는다 | https 인지, 내부망이나 IP 가 아닌지 본다 |
| 요금이 걱정된다 | 모델을 저가 라인으로 두고 벤더 계정에서 한도를 건다 |
| 키를 잘못 넣었다 | 같은 벤더로 새 키를 넣어 저장하면 덮어쓴다. 지우려면 삭제를 쓴다 |

서비스 설정 화면의 AI 탭에도 같은 카드가 있으며, 그 탭에 **서비스 전체에 걸리는 AI
설정은 없다.** 지금 로그인한 본인의 연결을 설정하는 자리다.
