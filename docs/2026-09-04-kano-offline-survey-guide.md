# Kano 오프라인 HTML 설문 운영 지침

인터넷 연결이 어려운 현장에서 Kano 설문 HTML을 배포하고 답변 파일을 회수해 등록할 때 따르는 절차다.

## 언제 쓰는가

**기기는 있지만 인터넷 연결이 없는 현장에서는 오프라인 HTML을 쓴다.**

| 상황 | 방법 |
| --- | --- |
| 인터넷에 연결된 응답자가 바로 답할 수 있다 | 온라인 초대 링크를 쓴다. |
| 노트북·휴대전화는 있지만 현장에서 인터넷을 쓸 수 없다 | 오프라인 HTML을 배포하고 저장된 답변 파일을 회수한다. |
| 기기를 쓰기 어렵고 종이로 받아야 한다 | Word 종이 설문을 쓰고 결과를 엑셀로 손입력한다. |
| HTML 파일을 주고받기 어려운 환경이다 | Word 종이 설문과 엑셀 손입력 경로로 보완한다. |

오프라인 HTML은 인터넷이나 CDN 없이 파일 하나로 열리고, 인쇄하면 답변 저장 영역이 숨겨진다.
회사 보안 정책이 HTML 첨부를 허용하는지와 특정 메신저에서 파일을 주고받을 수 있는지는 확인되지 않았다.
실제 배포 전에 사용할 기기와 전달 채널로 파일 열기·답변 저장·회신까지 파일럿해야 한다.

## 배포 절차

1. 배포 환경에서 `NEXT_PUBLIC_KANO_OFFLINE_SURVEY=on`으로 설정해 기능을 노출한다.
2. 프로젝트의 Kano 설문 화면에서 「오프라인 HTML 받기」를 누른다.
3. 내려받은 `Kano_설문_<프로젝트명>.html`을 파일럿에서 검증한 채널로 전달한다.
4. 응답자에게 아래 안내문을 함께 보낸다.

> 받은 HTML 파일을 열고 모든 질문에 답한 뒤 「답변 저장」을 눌러 주세요. 내려받아진 `kano-response-<8자>.html` 파일을 담당자에게 그대로 회신해 주세요. 다운로드가 막히면 화면에 나타나는 「내용 복사」를 눌러 복사한 내용을 담당자에게 보내 주세요.

응답자가 답을 덜 고르면 저장이 막히고 첫 번째 미답 문항이 강조된다. 저장된 답변 파일을 다시 열면
기존 답과 이메일이 복원된다. 수정해 다시 저장해도 같은 `submissionId`를 쓰므로 같은 응답을 갱신한다.

## 수집 절차

1. 회신받은 `.html`·`.htm`·`.json` 파일을 한 폴더에 모은다. 「내용 복사」로 받은 JSON은 내용을 바꾸지 말고 `.json` 파일로 준비한다.
2. 응답을 받을 프로젝트의 Kano 설문 화면에서 「오프라인 응답 파일 업로드」 카드를 찾는다.
3. 파일을 고른 뒤 검사 결과를 확인하고 「업로드」를 누른다. 파일 하나는 400KB 이하여야 한다.
4. 파일이 10개를 넘으면 화면이 10개씩 순서대로 배치해 등록한다. 한 배치가 409 또는 오류로 끝나면 다음 배치를 보내지 않고 남은 파일 수를 알린다.
5. 결과 패널의 등록 인원·응답 수와 실패 파일을 확인한다. 같은 파일은 `submissionId` 기준으로 안전하게 다시 시도할 수 있다.

실패 파일은 화면 문구에 따라 다음처럼 처리한다.

| 화면 문구 | 원인 | 담당자가 할 일 |
| --- | --- | --- |
| `GUARD` — 가드 문구 그대로 표시된다. 예를 들어 “빈 파일입니다. 내용이 있는 답변 파일을 올려 주세요.”, “파일 크기는 400KB를 초과할 수 없습니다.”, “.html 또는 .htm 또는 .json 파일만 업로드할 수 있습니다.”가 나온다. | 파일이 비었거나 400KB를 넘었거나 허용 확장자가 아니다. | 원본을 편집하지 말고 응답자에게서 허용 형식과 크기의 저장 결과를 다시 받는다. |
| `PARSE` — “아직 답하지 않은 원본 설문 파일입니다”. | 응답자가 「답변 저장」을 누르기 전의 배포용 설문 파일이다. | 응답자에게 모든 문항에 답하고 「답변 저장」으로 받은 파일을 회신해 달라고 한다. |
| `PARSE` — “이 앱이 만든 설문 파일이 아닙니다”. | HTML 안에 이 앱의 응답 데이터 영역이 없다. | 이 앱에서 받은 설문으로 다시 응답하고 저장한 HTML을 회신받는다. |
| `PARSE` — “답변 파일 형식이 올바르지 않습니다”. | JSON이나 응답 데이터의 필수 형식이 깨졌거나 값이 유효하지 않다. | 파일을 직접 고치지 말고 응답자가 다시 저장한 HTML 또는 「내용 복사」 결과를 받는다. |
| `WRONG_PROJECT` — “다른 프로젝트의 답변 파일입니다”. | 파일의 프로젝트와 현재 업로드 화면의 프로젝트가 다르다. | 파일이 속한 프로젝트 화면에서 올리거나 올바른 프로젝트의 설문으로 다시 받는다. |
| `UNKNOWN_REQUIREMENT` — “현재 설문에서 찾을 수 없는 문항입니다”. | 파일의 답을 현재 설문 문항에 연결할 수 없다. | 현재 설문으로 다시 응답받는다. 질문 변경 충돌이라면 아래 409 절차를 먼저 따른다. |
| `DUPLICATE_IN_BATCH` — “같은 응답자가 이 배치에 중복되어 있습니다”. | 같은 이메일이나 `submissionId`의 파일이 한 배치에 둘 이상 있다. | 응답자별로 최종 파일 하나만 남겨 다시 올린다. |
| `RESPONDENT_EXISTS` — “이미 다른 방법으로 응답한 이메일입니다”. | 같은 이메일의 온라인·엑셀·Google Forms 응답이 이미 있다. | 기존 응답을 바꿀 의도가 분명하면 「해당 파일만 덮어쓰기」를 누르고, 아니면 해당 파일을 제외한다. |

설문 배포 뒤 질문이 바뀌면 409 안내에 추가·삭제·문구 변경 수와 영향 파일이 나온다. 변경 내용을
확인하고 일부 답이 빠질 수 있음을 받아들일 때만 「일치하는 문항만 등록」을 누른다. id와 문구가
그대로인 문항의 답은 등록되고 문구가 바뀐 문항의 답은 버려지며, 결과 패널이 버린 답의 수를 알린다.
id가 모두 바뀌었어도 같은 문구의 현재 문항이 정확히 하나일 때만 그 문항으로 다시 연결된다.

이메일이 없는 답변은 합성 이메일로 저장된다. `submissionId`(하이픈이 든 UUID)에서 하이픈을 지운 뒤
앞 12자를 써서 `offline-<12자리 16진수>@import.local` 형식이 된다 — `submissionId` 가
`a1b2c3d4-e5f6-4a7b-8c9d-0e1f2a3b4c5d` 이면 `offline-a1b2c3d4e5f6@import.local` 이다.
초대 내역에서 답변 파일과 응답자를 맞춰 볼 때 이 규칙으로 찾으면 된다.

오프라인 초대 토큰은 `offline_<submissionId>` 형식이며 즉시 만료되므로 그 토큰으로 온라인 응답을 할 수 없다.

## 하지 말 것

- 설문을 배포한 뒤 요구사항을 AI로 다시 생성하거나 JSON으로 이관하지 않는다. id가 바뀌면 문구가 같은 현재 문항이 정확히 하나인 답만 다시 연결되고 나머지는 빠진다.
- 같은 답변 파일을 여러 번 저장해 여러 장 보내라고 안내하지 않는다. 같은 `submissionId`라 마지막 저장 내용만 남지만 담당자가 어느 파일이 최종본인지 헷갈린다.
- 응답자에게 HTML이나 JSON 파일을 직접 편집하라고 안내하지 않는다. 형식이 깨지면 답변 파일로 읽을 수 없다.

## 되돌리기

`NEXT_PUBLIC_KANO_OFFLINE_SURVEY`를 `on`이 아닌 값으로 바꾸면 화면에서 「오프라인 HTML 받기」와
「오프라인 응답 파일 업로드」 카드가 사라진다. 플래그를 꺼도 이미 들어온 응답과 초대는 남는다.

오프라인 응답만 골라 지우는 수단은 없다. 지우려면 온라인·엑셀 등 다른 경로의 응답까지 포함하는
프로젝트 전체 리셋을 해야 한다. 따라서 파일럿은 실제 운영 프로젝트와 분리한 별도 프로젝트에서 한다.
