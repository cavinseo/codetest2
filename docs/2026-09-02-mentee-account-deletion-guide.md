# 멘티 계정 삭제 운영 지침

관리자 화면에서 멘티 계정을 지울 때 따르는 절차다. 설계 근거는
`docs/superpowers/specs/2026-09-02-mentee-account-deletion-design.md` 에 있다.

## 한 줄 원칙

**막는 것이 기본이고, 지우는 것은 개인정보를 파기해야 할 때만 한다.**

## 언제 무엇을 하는가

| 상황 | 조치 |
| --- | --- |
| 프로그램이 끝났다 | **승인 취소** |
| 이용 기간이 만료됐다 | **승인 취소**(또는 그대로 둔다) |
| 중도 이탈했다 | **승인 취소** |
| 문제 행동으로 접근을 막아야 한다 | **승인 취소** |
| 본인이 계정 삭제·개인정보 파기를 요구했다 | **삭제** |
| 잘못 만든 계정이거나 테스트 계정이다 | **삭제** |

승인 취소는 `status` 를 되돌리고 세션을 끊는다. 로그인도 이미 로그인해 둔 기기도 즉시 막힌다.
데이터는 한 줄도 건드리지 않으므로, **접근 차단이 목적이라면 삭제가 나은 점이 하나도 없다.**

## 삭제 절차

관리자 화면의 회원 관리 목록에서 시작한다.

1. 지울 회원 행의 **삭제** 를 누른다.
2. 확인창에서 한 번 더 **삭제** 를 누른다. 이때는 아무것도 지워지지 않는다. 서버가 무엇이 벌어질지 계산해 돌려준다.
3. **마지막 확인** 창에 결과가 나온다. 어느 프로젝트가 누구에게 넘어가는지, 이력 몇 건의 주인이 비워지는지, 초대 코드 몇 건이 지워지는지다.
4. **삭제 사유** 를 고른다. 고르기 전에는 확정 버튼이 눌리지 않는다.
5. **삭제** 를 누르면 실행된다. 되돌릴 수 없다.

읽고 나서 마음이 바뀌면 **뒤로** 를 눌러 되돌아갈 수 있다. 되돌아간 뒤 다시 진행해도 마지막 확인을 다시 거친다.

### 사유 세 가지

| 사유 | 쓰는 때 |
| --- | --- |
| 본인 요청 | 정보주체가 계정 삭제나 개인정보 파기를 요구했다 |
| 오등록 | 잘못 만든 계정, 테스트 계정 |
| 보유기간 경과 | 보관 기간이 지나 정리한다(자동 파기 기능은 아직 없다) |

사유는 파기의 증빙이다. 로그에 사유와 건수가 남고, 이메일은 남지 않는다.

## 무엇이 사라지고 무엇이 남는가

| 사라진다 | 남는다 |
| --- | --- |
| 이름·이메일·비밀번호 | 소유했던 프로젝트와 그 안의 워크시트 전부 |
| 소속·직책·연락처·기업 정보(회원 프로필) | 설문 초대와 응답(발송자만 비워진다) |
| 개인 AI 연결 설정과 저장된 키 | 엑셀 가져오기 이력(가져온 사람만 비워진다) |
| 그 이메일로 발급된 초대 코드 전부 | 다른 사람이 만든 프로젝트의 내용 |
| 다른 프로젝트에 참여한 기록 | |

소유했던 프로젝트는 **그 프로그램의 매니저에게 넘어간다.** 프로그램은 멘티들의 프로젝트로 구성되므로
사람이 빠졌다고 작업물이 사라지면 안 된다. 넘겨받은 매니저는 그 프로젝트를 편집할 수 있다.

설문 응답자의 이메일은 응답자의 정보이고 프로젝트에 속한다. 멘티를 지워도 건드리지 않는다.

## 알아 둘 것

- **재가입해도 이전 프로젝트는 돌아오지 않는다.** 같은 이메일로 다시 가입하면 새 계정이다. 파기한 것을 되살리면 파기의 의미가 없다.
- **프로그램 담당자는 이 절차로 지울 수 없다.** "담당 중인 프로그램이 있어 삭제할 수 없습니다" 가 나오면 그 프로그램의 담당자를 다른 사람으로 먼저 옮긴다.
- **다른 역할(멘토·매니저)의 삭제는 다르게 동작한다.** 그쪽은 소유한 프로젝트가 함께 삭제된다. 이 지침은 멘티 전용이다.

## 파기 완료를 답할 때

본인 요청으로 지웠다면 요청자에게 알린다. 운영 DB 에서는 즉시 파기되지만 백업본은 그렇지 않으므로,
아래 두 가지를 함께 말해야 정확하다.

- 운영 DB 에서 파기했다.
- 자동 백업본은 **최대 7일 뒤** 소멸한다.

**Supabase 자동 백업 보존 주기는 7일이다**(2026-09-03 확인). 답변 문장 예시는 이렇다.

> 회원님의 계정과 개인정보를 운영 데이터베이스에서 파기했습니다. 자동 백업본에 남은 사본은
> 보존 주기에 따라 최대 7일 뒤 소멸합니다.

백업 정책이 바뀌면 이 숫자도 함께 고쳐야 한다. 지침에 적힌 값과 실제 설정이 갈리면 잘못된 답을 하게 된다.

### 7일 안에 백업을 복원했다면

복원은 파기 이전 시점의 데이터를 되돌리므로 **지웠던 계정이 다시 살아날 수 있다.** 백업을 복원한
뒤에는 그 사이 파기한 계정이 되살아났는지 확인하고, 되살아났다면 같은 절차로 다시 지운다.

## 내보낸 파일 취급

`scripts/export-current-db-data.mjs` 로 만든 JSON 덤프에는 회원의 개인정보가 그대로 들어 있다.
**쓰고 나면 즉시 지운다.** 이관·디버깅을 마친 덤프를 남겨 두면 파기한 정보가 그 파일에 살아 있다.

메신저·이슈·커밋 메시지에 회원의 이메일이나 임시 비밀번호를 옮겨 적지 않는다
(`lib/logger.ts` 의 규칙과 같은 이유다).
