# 관리자 계정·비밀번호 복구 절차

관리자 모드에 들어갈 수 없을 때 따라가는 순서다. 모든 명령은 **실데이터가 있는 원격
DB 를 바라보는 운영자 터미널**에서 사람이 직접 실행한다. 실행 AI 에게 위임하지 않는다.

## 먼저 알아야 할 구조

관리자 모드는 별도 계정이 아니라 일반 계정에 붙는 권한이다. 로그인은
`/api/auth/login` 이 처리하고, 관리자 화면은 `lib/authorization.ts` 의
`hasAdminAccess` 가 다시 한 번 막는다. 두 관문을 모두 통과해야 `/admin` 이 열린다.

| 값 | 어디서 보는가 | 통과 조건 |
| --- | --- | --- |
| `status` | 로그인 | `APPROVED` 여야 한다 |
| `accessExpiresAt` | 로그인 | 비어 있거나 미래여야 한다 |
| `role` | 관리자 게이트 | **첫 관문이다.** `ADMIN` 이 아니면 나머지는 소용없다 |
| `isAdmin` | 관리자 게이트 | `true` 면 통과한다 |
| `ADMIN_EMAILS` | 관리자 게이트 | `role=ADMIN` 인 계정의 주소가 목록에 있으면 통과한다 |

그래서 "관리자 계정을 잃었다"는 대개 둘 중 하나다. 어느 계정이 관리자였는지 모르거나,
계정은 아는데 위 다섯 값 중 하나가 어긋나 화면이 열리지 않는 것이다.

## 1단계 — 누가 관리자인지 찾는다

```sh
npm run find:admin
```

DB 를 읽기만 하는 스크립트다. 아무것도 쓰지 않으므로 먼저 돌려도 안전하다. 관리자
후보 계정을 모두 보여 주고, 들어갈 수 없는 계정은 무엇이 막는지까지 한 줄씩 적는다.

읽는 법은 이렇다.

- `[들어갈 수 있음]` 이 있다 — 계정은 살아 있다. 비밀번호만 잃은 것이므로 2단계로 간다.
- `[막힘]` 만 있다 — 붙어 있는 이유가 원인이다. 2단계가 `status`·`isAdmin`·`role` 을
  한꺼번에 바로잡는다.
- 아무 계정도 없다 — 관리자가 실제로 없다. 2단계에서 쓰던 계정을 관리자로 올리거나
  새로 만든다.
- `ADMIN_EMAILS 에 있으나 계정이 없는 주소` 가 보인다 — 환경 변수만 채워져 있고 계정이
  없는 상태다. 그 주소로는 로그인할 수 없으니 2단계에서 계정을 만든다.

## 2단계 — 권한을 바로잡고 임시 비밀번호를 받는다

```sh
npm run seed:admin -- <이메일> --reset-password
```

대상 DB 와 계정을 보여 주고 `y` 를 받은 뒤에만 쓴다. 하는 일은 이렇다.

- 계정이 있으면 `status=APPROVED`, `isAdmin=true`, `role=ADMIN` 으로 맞춘다.
- 계정이 없으면 그 주소로 새로 만들고 기본 프로필까지 넣는다.
- `--reset-password` 를 주면 임시 비밀번호를 새로 발급하고 `sessionVersion` 을 올려
  기존 로그인 세션을 전부 끊는다.

임시 비밀번호는 **터미널에 한 번만** 찍히고 어디에도 저장되지 않는다. 창을 닫기 전에
옮겨 적는다. 잃으면 같은 명령을 다시 돌리면 된다.

비밀번호는 그대로 두고 권한만 바로잡으려면 `--reset-password` 를 뺀다.

## 3단계 — 로그인하고 비밀번호를 바꾼다

`<주소>/admin` 에서 위 이메일과 임시 비밀번호로 로그인한다. 들어간 뒤 곧바로 비밀번호를
바꾼다(`/api/admin/password`). 이때도 `sessionVersion` 이 올라가 다른 기기의 세션은
끊어진다.

## 주의

- 임시 비밀번호를 메신저·이슈·커밋 메시지에 남기지 않는다. 로그와 응답 본문에 비밀번호와
  이메일을 남기지 않는 규칙(`lib/logger.ts`)과 같은 이유다.
- `ALLOW_DEV_ADMIN` 은 로컬 개발용 우회다. 배포 환경에서는 동작하지 않으므로 복구
  수단으로 쓰지 않는다. `npm run find:admin` 의 판정도 이 우회를 셈하지 않는다.
- 관리자는 화면에서 임명되지 않는다(`lib/member-roles.ts` 의 `canTransitionRole`).
  첫 관리자와 잃어버린 관리자는 위 스크립트로만 되살린다.
