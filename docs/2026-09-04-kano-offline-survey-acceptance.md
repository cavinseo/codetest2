# Kano 오프라인 HTML 설문 — 실계정 인수 검증 체크리스트

계획서 `docs/superpowers/plans/2026-09-04-kano-offline-html-survey.md` 의 Task 8 Step 2 다.
감리자가 컨테이너에서 확인할 수 있는 것(Step 1, 10단계 통과)은 끝났다. 여기 남은 것은
**리눅스 헤드리스에서 재현되지 않는 것들**이다 — Windows 브라우저의 다운로드 정책,
실제 로그인·권한, 원격 DB, Vercel 서버리스 상한.

각 항목의 "기대"는 코드에서 확인한 값이다. 다르게 나오면 그 자리에서 멈추고 무엇이
달랐는지 적어 두면 된다.

## 시작 전에

- [ ] **파일럿용 별도 프로젝트를 만든다.** 오프라인 응답만 골라 지우는 수단이 없다.
      지우려면 프로젝트 전체 리셋뿐이라, 실제 운영 프로젝트에서 하면 온라인·엑셀 응답까지
      함께 날아간다.
- [ ] 그 프로젝트에 고객요구사항을 **3건 이상** 등록한다. 요구사항이 0건이면 업로드 카드
      자체가 나오지 않는다.
- [ ] 배포 환경에 `NEXT_PUBLIC_KANO_OFFLINE_SURVEY=on` 을 넣고 배포한다.
      플래그가 없으면 「오프라인 HTML 받기」와 업로드 카드가 숨어 있다(라우트는 살아 있다).
- [ ] 브라우저 두 종(Chrome·Edge)에서 각각 밟는다. 다운로드 차단 정책이 다르다.

## A. 배포 — 설문 HTML 받기

- [ ] Kano 설문 화면에서 **「오프라인 HTML 받기」** 를 누른다.
      - 기대: 파일명이 `Kano_설문_<프로젝트명>.html`. 프로젝트명의 `\ / : * ? " < > |` 는
        `_` 로 바뀌고, 공백은 하나로 줄어들되 **그대로 남는다**. 60자를 넘으면 잘린다.
- [ ] 받은 파일을 **더블클릭**해서 연다(브라우저에 끌어다 놓지 말고, 응답자가 할 그대로).
      - 기대: 인터넷 없이도 화면이 완전히 그려진다. 글꼴·레이아웃이 깨지지 않는다.
      - 기대: 문항 수가 등록한 요구사항 수와 같고, 문항마다 라디오가 5+5개다.
- [ ] **Ctrl+P 로 인쇄 미리보기**를 연다.
      - 기대: 이메일 칸·「답변 저장」 버튼이 안 보인다(문항만 인쇄된다).

## B. 응답 — 저장과 재개

- [ ] 아무것도 고르지 않고 **「답변 저장」** 을 누른다.
      - 기대: 다운로드가 **일어나지 않는다**.
      - 기대: 문구가 `아직 답하지 않은 질문이 N개 있습니다.` (N = 문항 수 × 2)
      - 기대: 첫 번째 미답 문항에 빨간 테두리가 생기고 그리로 스크롤된다.
- [ ] 일부만 고르고 다시 누른다 → 남은 개수가 줄어드는지.
- [ ] 전부 고르고 **이메일을 대문자 섞어** 입력한 뒤 저장한다(예: `Test.User@Example.com`).
      - 기대: `kano-response-<8자리 16진수>.html` 이 내려온다.
      - **Windows 에서 여기가 가장 잘 막히는 지점이다.** 다운로드가 차단되거나
        "이 형식의 파일은 위험할 수 있습니다" 경고가 뜨면, 그 문구를 그대로 적어 둔다.
        경고를 눌러 받을 수 있는지도 확인한다 — 응답자에게 안내해야 할 문장이다.
- [ ] 다운로드가 막혔다면: 화면에 **「내용 복사」** 상자가 보이는지 확인하고 눌러 본다.
      - 기대: 클립보드에 JSON 이 들어오고, 그것을 `.json` 으로 저장하면 업로드에 쓸 수 있다.
- [ ] 받은 `kano-response-….html` 을 **다시 더블클릭**해서 연다.
      - 기대: 고른 답이 전부 복원되고 이메일도 그대로 있다.
      - 기대: 문구가 `이전에 저장한 답변이 실려 있습니다. 수정 후 다시 저장할 수 있습니다.`
      - 기대: 「내용 복사」 상자가 처음부터 보이고, **비어 있지 않다**.
- [ ] 답을 하나 바꿔 다시 저장한다.
      - 기대: **파일명이 아까와 같다**(같은 응답의 갱신이라는 뜻이다).

## C. 수집 — 업로드

- [ ] B 에서 받은 파일 하나를 **「오프라인 응답 파일 업로드」** 에 고른다.
      - 기대: 고르자마자 파일 옆에 `✓ 업로드할 수 있는 답변 파일`.
- [ ] 「업로드」를 누른다.
      - 기대: 성공 문구가 뜨고, **응답자 표·초대 내역·분석 화면에 반영**된다.
      - 기대: 초대 내역에서 이 응답자에 **오프라인 표시**가 붙고, 쓸모없는 「링크 복사」
        버튼이 보이지 않는다.
      - 기대: 이메일이 **소문자로** 저장돼 있다(`Test.User@…` → `test.user@…`).
- [ ] **같은 파일을 다시 업로드**한다.
      - 기대: 오류 없이 성공하고, **응답 수가 늘지 않는다**(같은 응답의 갱신).
- [ ] **이메일 없이** 저장한 파일을 하나 만들어 올린다.
      - 기대: 합성 이메일 `offline-<12자리 16진수>@import.local` 로 잡힌다.
        (하이픈 없는 16진수 12자다 — `offline-a1b2c3d4e5f6@import.local` 같은 모양)
- [ ] **원본(미답) 설문 HTML**(A 에서 받은 것)을 올린다.
      - 기대: 고르는 즉시 `✗ 답하지 않은 원본 설문 파일`, 업로드하면
        `아직 답하지 않은 원본 설문 파일입니다`.
- [ ] 아무 `.txt` 나 이미지 파일을 올려 본다.
      - 기대: `.html 또는 .htm 또는 .json 파일만 업로드할 수 있습니다.`

## D. 충돌 처리

- [ ] 응답을 하나 등록해 둔 상태에서, **요구사항 문구 하나를 수정·저장**한 뒤 그
      응답 파일을 다시 올린다.
      - 기대: 409 안내 — `설문 배포 후 질문이 바뀌었습니다(추가 N·삭제 N·문구 변경 N).`
        와 영향 파일 목록.
      - 기대: **「일치하는 문항만 등록」** 버튼이 뜬다. 누르면 등록되고,
        `문구가 바뀐 문항의 답 N개는 등록하지 않았습니다.` 가 함께 뜬다.
- [ ] **온라인 초대로 이미 응답한 이메일**을 답변 파일에 적어 올린다.
      - 기대: `이미 다른 방법으로 응답한 이메일입니다` 와 **「해당 파일만 덮어쓰기」** 버튼.
      - 기대: 덮어쓰기를 누르면 그 파일만 반영되고 다른 응답은 그대로다.
      - 참고: 이 판정은 **초대가 있으면** 걸린다. 초대만 보내고 아직 응답하지 않은
        이메일에도 같은 문구가 뜬다("응답한"이라는 표현이 정확하지 않은 자리다).
        그렇게 동작하는 게 맞는지 이 자리에서 한 번 봐 두면 좋다.

## E. 실배포(Vercel) — 여기서만 드러나는 것

로컬·컨테이너에 없는 계약이라 **반드시 실배포 URL 에서** 한다.

- [ ] 답변 파일을 **11개** 만든다(서로 다른 응답 11건). 한 번에 골라 업로드한다.
      - 기대: 진행 표시가 `1/2 배치` → `2/2 배치` 로 간다(10개 + 1개).
      - 기대: 최종 등록 인원이 11명이다.
      - 기대: 화면이 멈추거나 타임아웃되지 않는다.
- [ ] 그중 한 배치가 실패하도록 일부러 만들어 본다(예: 6번째 파일을 원본 설문 HTML 로 교체).
      - 기대: 실패 파일이 **파일명과 함께** 목록에 뜨고, 나머지는 정상 등록된다.
- [ ] 400KB 를 넘는 파일을 하나 올려 본다(문항이 아주 많은 설문이면 자연히 커진다).
      - 기대: `파일 크기는 400KB를 초과할 수 없습니다.`
- [ ] 업로드 직후 **Vercel 함수 로그**를 본다.
      - 기대: 이메일·파일명·submissionId 가 로그에 **없다**. 있으면 즉시 알린다.

## F. 되돌리기

- [ ] `NEXT_PUBLIC_KANO_OFFLINE_SURVEY` 를 지우거나 `off` 로 바꿔 재배포한다.
      - 기대: 「오프라인 HTML 받기」와 업로드 카드가 사라진다.
      - 기대: **이미 들어온 응답과 초대는 그대로 남아** 분석에 계속 반영된다.
      - 기대: 초대 내역의 오프라인 표시는 **그대로 보인다**(데이터가 있으면 참인 표시라
        기능 플래그와 분리해 두었다).

  나온 것인지 감리자가 되짚을 수 있다.
- 전부 통과하면 계획서 Task 8 Step 2 를 `- [x]` 로 바꾸고, 이 파일에 통과 날짜와
  브라우저 버전을 한 줄 남긴다.
- 확인되지 않은 채 남는 것들은 계획서 Task 8 Step 3 에 정리해 두었다. 배포 판단은
