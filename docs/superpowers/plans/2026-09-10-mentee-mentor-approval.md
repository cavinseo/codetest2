# 멘티·멘토 권한과 프로젝트 승인 구현 및 검수 계획

## 확정 정책

- 멘티는 멘토·프로그램 매니저·관리자로 전환할 수 없다. 관리자는 역할 변경 대상에서 제외한다.
- 역할 전환은 관리자에 의한 멘토 ↔ 프로그램 매니저만 허용한다.
- 프로그램 개설은 관리자만 가능하다. 담당 프로그램 매니저는 프로그램 운영과 멘토 배정을 수행한다.
- 관리자와 담당 프로그램 매니저가 멘티당 멘토 1명을 배정·교체·해제한다.
- 멘토는 배정된 멘티의 기존·신규 프로젝트를 조회하고 워크시트별 코멘트를 남기지만 본문을 수정하지 못한다.
- 멘티는 본인 소유 프로젝트 1개까지 직접 개설하며 이후 개설마다 승인 1건을 사용한다.
- 기존 프로젝트와 작성 데이터는 보존한다. 실DB 적용과 실제 계정 검증은 별도 완료 여부를 명시한다.

## 단계별 통과 지표

앞 단계의 필수 검수가 통과한 뒤 다음 단계 구현을 시작한다. 실패 시 해당 단계를 수정·재검증한다.

| 단계 | 필수 검수 지표 | 검증 수단 | 상태 |
|---|---|---|---|
| 0. 기준 확정 | 작업 트리 확인, 확정 정책 기록, 기존 테스트 기준 확보. | git 상태 및 전체 테스트. | 완료. 기준 119파일·1,396테스트. |
| 1. 회원·프로그램 권한 | 역할 전환 16조합 일치, 멘티/관리자 변경 UI 없음, 매니저 프로그램 개설 403·DB 쓰기 0, 운영 권한 유지. | 역할·API 회귀 테스트, 타입 검사, 변경 순수 모듈 mutation. | 통과. 154테스트·타입·린트, 134뮤턴트 100%. |
| 2. 배정 저장 구조 | 멘티당 단일 멘토 보장, 신규 테이블 참조 무결성, 기존 프로젝트 무삭제, 실DB 미접속. | Prisma validate/generate, SQL 검토. | 통과. validate/generate 성공, 신규 테이블만 생성. 실DB 미적용. |
| 3. 멘토 배정·열람 | 관리자/담당 PM만 배정, 타 PM 403, 해제 시 접근 회수, 옛 EDITOR 권한이 있어도 멘토 쓰기 403. | 배정·인가·목록 API 테스트. | 통과. 91테스트·타입 검사. |
| 4. 추가 개설 승인 | 1개 직접 생성, 2개째 승인 필요, 담당 PM 승인·반려, 승인 1회 소비, 동시 요청 직렬화, 기존 프로젝트 유지. | 생성·승인·트랜잭션 API 테스트. | 통과. 44테스트·타입 검사. 실제 DB 동시 요청 검증은 이월. |

- [ ] 마이그레이션 적용 후 실제 계정과 DB 동시 요청으로 인수 검수를 완료한다.

## 데이터 전환 원칙

기존 프로젝트별 COACH 배정은 멘티의 모든 프로젝트에 걸쳐 후보가 단일한 경우에만 멘티 배정으로 승계한다. 후보가 여러 명이면 자동 선택하지 않고 재배정 대상으로 남긴다. 기존 기록과 프로젝트는 삭제하지 않는다.

## 적용 경계

저장소의 실DB 보호 지침에 따라 개발 서버 기동과 원격 DB 변경을 수행하지 않는다. 코드·마이그레이션 파일·모의 테스트를 준비하며, 운영 적용을 했다고 보고하지 않는다.
