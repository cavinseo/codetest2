# 멘티 초대 코드 재발급

## 배경

2026-11 보안 점검에서 확인한 문제다. 멘티 초대 코드는 최초 가입뿐 아니라 이후 반복
로그인에도 쓰인다(`app/api/auth/invite-login`). 그 세션에서는 기존 비밀번호 없이 새
비밀번호를 정할 수 있다(`app/api/admin/password`, `verificationMethod: 'invite'`).
즉 코드는 비밀번호와 같은 값인데, 메일에 평문으로 남고 **바꿀 방법이 없다** — 사용했거나
회원이 연결된 코드는 회수·삭제가 막혀 있다. 메일이 전달·유출되면 대응 수단이 회원 삭제나
승인 취소뿐이다.

## 확정 기준

- 재발급은 유출 대응 수단이다. 코드를 잃어버린 멘티에게는 기존 "메일 재발송"을 쓴다.
- 같은 초대 행의 `code` 만 새 값으로 바꾼다. 발급 기록·기한·프로그램·회원 연결은 그대로다.
- 옛 코드는 즉시 쓸 수 없다. 회원이 연결돼 있으면 그 회원의 자격을 함께 돌린다.
  - `sessionVersion` 을 올려 이미 발급된 세션을 모두 끊는다(옛 코드로 로그인한 제3자 포함).
  - 비밀번호를 알 수 없는 임의 값으로 바꾼다. 옛 코드로 로그인한 제3자가 정해 둔
    비밀번호가 남으면 코드를 바꿔도 계정이 넘어간 채다. 멘티는 새 코드로 로그인해 다시 정한다.
- 권한은 기존 초대 관리와 같다: 관리자 전체, 매니저는 자신이 개설한 프로그램의 코드만.
- 만료된 코드는 재발급하지 않는다. 기한을 먼저 연장한다(메일 재발송과 같은 기준).
- 새 코드는 등록 이메일로 발송한다. 응답 본문에는 관리자에게만 코드를 싣는다(목록 API 와 같은 기준).
  매니저는 코드를 보지 못하므로, 메일이 실패하면 "메일 재발송"으로 다시 보낸다.
- 코드·이메일을 로그에 남기지 않는다.
