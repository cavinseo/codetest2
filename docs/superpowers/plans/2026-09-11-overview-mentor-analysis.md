# 개요 보강과 워크시트 멘토 분석 연동

## 마지막 개발 요청 원문과 재개 위치

> 개요에 추가되어야 하는 사항
>
> 1. 제품(서비스) 명
> 2. 제품 이미지
> 3. 시장정의
> 4. 목표 고객
>
> 다음 워크시트에는 '멘토만 작성하고  볼 수 있는 분석(보고) 기능추가하고 이 곳에 작성한 내용은 결과보고서의 해당 워크시트 부분에 반영한다.)
>
> 적용 워크시트는 ws-2,ws-3, ws-4, ws-12(최종목표스펙 항목별 설명), WS-15(핵심자산, 보완자산), ws-13(개선제품(서비스)명 및 개선제품 설명 ,ws-16,ws-17

2026-09-11 재개 위치는 1단계 개요 구현·검수 완료 후 2단계 권한 확정이다. 아직 운영에 배포하지 않았다.

확인이 필요한 두 항목은 다음과 같다. 답변을 받기 전에는 새 분석을 공개하지 않는다.

1. 멘토가 완료한 결과보고서에서는 멘티도 분석 내용을 볼 수 있는가.
2. 새 분석 초안은 관리자·미배정 프로그램 매니저도 제외하고 배정 멘토에게만 허용하는가. 기존 결과보고서 API는 관리자·매니저의 초안 열람을 허용한다.

## 요구사항과 보존 기준

- 개요에 프로젝트명과 별도의 제품(서비스)명, 제품 이미지, 시장정의, 목표 고객을 저장한다.
- 기존 프로젝트 데이터와 완료 보고서를 일괄 수정하지 않는다. 신규 필드는 선택 항목으로 추가한다.
- WS-2, WS-3, WS-4, WS-12, WS-13, WS-15, WS-16, WS-17에 멘토 분석(보고) 작성 영역을 둔다. 기존 공개 ‘멘토 의견’과 분리한다.
- WS-12는 최종 목표 스펙 항목별 설명, WS-13은 개선 제품명과 설명, WS-15는 핵심자산과 보완자산 분석을 구분한다.
- 저장된 분석은 결과보고서 미리보기의 해당 워크시트 부분에 반영한다. 기존 완료본은 다시 완료하기 전까지 유지한다.
- 완료 보고서의 분석 공개 범위와 관리자·매니저의 초안 열람 범위는 사용자 답변 후 확정한다.

## 단계별 실행과 검수

### 1. 개요 저장과 화면

- [x] 신규 필드 마이그레이션과 서버 입력 검증을 추가한다.
- [x] 개요의 편집·조회·취소에 네 항목을 연결한다. 이미지 최적화와 크기 제한을 적용한다.
- [x] 누락 필드의 기존 값 보존, 이미지 검증, 멘토의 원본 수정 거절을 테스트한다.

### 2. 멘토 분석 저장과 권한

- [ ] 지정한 8개 워크시트만 지원하는 분석 입력 계약을 정의한다.
- [ ] 기존 결과보고서 초안 저장 구조를 재사용하고 버전 충돌을 검사한다.
- [ ] 조회·저장 권한을 서버에서 강제한다. 멘티·미배정 멘토의 직접 API 접근을 거절한다.
- [ ] 다른 워크시트 분석과 기존 보고서 교정 내용을 덮어쓰지 않는지 검증한다.

### 3. 결과보고서 연결

- [ ] 개요의 신규 필드와 워크시트 분석을 해당 보고서 절에 넣는다.
- [ ] 기존 보고서 전용 입력은 보존하며 신규 원본이 없는 경우 호환한다.
- [ ] 분석 수정 시 미리보기 갱신 필요 상태와 버전을 갱신한다. 완료본은 보존한다.
- [ ] 미리보기와 Word 문서의 항목 매핑 및 완료본 공개 경계를 테스트한다.

### 4. 통합 검수

- [ ] 관련 테스트, 전체 테스트, lint, build를 실행한다.
- [ ] 격리 로컬 DB에서 마이그레이션·권한·저장·보고서 생성을 확인한다.
- [ ] 브라우저에서 편집·저장·재조회와 멘토 전용 표시를 확인한다.
- [ ] 검수 결과와 배포 전 필요한 DB 반영 절차를 기록한다. 운영 배포는 별도 요청 시 수행한다.
