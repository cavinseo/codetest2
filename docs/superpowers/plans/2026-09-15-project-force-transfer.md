## 계약.

관리자만 프로젝트 관리에서 다른 승인·유효 멘티로 이관한다. 이관은 새 프로젝트 생성이나 개설 승인 소비가 아니며 프로젝트 ID와 모든 하위 데이터를 보존한다. 대상 멘티의 소속 프로그램으로 프로젝트만 이동한다. 멘티 자체의 프로그램은 바꾸지 않는다.

원본 멘티에 유효한 담당 멘토가 있으면 대상 멘티에게 같은 멘토를 배정한다. 기존 대상 멘토가 다르면 대상의 다른 모든 프로젝트에도 적용되는 점과 프로젝트 수를 명확히 표시하고 확인한다. 원본의 멘토 배정은 유지한다. 원본 멘토가 없으면 대상의 기존 멘토는 유지한다. 원본 멘토가 미승인·만료·잘못된 역할이면 먼저 배정을 정리하도록 거절한다.

다른 프로그램 이관과 대상 멘토 교체는 선택 후 미리보기와 명시적 최종 확인을 거친다. 원본/대상 정보나 배정이 그 사이 바뀌면 409로 중단하고 다시 확인한다. 실제 운영 자료를 이관하는 검증은 하지 않는다.

이관 시 해당 프로젝트의 원래 소유자와 새 소유자의 ProjectMember 행만 제거하여 이전 소유자의 접근 잔존과 새 소유자 중복을 막는다. 다른 팀원과 의견 작성자·보고서 버전·개설 승인 정보는 보존한다. DB 트랜잭션으로 소유권과 멘토를 함께 변경하며 경합 실패 시 부분 변경이 없어야 한다.

## 검증.

관리자 인가, 대상 유효성, 멘토 교체·없음·동일 배정, 교차 프로그램, 원래 멘티의 다른 프로젝트 보존, 멤버 정리 범위, 워크시트/보고서/의견/승인 보존, 동시 이관·배정 변경·삭제의 충돌을 확인한다. 운영과 분리된 localhost DB에서 신설 API를 실행한다. UI는 실제 컴포넌트를 브라우저로 선택·확인·완료까지 검증한다. npm run lint, npm run test, npm run test:integration, npx tsc --noEmit, npm run build를 주 작업자가 직접 실행한다.
