# report.pdf 우선 결과보고서 적용 계획과 입력 공백 검토.

## 1. 이번 검토의 범위.

- 기준 원본은 `E:/Dropbox/codetest2/public/asset/report.pdf`다. 가로 5면에 세로 10쪽을 모아 놓은 문서로, 전체 페이지를 이미지로 확인했다.
- 이번 작업은 적용 계획과 적용 전 샘플 작성이다. 앱 소스, DB, 저장된 보고서, 운영 배포는 변경하지 않았다.
- 입력 공백은 현재 코드의 개요 입력 화면·API·데이터 형식과 보고서 생성기를 기준으로 판단했다. 특정 프로젝트의 실제 입력 완료 여부를 조회한 결과는 아니다.
- 샘플은 `E:/Dropbox/codetest2/output/pdf/report-template-preview.pdf`다. 13쪽이며 예시 문구·예시 자료를 사용한다. WS-4·7·9 그림은 기존 앱을 테스트 자료로 렌더링한 화면이다. 다른 그림은 배치 검토용 표 이미지다. 실제 기업의 결과나 저장된 멘토 의견으로 오인하지 않도록 표시했다.

## 2. 적용 원칙.

1. 표지 제목, 장 제목, 절 순서, 회색 제목 띠, 워크시트 그림 자리와 쪽 번호를 원본에 최대한 맞춘다.
2. 원본이 두 쪽 모아찍기 형식이므로 샘플은 읽기 편한 A4 세로 개별 쪽으로 풀었다. 실제 데이터 길이에 따라 페이지를 늘리며, 원본 10쪽을 맞추려고 내용을 삭제하거나 축소하지 않는다.
3. WS-1 앞의 제품 정의는 프로젝트 개요에서 불러온다. 기업명·작성일·코치명은 현재 개요에 없으므로 출처를 확정한 뒤 연결한다.
4. WS-1은 원본의 현재 매출표와 향후 1년 목표매출표를 구분해 유지한다.
5. WS-2 이후의 각 절은 `절 제목 → 해당 워크시트의 저장된 멘토 분석(보고) → 실제 워크시트 결과 그림` 순서로 통일한다.
6. 분석문을 임의로 작성하거나 요약하지 않는다. 저장된 원문을 사용하고, 입력되지 않은 경우에는 누락 상태를 구별한다.
7. WS-12는 저장된 항목별 설명을 그림 앞에, WS-13은 저장된 개선 제품명·설명을 그림 앞에 둔다. WS-15는 핵심자산·보완자산 분석을 그림 앞에 둔다.
8. 이전 요청에 따라 WS-15·16·17을 마지막 `Ⅴ. 자산 및 자금계획`으로 포함한다.
9. 원본에 없는 WS-6 질문지와 WS-14 개발계획서는 현재 샘플 본문에서 제외했다. 이번 요청이 이 두 워크시트의 추가까지 포함하는지는 구현 전에 확정할 사항이다. WS-8은 현재 앱의 독립 워크시트가 아니다.

## 3. 개요 입력과 보고서 앞부분의 대응.

| 보고서 항목 | 현재 개요 상태 | 현재 보고서의 동작 | 판단과 개선 검토안 |
|---|---|---|---|
| 기업명 | 기업명 전용 항목 없음. 프로젝트명만 있음. | 프로젝트명을 기업명으로 출력함. | 보완 필요. 회원정보 `MemberProfile.companyName`은 있으므로 이를 개요로 불러올지, 프로젝트별 기업명으로 별도 저장할지 결정한다. 프로젝트명을 기업명으로 임의 대체하지 않는다. |
| 작성일 | 보고서 작성일 항목 없음. | 미리보기 생성 시 현재 날짜를 사용함. | 보완 필요. 개요에서 작성일을 확인·저장하도록 할지, 생성일 자동 사용을 예외로 허용할지 결정한다. 프로젝트 생성일과는 다르다. |
| 코치명 | 개요의 코치명 항목 없음. | 보고서 API의 배정 멘토명을 사용함. | 개요 출처 연결 보완 필요. 배정 멘토명을 개요에 자동 표시하는 방안을 검토한다. 서명 표시명과 편집 권한은 별개로 유지한다. |
| 제품(서비스)명 | `productName` 입력 가능. | 보고서에 연결됨. | 기존 값을 사용한다. 실제 미입력 여부는 대상 프로젝트별 확인이 필요하다. |
| 제품설명 | 간단 설명 `description`, 상세 제품개요 `detailedDescription` 입력 가능. | 간단 설명만 출력함. | 입력란 신설보다 연결 보완이 필요하다. 상세 제품개요를 제품설명에 이어 붙이고 긴 내용은 다음 페이지로 이어지게 한다. |
| 시장정의 | `marketDefinition` 입력 가능. | 보고서에 연결됨. | 개요 저장값을 사용한다. |
| 목표고객 | `targetCustomer` 입력 가능. | 보고서에 연결됨. | 개요 저장값을 사용한다. |
| 제품 이미지 | 등록 가능. | 보고서에 연결됨. | 원본의 필수 항목은 아니다. 등록된 경우 제품설명에 보조 자료로 배치하는 방안을 유지한다. |
| 사업계획 파일 | 첨부 가능. | 파일 본문을 자동으로 보고서에 넣지는 않음. | 첨부 내용을 임의 추론하지 않는다. 필요한 설명은 개요의 저장 필드로 확정한다. |

기업명·작성일·코치명의 출처가 가장 먼저 결정되어야 한다. 제품명·시장정의·목표고객은 입력 기능이 없는 문제가 아니라, 대상 프로젝트에 실제 값이 있는지 별도 확인해야 하는 항목이다.

### 원본 진단표의 별도 공백.

- 예·아니요로 답하는 4개 진단 문항이 필요하다. 미응답을 ‘아니요’로 취급해서는 안 된다.
- 경쟁자 이름과 전년도 매출액, 경쟁자의 주요 고객 5개, 경쟁우위 확보를 위한 제품개선항목 입력이 필요하다.
- 개선항목 도출과정에 대한 의견이 필요하다.
- 현재 WS-4의 자유 분석문 하나로 위 값을 자동 확정할 수 없다. WS-4 멘토 분석 영역에 구조화된 진단 항목을 둘지, 보고서의 별도 입력으로 둘지 결정해야 한다.

### WS-3 AI 멘토링과 보고서 분석의 구분.

- 이번에 추가한 가치사슬·가치시스템 AI 분석은 멘토링 창의 임시 결과다. 현재 창을 닫으면 초기화되고 `멘토 분석(보고)`에 자동 저장되지 않는다.
- 따라서 보고서에는 현재 저장된 `멘토 분석(보고)`만 사용한다. AI 분석을 보고서에 넣으려면 멘토가 확인한 뒤 보고용 분석에 반영·저장하는 흐름이 별도로 필요하다.

| 단계 | 구현할 내용 | 완료 확인 방법 |

| 5. 문서 검수 | 미리보기와 Word 출력에 같은 데이터·분석·그림을 적용한다. | 대표 프로젝트로 전체 문서를 렌더링하고 한글·표·페이지 넘김·해상도를 시각 확인한다. |
| 6. 호환성 확인 | 기존 초안·완료본을 그대로 읽고 사용자가 재생성할 때만 새 양식을 적용한다. | 기존 보고서·분석 보존, 그림만 갱신 시 교정 문구 유지, 저장·완료·재조회 테스트 및 lint·test·build. |

### 구현 시 확인할 제약.

- 현재 캡처 데이터 형식과 화면은 WS-4·7·9 세 종류에 한정되어 있다. 각 워크시트에서 PNG를 내려받는 기능과 보고서 전체에 자동 첨부하는 기능은 범위가 다르다.
- 보고서 저장 요청은 3,500,000바이트 제한이 있다. 여러 그림을 추가할 때 글자가 읽힐 정도의 해상도를 유지하면서 이 한도에 들어가는지 측정해야 한다. 부족하면 이미지 저장 방식을 따로 설계해야 한다.
- 넓은 QFD와 행이 많은 표는 A4 세로 한 쪽에 억지로 축소하지 않는다. 가로 페이지 또는 연속 페이지 분할로 해결하는 안을 검토한다.
- 원본의 표 모양과 현재 워크시트의 열이 다를 경우, 장·절 구성은 원본을 따르고 그림은 현재 워크시트의 실제 내용을 보존한다. 새로운 빈 양식으로 실제 결과를 바꾸지 않는다.
- 출력문에 입력 출처·보완 필요 안내를 어느 수준까지 남길지는 샘플 검토 후 확정한다. 현재 PDF의 파란 설명과 갈색 보완 표시는 검토용이다.

## 7. 샘플 검증.

- 원본 5면 전체를 이미지로 확인했다.
- 샘플 PDF는 A4 세로 13쪽이다. WS-1과 이후 13개 워크시트를 포함하며 WS-9·11은 원본 순서에 따라 두 절에서 사용한다.
- 15개 분석·그림 배치를 기록하고 각 분석이 그림보다 앞에 생성되는 것을 확인했다.
- 모든 쪽에 적용 전 샘플 표시가 있고, 실제 멘토 분석이 아닌 문구에는 배치 예시를 표시했다.
- 앱 기능은 수정하지 않았으므로 앱 테스트를 다시 실행하지 않았다. 샘플의 페이지·글꼴·텍스트·이미지와 렌더링을 검증했다.

## 8. 실제 프로젝트 샘플의 표지 규칙 확정.

- 후속 사용자 지시에 따라 `AI PLC 관리 장비` 프로젝트의 실제 저장 자료로 검토용 샘플을 작성했다.
- 기업명은 프로젝트 소유자의 회원정보 회사명인 `KNF`를 사용했다.
- 작성일은 샘플 생성 시점의 한국 날짜를 자동 산출한다. 이번 출력일은 `2026.09.28`이다. 별도 개요 입력은 필요하지 않다.
- 코치명은 프로젝트 소유자에게 배정된 담당 멘토 이름을 자동 조회한다. 이번 프로젝트는 `서진원`이다. 별도 개요 입력은 필요하지 않다.
- 기업명·작성일·코치명·케이랩스·KS-QFD를 표지의 가로 중심에 맞췄다.
- 실제 자료 샘플은 `output/pdf/report-ai-plc-preview.pdf`이며 A4 세로 20쪽이다. 긴 워크시트는 행을 생략하지 않고 연속 페이지에 배치했다.
- 표는 저장 자료를 인쇄용 그림으로 구성했다. Kano 그래프는 저장 응답을 로컬 앱의 기존 계산식과 화면에 연결하여 캡처했다. 운영 DB는 읽기 전용 트랜잭션으로 조회했다.
- 이 프로젝트에는 개요 전용 제품명·상세설명·시장정의·목표고객·제품 이미지, 멘토 분석(보고), WS-4 적합도, WS-12 최종 스펙, WS-15 자산이 저장되어 있지 않았다. WS-13은 저장된 1개 행만 반영했다.
