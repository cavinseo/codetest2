# Kano 분석 워크시트 멘토 열람 권한.

## 요구사항과 확정 기준.

- Kano 분석 집계표와 TIMKO/만족계수 그래프에 기존 멘토 분석(보고) 권한을 적용한다.
- 사용자 확인에 따라 현재 배정 MENTOR와 멘토로 배정된 PROGRAM_MANAGER는 열람·편집하며 ADMIN은 읽기만 한다. 멘티 및 미배정 매니저는 열람·편집하지 못한다.
- 권한은 인증된 프로젝트 접근 결과로 판단한다. 응답 데이터와 배정은 수정하지 않는다.
- WS-6 설문 작성·수집과 응답 수 요약, 후속 워크시트의 기존 계산 및 멘토가 공개한 결과보고서는 기존 계약을 유지한다.

## 구현 및 검증.

- [x] Task A. 공통 Kano 분석 권한 함수 및 분석 GET/PATCH 권한 검사를 추가한다. 허용된 프로젝트 사용자는 `view=summary`로 응답 수와 열람 가능 여부만 조회한다. 역할별 API mock 테스트로 조회·수정·비로그인 차단 및 요약에 분석 내용이 없는 것을 확인한다.
- [x] Task B. 프로젝트 탭, 독립 페이지 메뉴, WS-6 분석 탭과 직접 접근 화면에 권한을 적용한다. 멘티 설문관리 유지, 분석 메뉴 숨김, 관리자 읽기 전용, 배정 멘토 편집을 컴포넌트 테스트로 확인한다.
- [x] Task C. 개별 분석 엑셀은 비허용 사용자에게 403으로 응답하고 전체 엑셀에서 두 분석 시트만 제외한다. 나머지 워크시트 및 JSON 백업의 원자료 계약은 유지한다. Excel 실제 워크북 검사로 검증한다.
- [x] Task D. 기존 작업폴더에 이번 변경만 통합하고 관련/전체 테스트, 타입 검사, lint, production 빌드를 더미 DB 환경에서 실행한다. 실DB·개발서버를 실행하지 않는다. 결과보고서 및 격리 커밋을 남긴다.

## 검토 위험.

- 화면만 숨기면 분석 API와 전체 엑셀에서 우회할 수 있어 서버 권한도 함께 적용한다.
- WS-6 응답 수 표시는 분석 상세 API를 사용하므로 공개 가능한 수집 요약과 멘토 전용 분석 상세를 구분한다.
- 기존 회귀 테스트에서 OWNER/VIEWER에게 분석을 허용한 전제는 새 권한 계약에 맞춰 변경하며 데이터 처리 단언은 유지한다.
- clean release와 기존 작업폴더에 다른 미완료 변경이 있으므로 전체 파일 덮어쓰기 대신 변경분을 통합한다.

## 구현 중 추가 확인.

- 코드 검토에서 WS-5 요구사항 저장이 `kanoWeight`를 수정할 수 있는 우회를 확인했다. 일반 요구사항 편집은 유지하고 분석 편집 권한이 없으면 가중치를 제출 데이터에서 제외하여 기존 값 및 0을 보존한다. 신규 행은 DB 기본값 null을 사용한다.
- JSON 백업 복원은 기존 전체 데이터 복원 기능으로 유지하며 분석 워크시트의 편집 UI/API와 구분한다.
- 테스트 작성 중 전체 검사가 새 테스트 파일의 중간 저장본을 읽어 일시적인 구문 오류가 발생했다. 작성 완료 후 전체 검사를 다시 실행하여 release 3,250개, 기존 작업폴더 3,337개가 모두 통과했다.
- 두 작업폴더의 lint 및 production 빌드, 타입 검사를 통과했다. 원격 DB 연결 및 개발 서버 실행 없이 더미 환경과 mock으로 검증했다.
