# 고객요구사항 순서 연동 계획.

## 계약과 성공 기준.

- WS-5의 2차 그룹 → 1차 그룹 → 요구사항 순서를 모든 요구사항 기반 출력의 기준으로 사용한다.
- 기존 Kano 교정 질문·가중치·응답과 QFD 연결은 동일 ID에 남는다. 순서 변경으로 삭제하거나 다시 생성하지 않는다.
- WS-10·11·13은 텍스트 연결을 사용하므로 유일하게 식별되는 문구만 연결한다. 불명확한 기존 작성 행은 상대 순서와 내용을 보존한다.
- QFD 점수와 TOP5 선정 집합은 유지하고 선정 이후 표시 순서만 WS-5를 따른다. WS-12는 연결된 WS-10 스펙 묶음 단위로 이동한다.
- 새 설문 응답 파일에는 항목 식별자를 보관한다. 이전 파일도 문구로 식별할 수 있으면 원래 항목에 연결하고 식별할 수 없으면 저장 전 오류를 반환한다.
- 보고서 재생성·표 갱신 시 순서를 적용한다. 기존 완료본은 저장 스냅샷 계약을 유지한다.
- 실DB 쓰기·마이그레이션·개발 서버 실행 없이 Prisma mock과 기존 테스트로 검증한다.

## 검토 결과.

- WS-5 화면만 그룹 정렬하고 Kano와 QFD 조회·출력은 DB의 원래 order를 따른다.
- 요구사항 POST는 생략된 Kano 필드를 null로 덮어써 기존 질문·가중치를 지울 수 있다.
- 오프라인·엑셀 응답의 문항 index를 현재 요구사항 배열에 대입하면 재정렬 전 응답이 다른 항목에 붙을 수 있다.
- QFD 화면·보고서의 셀 병합은 아직 1차 그룹이 상위인 규칙을 사용한다.
