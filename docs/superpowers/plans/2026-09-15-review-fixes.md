# 전체 코드 검토 후 결함 수정과 운영 반영.

기준 커밋 a761152. 사용자가 전체 리뷰의 미완료 항목을 마친 뒤 푸시·공개하도록 요청했다. 검토 보고서의 F01~F11을 수정하고 전체 검사·운영 확인을 수행한다. 운영 DB .env는 읽거나 사용하지 않는다. Prisma 스키마 변경 없이 구현하며 로컬 DB로 자료 보존을 검증한다.

## 확정 계약.

- F01. admin 코드 표시와 멘티 반복 코드 로그인 유지. PM에게는 목록·발급 응답에서 원문 코드를 노출하지 않고 발송 결과만 제공한다.
- F02. 멘티 프로그램 재배정은 User.programId와 사용 중 초대의 programId를 같은 트랜잭션에서 변경한다. 기존 계정 기한은 유지하고 새 프로그램 종료 제한은 기존 인증 정책으로 적용한다. 과거 프로젝트의 프로그램은 임의 변경하지 않는다.
- F03. 삭제 대상이 발급한 코드는 실행 관리자에게 발급 관리 책임을 이전하여 코드와 사용자를 보존한다. 삭제 확인 화면·응답에서 건수를 안내한다. 스키마는 유지한다.
- F04. 공백 세부기능이 분석·순위에 포함되지 않게 하고 신규/복원 입력의 공백을 막는다. 기존 관계 데이터는 조회만으로 삭제하지 않는다.
- F05. 내 소속은 현재 MentorAssignment를 기준으로 조회한다. 과거 COACH를 현재 배정으로 취급하지 않는다.
- F06. 손대지 않은 기존 제품 개요 null을 보존하여 보고서 자유입력이 유지되게 한다. 사용자의 명시적 빈 문자열 삭제는 유지한다.
- F07. 원격 MCP의 공인 HTTPS 조건을 실제 요청에도 적용한다. 리디렉트와 사설 DNS 주소 우회 차단, 로컬 모드의 명시적 localhost 동작은 유지한다.
- F08. 로그아웃은 현재 sessionVersion과 일치하는 쿠키만 서버 세션을 무효화한다. 브라우저 쿠키 삭제는 항상 한다.
- F09. 마지막 관리자 삭제는 공통 잠금과 트랜잭션 안 재확인으로 동시 삭제를 막는다.
- F10. 보고서의 미저장 교정은 브라우저 뒤로가기에도 저장/나가기 확인을 제공한다.
- F11. 최신 이력 100건 제한 때문에 미결 신청이 숨지 않게 한다.
- 품질. 기존 CI 기준을 낮추지 않고 project-creation-approval의 검증 공백을 채워 CRAP 검사 실패를 해결한다.

## 검증 환경.

수정 작업 폴더는 review-fixes이며 node_modules만 기존 설치와 연결한다. 로컬 PostgreSQL 127.0.0.1:55439의 program_restore_qa를 사용한다. 모든 fixture는 고유 ID로 생성·정리하고 원격 DB 또는 실회원으로 쓰기 검증하지 않는다. 브라우저 검증과 통합 테스트 실행은 주 작업자가 수행한다. 검토 담당은 읽기만 하고, 구현 담당은 지정 파일만 수정한다. 이 계획의 완료 체크는 실제 검증 뒤 갱신한다.
