# WS-2 기능분석 프롬프트 작성 도우미.

## 확정 계약.

- 사용자 정정에 따라 도우미를 ‘질문 답변으로 Claude·OpenAI에 붙여 넣을 기능분석 프롬프트를 작성하는 기능’으로 정의한다. 표 자동 작성·반영 계획은 대체한다. WS-2 제목 영역의 ‘기능분석 작성 도우미’ 버튼으로 팝업을 연다.
- 제품·사용자, 고객의 현행 대안·지불 이유, 현재 기능·보유기술·제약·시험/상용 범위를 단계별로 묻는다. 프로젝트명·설명은 현재 화면 자료에서 미리 채우고 수정 가능하다. 필수값은 제품명·제품설명·사용자·현행 대안·고객이 원하는 결과이며, 나머지는 ‘미제공·확인 필요’로 처리할 수 있다.
- 마지막 화면에서 생성 프롬프트 전체를 열람·복사한다. 클립보드 접근 실패 시 전체 선택 후 수동 복사하는 방법을 제공한다. 단계 이동·팝업 닫기/다시 열기에서 입력을 유지한다. 현재 페이지를 벗어나기 전까지만 보관한다.
- 기존 WS-2 내용은 사용자가 포함 여부를 선택하며 복사 전 확인할 수 있다. 기존 자료는 참고 데이터이고, 새로운 기능을 현재 구현 사실로 취급하지 않도록 프롬프트에서 구분한다.
- 동일 입력은 동일 프롬프트를 만든다. 공급자 공통 역할·분석 순서·기능 ID·고정 표 머리글·확인 기준을 명시하여 출력 구조를 맞춘다. 공급자 간 분석 내용 자체가 같다고 보장하지 않는다.
- 외부 AI 호출·자동 전송·스펙표 반영·DB 저장을 추가하지 않는다. 현재 AI 에이전트와 권한·저장 API는 변경하지 않는다. 새 도우미는 기존 작성 권한의 UI 범위 안에서 제공한다.

## 사용하는 스킬.

- 사용자 지정 원본은 https://github.com/cavinseo/skills/tree/main/fast-functional-analysis-repo 이다.
- `SKILL.md`(blob `796193adb343070dad81bf7f189bcfdbb99a06cc`)와 `references/method.md`, `quantification.md`, `kano-qfd.md`를 읽었다. README에서 MIT 사용·수정·배포 안내를 확인했다.
- 고객 과업→기본기능→핵심→세부→세세부 계층, 동사형 기능 문장, 기본기능의 경쟁자·수단·그래서 테스트, How–Why 검증, 시나리오 분기·복귀점, 정량값의 가설 표시, Kano 사용자 계층 분리 및 잔여 리스크를 프롬프트 본문에 내장한다.
- 스킬 링크를 읽지 못하는 외부 AI도 사용할 수 있도록 핵심 절차와 출력 형식을 프롬프트 안에 포함한다. 후속 요청에 따라 프롬프트 버전 FAST-WS2-1.2는 분석 결과를 8개 절과 WS-2 4열 표를 갖춘 단일 HTML 보고서로 요구한다. 맨 마지막에는 현행 기능을 핵심기술·세부기술·세세부기술·적용기술 순서의 엑셀 붙여넣기용 표로 작성하도록 지시한다. 셀 병합·추가 열 없이 상위 이름을 매 행 반복하고, 붙여넣기 안내는 표 앞에 둔다. 내장 CSS·인쇄 형식·HTML 텍스트 이스케이프를 지정하고, 팝업에서 HTML 저장 방법을 안내한다. 도우미에서 외부 AI 분석이나 생성된 HTML 실행을 수행하지 않는다.
- 고정 출력은 분석 전제, 과업·기본기능, 기능 계층표, WS-2 현행 기능 4열 표, How–Why, 시나리오, 정량·Kano/QFD 가설, 리스크·다음 확인사항 순서로 구성한다. 확인된 현재 기능과 제안·가설은 구분하고 확인되지 않은 숫자·VOC를 사실로 만들지 않는다.

## 구현 범위.

- `lib/function-analysis-prompt.ts`에 질문 정의·입력 검증과 결정적인 프롬프트 생성 함수를 추가한다. 사용자 답변·현재 표는 JSON 데이터 구역으로 구분하고 본문 규칙과 섞이지 않게 이스케이프한다.
- `components/project/FunctionAnalysisAssistant.tsx`에 단계별 질문·이전/다음·검토·복사 팝업을 추가한다. 입력은 부모 페이지 생명주기 동안 유지하고 접근 가능한 dialog와 명시적 레이블을 쓴다.
- `components/project/SpecTable.tsx`에는 제목 영역 버튼과 도우미 상태/연결만 추가한다. 기존 rows를 변경하는 콜백을 넘기지 않는다.
- 단위 테스트는 모든 답변 반영, 선택적 기존 스펙 포함, 출력 순서·표 머리글·ID 규칙, 스킬 핵심 계약, 미제공 처리·필수 검증·원본 불변성·결정성을 검증한다.

## 단계별 검수.

- [x] 검토. 기존 흐름과 사용자 정정, 지정 스킬의 질문·분석·검증 계약을 확인했다.
- [x] 구현. 프롬프트 생성 모듈, 질문 팝업, WS-2 진입점을 구현했다.
- [x] 자동 검수. 관련 테스트 28개·전체 테스트 1,756개, 타입·lint·빌드를 통과했다. 고정 출력 제목을 변경했을 때 회귀 테스트 실패를 확인하고 원복했다.
- [x] 실제 화면 검수. 격리 환경에서 필수 답변, 이전/다음, 닫기/재열기, 기존 표 포함/제외, 프롬프트 생성·복사·전체 선택과 다크/라이트 표시를 검증했다. 복사 거부·API 미제공 안내는 실제 컴포넌트 핸들러를 대역 환경에서 실행해 별도 검증했다. 스펙표와 DB가 바뀌지 않고 도우미 사용 중 서버 요청이 발생하지 않음을 확인했다.
- [x] 결과 기록. 검수 결과를 보고서로 정리했으며 구현과 결과 보고서를 별도로 커밋한다.

운영 DB 변경·푸시·배포는 이번 구현 범위에 포함하지 않는다.

## 향후 정식 버전 전환.

당분간 현재 프롬프트 제공 방식을 유지한다. 향후 기존 AI 에이전트를 도우미의 API 실행으로 대체하고, 멘티 계정 전체 누적 5회 제한을 적용한다. 현재는 실행 기능·횟수 제한을 활성화하지 않으며, 재사용 경계와 사용량·동시 요청·HTML 검증·기존 경로 교체 기준은 [API 전환 설계](2026-09-11-function-analysis-api-transition.md)에 기록한다. 실패 차감 등 미확정 정책은 전환 전에 결정한다.
