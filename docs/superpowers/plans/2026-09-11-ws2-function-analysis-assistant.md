# WS-2 기능분석 작성 도우미.

## 확정 계약.

- 사용자가 선택한 ‘질문에 단계별로 답하면 기능분석표를 완성’ 방식을 구현한다. WS-2 제목 영역에 ‘기능분석 작성 도우미’ 버튼을 추가한다.
- 질문은 제품이 고객에게 제공하는 핵심기능, 해당 핵심기능의 하위 동작, 세부기능을 수행하는 구체적 동작, 각 동작에 적용하는 기술 순서이다. WS-2의 기존 핵심기술·세부기술·세세부기술·적용기술 열로 답변을 직접 정리한다. 외부 AI가 답변을 임의로 만들어 채우지 않는다.
- 기존 핵심기술과 선택한 핵심기술의 하위 세부기술을 선택할 수 있고 새 항목도 직접 입력한다. 작성 예시와 앞 단계 답변을 보여준다. 핵심·세부·구체 동작은 필수, 기술은 모르면 비워둘 수 있다.
- 마지막에 표로 검토·교정하고 추가할 행을 선택한다. 추가만 수행하며 기존 표·기술값을 덮어쓰지 않는다. 같은 핵심·세부·세세부 경로는 중복 추가하지 않고 기존 표에서 수정하도록 안내한다.
- 취소 전 변경은 도우미 안에만 있다. 미반영 답변이 있을 때 닫기 전에 확인한다. 반영은 WS-2의 편집 상태에 추가하고 사용자가 기존 저장 버튼으로 저장한다. 이전 단계 이동에서는 답변을 유지한다.
- 서버 프로젝트 목록의 기존 역할 OWNER·EDITOR·ADMIN일 때만 새 작성 버튼을 제공한다. 멘토·조회자는 새 도우미로 수정할 수 없다. 저장 API의 기존 쓰기 권한을 유지한다.
- 기존 AI 에이전트와 생성 엔진, DB 스키마, 보고서 기능은 수정하지 않는다. 기존 AI 에이전트의 전체 교체·refine 제한은 사전 검토에서 발견한 별도 이슈로 기록한다.

## 구현 범위.

- `lib/function-analysis-assistant.ts`에 답변의 표 변환, 기존 계층 선택지, 선택 결과의 안전한 추가 함수를 둔다. 기존 표의 생략된 상위 이름은 선택지·중복 판정에서만 해석하고 원본 행을 보존한다.
- `components/project/FunctionAnalysisAssistant.tsx`에 접근 가능한 단계별 모달을 추가한다. 복수 구체 동작은 한 줄에 하나씩 받아 적용기술을 각각 작성하고 결과를 교정·선택한다.
- `components/project/SpecTable.tsx`에는 버튼·프로젝트 역할·도우미 열기와 추가 연결만 변경한다. 기능분석 도우미 결과는 기존 rows에 추가한다.
- 단위 테스트는 답변 정리, 계층 선택지 범위, 생략 계층 해석, 기존 값 보존, 중복·공백·선택 적용을 검증한다.

- [ ] 구현. 순수 변환·추가 함수, 단계별 질문 화면, 두 WS-2 진입점의 버튼을 구현한다.

- [ ] 실제 화면 검수. 격리 로컬 DB에서 필수 답변, 이전·다음, 취소, 기술 공란, 결과 교정·선택, 기존 항목 추가와 저장·새로고침을 확인한다. 멘토 화면에는 새 도우미 버튼이 없는지 확인한다.
