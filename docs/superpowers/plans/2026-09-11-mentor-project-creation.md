# 관리자 활성화 방식의 멘토 프로젝트 생성.

## 요청.

> 멘토가 프로젝트를 만들수 있는 기능을 추가하되 기능을 비활성화가 디폴트로 두고 관리자에 의해서활성화 될 수 있도록 하라.

## 확정 조건.

- 멘토의 신규 프로젝트 생성은 기본 비활성이다.
- 관리자만 생성 기능을 활성화하거나 다시 비활성화할 수 있다.
- 화면 표시뿐 아니라 프로젝트 생성 API에서 현재 권한을 검사해야 한다.
- 기존 멘티의 추가 프로젝트별 승인과 관리자만 프로그램을 개설하는 규칙을 보존한다.

## 사용자 확정 답변.

1. 관리자가 멘토별로 활성화·비활성화한다.
2. 배정받은 멘티 소유 프로젝트를 대신 개설한다.

서버가 배정 멘티의 소속 프로그램과 소유자를 결정한다. 두 번째 이후 프로젝트는 기존 멘티별 개별 승인 규칙을 적용한다. 생성 권한을 비활성화해도 현재 배정된 프로젝트의 열람·편집 권한은 유지한다.

## 단계와 검수 기준.

1. 설정 저장과 관리자 화면을 추가한다. 기존·신규 멘토가 모두 기본 비활성이고 관리자 이외의 설정 변경은 거절되는지 검증한다.
2. 대시보드와 생성 API를 연결한다. 허용 멘토만 생성 가능하고 비활성화 후 이미 열린 화면에서도 서버가 신규 생성을 거절하는지 검증한다.
3. 확정된 소유권·프로그램 범위를 적용한다. 생성한 프로젝트를 적법한 계정이 조회·편집할 수 있고 다른 멘티·프로그램 권한을 획득하지 않는지 검증한다.
4. 관련 API/권한 테스트, 격리 DB 테스트, lint·전체 테스트·빌드와 브라우저의 활성화→생성→비활성화 흐름을 검수한다. 운영 데이터는 시험 자료로 사용하지 않는다.

## 주요 수정 후보.

- `prisma/schema.prisma`, 필요한 마이그레이션.
- `app/api/admin/users/route.ts`, `components/admin/MembersTab.tsx`, `app/admin/page.tsx`.
- `app/api/me/profile/route.ts`, `app/dashboard/page.tsx`, `app/api/projects/route.ts`.
- `lib/member-roles.ts`, 소유권 결정에 따라 `lib/authorization.ts`, `lib/program.ts`, `lib/project-creation-approval.ts`.

## 구현 및 검수 결과.

- User.mentorProjectCreationEnabled를 기본 false로 추가했다. 마이그레이션은 기존 users 데이터에 컬럼만 추가하며 기존 계정·프로젝트를 변경하거나 삭제하지 않는다.
- 관리자 회원 관리에서 멘토별로 설정한다. 프로그램 매니저·멘토·멘티는 설정 API에서 403이며 멘토 외 계정은 설정 대상이 아니다. 역할이 바뀌면 생성 허용을 초기화한다.
- 멘토 대시보드에는 기본 사용중지 버튼을 표시한다. 활성화 후 배정 멘티와 현재 프로그램의 미사용 승인만 선택한다. 프로젝트 소유자·프로그램은 서버에서 멘티 기준으로 결정한다.
- 생성 트랜잭션에서 멘토 계정, 멘티 계정, 배정 행을 잠그고 현재 권한을 다시 검사한다. 추가 프로젝트에는 멘티별 미사용 승인 한 건이 필요하다.
- 비활성화는 신규 개설만 차단한다. 배정 프로젝트의 기존 열람·편집 권한은 유지한다.

## 배포 시 적용 순서.

현재 변경은 로컬 구현이다. 운영 반영 시 Prisma 마이그레이션 20260911114230_mentor_project_creation을 먼저 적용한 뒤 앱을 배포한다. 컬럼 추가 후에도 모든 멘토는 비활성이며 관리자가 회원 관리에서 필요한 멘토만 활성화한다. 이번 작업에서는 푸시·배포를 실행하지 않았다.

최종 소스 기준 npm run build도 통과했다. (2026-09-11.)
