# 운영 실계정 검증 진행 상태.

2026-10-15 사용자가 운영 멘토·멘티 계정으로 워크시트 입력 저장, Kano 응답 선택·전체 삭제와 삭제 전 확인창을 검증하도록 요청했다. 두 역할의 저장·선택 삭제·전체 삭제를 운영에서 확인했다. 최신 결과와 검증 한계는 [최종 운영 검증 기록](task-live-verification.md)에 정리했다. 아래의 초기 준비 기록과 후속 기록은 수행 시점이 다르다.

## 초기 준비 상태.

- 사용 가능한 브라우저는 Codex 인앱 브라우저이다. 기존 공개 설문 탭은 유지했다.
- `https://codetest2-rouge.vercel.app/login`을 새 검증 탭에 열었다.
- 로그인 화면에는 멘토·멘티 역할 선택, ID·비밀번호 입력과 Google 로그인 경로가 있다. 로그인 세션은 아직 확인하지 못했다.
- 사용자에게 해당 화면에서 직접 로그인하고 로그인 역할을 알려 달라고 요청했다. 비밀번호를 채팅에 제공할 필요는 없다.
- 기존 접수 응답이 없는 검증 전용 프로젝트를 지정하거나 새 테스트 프로젝트/응답을 만들어 진행하는 선택을 요청했다. 아직 대상이 정해지지 않았다.
- 실제 운영 저장·업로드·설문 제출·이메일 발송·삭제는 모두 0건이다.

실제 운영 기능 검증은 위 항목을 두 역할 모두에서 관찰해야 완료로 판정한다. 이전 배포의 3,351개 검사와 모의 브라우저 결과를 이 요청의 실계정 검증으로 간주하지 않는다.

## 준비한 보존 원칙.

루트가 직접 브라우저를 조작하며 운영 DB 스크립트나 API 우회 인증을 사용하지 않는다. 검증 데이터는 지정된 테스트 전용 프로젝트에서 새로 만든 요구사항과 응답만 사용한다. 기존 사용자 접수 응답이 들어 있는 프로젝트에서는 전체 삭제를 시험하지 않는다. 전체 초대 리셋과 전체 응답 삭제는 구분한다.

운영에서 다운로드한 전용 업로드 양식을 사용하고 문항 연결 ID를 보존한다. 새 응답을 추가하는 정책을 사용한다. 선택 삭제 후 재수집할 때는 삭제한 응답자만 포함해 중복 응답자의 409 거절을 피한다. 두 역할이 같은 테스트 프로젝트에 접근할 수 있는지 로그인 뒤 확인한다.

표준 확인창은 운영의 `window.confirm` 그대로 시험하며 shim/mock으로 대체하지 않는다. 브라우저 도구가 native 확인창을 처리하지 못하면 사용자 조작과 그 결과를 구분하여 기록한다.

## 다음 진행에 필요한 정보.

초기 멘토 로그인에서는 검증 멘티에게 미배정되어 접근이 차단됐다. 이후 사용자가 배정된 멘토 로그인 경로를 선택했고 검증 프로젝트의 편집자 접근을 확인했다. 이 접근 제한은 해소됐으며 권한을 우회하거나 임의로 배정을 바꾸지 않았다. 마지막 전체 삭제 후 새 서버 조회, 초대 보존·분석 빈 상태 확인까지 끝났다.

## 후속 실제 운영 진행 기록.

위 내용은 로그인 전 준비 상태다. 이후 사용자가 멘토 로그인과 새 테스트 프로젝트/응답 생성을 승인했고, 다음 실제 운영 조작을 수행했다.

- 멘토 대시보드 로그인을 확인했다. 이 계정의 새 프로젝트 생성은 사용중지 상태이므로 권한을 변경하지 않았다.
- 사용자에게 멘티 로그인을 요청한 뒤 실제 멘티 대시보드의 소유 프로젝트 0개와 생성 가능 상태를 확인했다.
- 멘티로 `운영 기능 검증 2026-10-15`, ID `proj_993e1ebea9bc423d`를 생성했다. 설명에 모든 자료가 검증용임을 명시했다. 기존 접수 응답은 0건이었다.
- WS-5에서 신규 입력을 추가 버튼 없이 상단 저장으로 저장했다. 이어 두 행을 편집하면서 다른 행으로 전환한 뒤 편집 중 상단 저장을 수행했다. 운영 requirements 경로를 새로 열어 두 문구가 유지됨을 확인했다. 두 문항 ID는 `req_1791996487903_0d7u`, `req_1791996523701_1l82`다.
- 멘티가 Kano 긍정/부정 질문 1쌍을 저장하고 페이지를 새로고침해 유지됨을 확인했다. 분석 결과 진입점은 표시되지 않았다.
- QFD에서 경쟁사·기술특성을 추가하고 경쟁 값 120과 목표치 150을 Enter로 저장했다. 운영 qfd 경로를 새로 열고 기본으로 접힌 기술특성을 펼친 뒤 측정단위 ms, 경쟁 값 120, 목표치 150을 확인했다. 이 검증은 일반 Enter 저장이며 실제 OS의 한글 조합 상태 재현으로 간주하지 않는다.
- 실제 운영의 응답 양식을 다운로드했다. 스프레드시트 스킬로 문항 ID와 다른 시트 값을 보존하면서 3명 파일을 만들었다. 루트가 ZIP/XML 읽기로 숫자 12개 및 비응답 3개 시트 값을 원본과 별도로 대조했다.
- 추가 정책으로 `qa-a@qa.invalid`, `qa-b@qa.invalid`, `qa-c@qa.invalid`의 응답을 실제 운영에 업로드했다. 3명과 문항 2개별 O/A/M 답변이 표시됐다. 이메일 발송은 하지 않았다.
- 표준 확인창을 여는 자동 클릭은 CDP Input.dispatchMouseEvent timeout을 보고했고 getJsDialog는 undefined였다. 확인 함수 shim을 사용하지 않았다. 사용자에게 표준 창 조작을 요청했다.
- 사용자의 처음 취소 보고 뒤 선택 응답 삭제가 관찰됐다. 사용자가 이후 ‘확인을 눌렀다’고 보고를 정정했으므로 이를 취소 실패나 제품 결함으로 단정하지 않는다. 별도 실제 취소 시험을 다시 진행한다.
- 중단 후 새 운영 탭으로 재조회했을 때 qa-a/qa-b는 삭제되고 qa-c 한 명만 남았다. 초대 3개는 보존됐으며 qa-a/qa-b는 응답 대기, qa-c는 완료 상태다.
- 현재 qa-c 한 명을 선택하고 사용자에게 선택 삭제 확인창에서 취소하도록 요청했다. 이 취소의 사후 관찰은 아직 대기 중이다.

위 기록 이후 qa-c 취소 보고 직후 목록과 선택 보존을 관찰했다. 이어 사용자가 전체 삭제의 확인을 직접 누른 뒤 페이지를 새로고침했으며, 완료 0명·빈 응답 목록·초대 3명 응답 대기를 확인했다. `tmp/live-role-mentee-all-delete-result.json` 및 `output/live-role-mentee-all-delete-2026-10-15.png`가 근거다.

멘토 시험 준비를 위해 같은 검증 파일을 추가 정책으로 다시 업로드했고 새로고침에서 3명 완료를 확인했다. 사용자에게 추가 멘티 취소 시험을 요청했으나 사용자가 생략하도록 지시하여 실행하지 않았다. 앞선 취소 직후 서버 재조회는 미검증으로 남긴다. 네트워크 기록이 없으므로 취소 시 DELETE 0건을 주장하지 않는다.

멘티의 WS-5, Kano 질문, QFD 일반 입력 저장과 선택·전체 삭제는 관찰했다. 모든 워크시트나 실제 OS 한글 IME 조합 입력까지 검증했다고 확대하지 않는다. 제품 소스와 설정을 수정하거나 재배포하지 않았다.

멘토 로그인 뒤 검증 프로젝트의 실제 접근 차단을 확인한 화면은 `output/live-role-mentor-access-blocked-2026-10-15.png`이다. 대시보드의 기존 사용자 프로젝트는 수정하지 않았다.

## 배정된 멘토의 후속 검증.

사용자가 배정된 멘토 계정으로 로그인하는 경로를 선택했다. 이후 실제 대시보드에서 같은 검증 프로젝트의 링크와 ‘편집자’ 표시를 확인했고 Kano 페이지에서 분석 결과 진입과 멘토 의견 입력도 확인했다.

- WS-5 두 행을 ‘멘토 편집 중 저장 검증 1’, ‘멘토 행 전환 저장 검증 2’로 수정했다. 첫 행 편집 중 두 번째 행으로 이동하고, 두 번째 행 편집을 끝내기 전에 상단 저장을 눌렀다. 새로운 requirements 경로에서 두 값이 유지됐다. 근거는 `tmp/live-role-mentor-input-result.json`과 `output/live-role-mentor-input-2026-10-15.png`이다.
- WS-5 수정 이후 기존 사용자 지정 Kano 질문이 보존된 것을 관찰했다. 첫 질문의 긍정·부정 문구를 ‘멘토 저장 검증 긍정 질문 1’, ‘멘토 저장 검증 부정 질문 1’로 바꾸고 상단 저장했다. 새로고침에서 값 유지와 분석 진입점을 확인했다. 근거는 `tmp/live-role-mentor-kano-question-result.json`이다.
- QFD 경쟁사 값을 130, 목표치를 160으로 바꾸고 각각 Enter로 저장했다. 새로운 qfd 경로에서 접힌 기술특성을 펼쳐 ms·130·160을 확인했다. 근거는 `tmp/live-role-mentor-qfd-result.json`과 `output/live-role-mentor-qfd-2026-10-15.png`이다. 이는 일반 Enter 저장이며 OS 한글 IME 조합 입력 재현이 아니다.

멘토의 독립 응답자 보기에서 선택 0명일 때 선택 삭제가 비활성인 것을 확인했다. qa-a·qa-b를 선택한 뒤 사용자가 직접 표준 확인창에서 취소했다. 직후 두 선택·3행이 유지됐으며 브라우저 새로고침과 응답자 보기 재진입에서도 3행이 유지됐다. 근거는 `tmp/live-role-mentor-cancel-immediate.json`, `tmp/live-role-mentor-cancel-fresh.json`과 같은 이름의 화면 PNG이다.

전체 선택으로 3명 선택이 되고 qa-c만 해제하면 2명 선택으로 바뀌는 것을 확인했다. 이어 사용자가 선택 삭제의 확인을 직접 눌렀다. 새로고침에서 완료 1명·응답률 33%·초대 3명 보존을 확인했고, 응답자 보기에는 qa-c의 두 문항만 남았다. 분석 내부 응답자 보기에서도 같은 삭제 도구가 보였고 집계는 총 응답 2개·응답자 1명·분석 항목 2개였다. 근거는 `tmp/live-role-mentor-selection-result.json`, `tmp/live-role-mentor-selected-delete-result.json`, `output/live-role-mentor-selected-delete-2026-10-15.png`이다.
