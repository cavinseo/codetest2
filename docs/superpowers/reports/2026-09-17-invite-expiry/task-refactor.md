# 초대 기한 기능 리팩토링

## 검토와 성공 기준

사용자는 직전 초대 기한 수정의 기능을 유지하면서 긴 함수 분리, 명확한 이름, 중복 통합과 미사용 코드 제거, 실행 검증 및 배포를 요청했다. 대상은 초대 발급·연장 API와 날짜 편집 화면이다.

- API 입력·응답, 오류 문구·상태 코드, 관리자·매니저 권한을 유지한다.
- 날짜 검증 순서, 프로그램 종료 시각 제한과 기존 멘티 기한 보존을 유지한다.
- 이메일 잠금 → 초대 행 잠금 → 재조회 → 회원 조건부 갱신 → 초대 저장 순서와 단일 트랜잭션을 유지한다.
- 화면의 날짜 클릭·저장·취소, 오류 표시, 작업 중 중복 요청 방지와 계정 연결 후 상태 갱신을 유지한다.
- 변경 전 관련 7개 파일의 225개 테스트를 기준으로 삼고, 테스트를 변경하지 않은 상태로 다시 실행한다.

## 변경 내용

- `lib/invite-management.ts`에 발급·연장 처리를 모으고, 계정 조회와 조건부 기한 갱신을 역할별 함수로 분리했다. API 함수는 인증·입력·응답·메일 처리에 집중한다.
- 발급·연장에 중복된 날짜 검증과 종료 시각 제한, 이메일 잠금, 유효 초대 조회를 공통 함수로 통합했다.
- `user`, `existing`, `linkExisting`을 역할이 드러나는 `mentee`, `existingAccount`, `shouldLinkExistingMentee` 등으로 바꿨다.
- 날짜 표시·편집을 `InviteExpiryCell`로 분리하고 기존 날짜 입력 검사를 `getInviteExpiryInputError`로 공유한다.
- 화면의 `busy`, `mounted`, `loadRequest`, `load`를 `operationInFlight`, `isMounted`, `latestLoadRequestId`, `loadInvitesAndPrograms`로 명확히 했다. 네 작업의 종료 처리는 `finishOperation`으로 합쳤다.
- 화면에서 읽지 않는 타입 항목 두 개와 분리 후 불필요한 import·파생 변수를 제거했다. 삭제할 주석 처리된 실행 코드는 없었고, 동시 처리·권한에 관한 설명은 보존했다.
- POST는 94줄에서 62줄, PATCH는 88줄에서 19줄이 됐다. 스키마와 운영 데이터 변경은 없다.

## 실행 검증

- 변경 전후 관련 225개 테스트가 모두 통과했다. 테스트 파일은 수정하지 않았다.
- 전체 168개 파일의 2,420개 테스트, 린트, TypeScript 검사, 변경 줄 공백 검사를 통과했다.
- 실제 PATCH와 로그인 핸들러를 연결한 회귀 테스트에서 기존 멘티의 기한 저장·반복 로그인·만료 거절을 확인했다.
- React DOM 테스트로 발급 날짜 필수 입력, 날짜 편집·저장·취소, 오류와 중복 요청 방지, 계정 연결 후 사용 상태 표시를 확인했다.
- 운영 빌드도 통과했다.
