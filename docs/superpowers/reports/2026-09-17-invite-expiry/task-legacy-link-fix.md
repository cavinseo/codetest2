# 기존 멘티의 초대 기한 변경 오류 수정

## 원인과 재현

- 운영 화면에서 대기 초대의 날짜를 저장하면 `이미 가입된 이메일입니다.`라는 409 응답이 발생했다.
- 운영 DB를 읽기 전용으로 확인한 결과, 해당 이메일에는 같은 프로그램의 승인된 일반 멘티가 있었고 다른 초대 연결은 없었다. 초대의 `usedAt`과 `usedById`, 회원의 이용 기한은 null이었다.
- 미사용 초대에 대한 기존 회원 중복 검사가 정상적인 기존 멘티의 기한 변경도 차단했다. 단순히 검사를 제거하면 초대 코드 로그인은 여전히 실패하므로, 관리자가 날짜를 저장할 때 회원 연결과 이용 기한을 함께 저장해야 한다.
- API와 화면 회귀 테스트를 먼저 추가하여 기존 구현에서 5개 실패를 확인했다.

## 수정 범위

- 관리자 또는 담당 매니저가 날짜를 연장할 때, 이메일·프로그램이 일치하고 승인된 비관리자 멘티이며 다른 초대 연결이 없는 경우 기존 회원에 연결한다.
- 초대 코드와 회원 이용 기한, 연결 시각·회원 ID를 같은 트랜잭션에서 저장한다. 코드나 계정을 새로 만들지 않는다.
- 다른 유효 초대, 다른 프로그램·역할, 미승인 회원, 기존 연결은 거절한다. 회원에게 이미 저장된 더 긴 이용 기한은 줄이지 않는다.
- 회원 정보와 기한, 연결 없음 조건을 다시 확인하는 조건부 갱신으로 동시 변경을 보호한다.
- 저장 응답에 사용 시각을 포함하여 화면 상태와 회수 버튼도 즉시 갱신한다. 일반 로그인 API의 기존 계정 연결 거절 정책은 유지한다.
- 운영 데이터 일괄 수정이나 추가 DB 마이그레이션은 필요하지 않다. 사용자가 날짜를 저장할 때 해당 행만 처리한다.

## 검증

- 관련 135개 테스트 통과.
- 전체 168개 파일, 2,420개 테스트 통과.
- 린트와 TypeScript 검사 통과.
- 상태를 보존하는 DB 모형으로 실제 PATCH와 초대 로그인 핸들러를 연속 호출하여, 기존 오류 → 기한 저장 → 동일 회원으로 반복 로그인 → 만료 시 거절을 확인했다. 운영 회원을 대신 로그인하지 않았다.
- 실제 React DOM에서 기한 저장 후 사용됨 표시와 회수 버튼 제거를 확인했다.
- 운영 빌드 통과.
- 운영 DB의 대상 행을 읽기 전용으로 다시 확인하여 같은 프로그램의 승인된 멘티·다른 초대 연결 없음·요청 날짜의 연장 가능·회원 기존 기한 보존 조건이 모두 참임을 확인했다.
