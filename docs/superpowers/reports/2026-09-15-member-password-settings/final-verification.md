# 회원 비밀번호 설정·변경 최종 검증.

사용자 요청에 따라 본인 `/profile`의 회원정보 수정 아래에 비밀번호 설정·변경 폼을 추가했다. 초대코드 가입 멘티는 유효한 본인 초대코드 또는 현재 비밀번호로 확인할 수 있다. 다른 회원은 현재 비밀번호로 확인한다. 기존 초대코드 로그인과 회원·프로그램·프로젝트 연결은 유지한다.

작업 기준 커밋은 `bd96476`이다. 제품 구현은 `3f75112`, 프로그램 종료 경합 보완은 `55ce0a7`, 실제 DB 통합 테스트는 `d0575b2`와 `393ee63`에 기록했다. 관리자에 의한 타인 비밀번호 재설정과 데이터 모델 변경은 포함하지 않았다.

## 독립 검토와 수정.

구현자 외 검토자가 요구사항 충족, 코드 결함, 경계 조건을 각각 읽기 전용으로 검토했다. 프로그램 PATCH로 종료일이 과거로 바뀌어도 사용자 세션 버전이 유지되는 경합이 확인되었다. 주 작업자가 실제 관리자 API로 재현하고 현재 비밀번호 방식에도 초대·프로그램 이용 기한 스냅샷 조건을 적용했다. 역할이 변경된 회원은 조회한 실제 역할로 조건을 비교하므로 초대 확인의 멘티 전용 조건을 강제하지 않는다.

최초 기능 RED는 주 작업자가 기존 API에서 25개 실패·6개 통과를 확인했다. 추가 경합은 최종 API를 보관하고 `f2339a5`의 이전 API로 일시 교체하여 주 작업자가 독립적으로 재확인했다. 1개 테스트에서 상태 200, 해시 변경, 세션 버전 증가, 쿠키 발급의 네 단언이 실패했다. 최신 파일을 그대로 복원한 후 같은 통합 파일 10개 테스트가 모두 통과했다.

## 실제 브라우저 검수.

로컬 운영 빌드에 별도로 생성한 가상 멘티·멘토 계정만 사용했다. 멘티 사용자 정보에서 초대 확인 기본 선택, 현재 비밀번호 확인으로 전환, 각각의 필수 입력 오류를 확인했다. 비밀번호 폼을 조작해도 작성 중 회원정보가 보존되었다. 멘토 사용자 정보에는 현재 비밀번호 필드가 나타나고 초대 확인 선택지는 나타나지 않았다. 카드 배치도 스크린샷으로 확인했다.

브라우저 도구는 새 인증정보 입력 전에 사용자에게 조작을 맡기도록 요구한다. 따라서 브라우저에서 새 비밀번호를 입력하거나 저장하지 않았다. 저장 성공·실패와 입력 초기화는 DOM 테스트로, 실제 비밀번호 변경·재로그인·세션은 격리 DB의 실제 API로 검증했다. 이를 운영 브라우저 비밀번호 변경 성공으로 주장하지 않는다.

검수 탭은 닫지 않고 서비스 로그인 화면으로 이동한 뒤 유지 표시했다. 로컬 서버를 종료할 때 PID만으로 종료하는 명령은 자동 승인 검토에서 거절되어, 현재 명령줄·실행 파일·부모 PID까지 다시 일치하는 것을 확인한 뒤 해당 검수 서버만 종료했다. Codex 프로세스와 다른 창을 종료하지 않았다.
