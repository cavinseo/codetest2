# 미완료 작업 후속 검수 결과

검수일은 2026-09-10이다. 기존 작업 브랜치 `codex/mentee-mentor-approval`에서 빌드 복구와 격리 환경 검수를 완료했다. 운영 DB 변경, main 병합, 운영 배포는 아직 완료하지 않았다.

## 수정 결과

- `docx`를 9.5.1로 고정했다. 기존 잠금 파일의 9.7.1은 `ImageRun`의 `super` 호출 변환 중 Next 빌드 오류를 일으켰다. 동적 로딩과 기존 `transpilePackages` 설정은 유지했다.
- `technical_benchmarks`에 RLS를 활성화하는 별도 후속 마이그레이션을 추가했다. 이 테이블은 서버 Prisma 인가로 접근하며 공개 Data API 정책은 열지 않는다.
- 실제 PostgreSQL과 실제 세션 인가를 쓰는 멘토링 통합 검수 5건을 추가했다.
- 프로그램 매니저 화면 안내의 “프로그램 개설”을 “담당 프로그램 관리”로 수정했다. 프로그램 개설 버튼이 관리자에게만 제공되는 기존 권한과 문구를 일치시켰다.

## 운영 적용 대기 사항

운영 DB의 기존 적용 이력은 11개이며 다음 4개가 남아 있다.

1. `20260908000000_add_technical_benchmark`.
2. `20260908120000_worksheet_manual_revenue`.
3. `20260910190000_mentee_mentor_approval`.
4. `20260910193000_secure_technical_benchmarks`.

매출 마이그레이션은 사용자가 이미 승인한 기존 2·3차년도 매출 초기화를 수행한다. 그 외 기존 행이 보존되는지 적용 전후 건수·해시로 검증하도록 준비했다. 운영 데이터가 검수 도중 변경되면 비교 차이를 별도로 확인해야 한다.

자동 승인 검토는 운영 환경변수 내보내기, 원본 매출값 백업, 건수·해시 보관을 각각 거절했다. 거절된 작업은 실행되지 않았으며 우회하지 않았다. 현재 사용자에게 요청한 승인은 **원본 값 없이 테이블별 건수·비교용 해시만 임시 보관**하는 범위다. 환경변수나 원본 금액 내보내기 승인을 요청한 것은 아니다.

사용자 승인 후 건수·해시 검증, 운영 마이그레이션, main 병합·푸시, Vercel 운영 배포 및 응답 확인 순서로 이어간다. DB 스키마가 준비되기 전에 새 앱을 운영 배포하지 않는다. 마지막 확인된 원격 main은 `43d6b945b3df303fae31bb92add7de8a3b365ed1`이며 작업 브랜치에는 기존 결과보고서와 멘토링 작업을 포함한 선행 29개 커밋이 있다. 병합 직전에 원격 상태를 다시 확인해야 한다.

빌드 로그는 저장소 밖 `C:/Users/Public/Documents/ESTsoft/CreatorTemp/finalize-build.log`에 있다. 운영 배포 성공이나 운영 데이터 보존 완료를 이 보고서의 로컬 검수 결과로 대신 주장하지 않는다.
