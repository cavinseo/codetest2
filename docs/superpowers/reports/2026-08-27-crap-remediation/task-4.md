### Q-1. `getKanoTopic` 이 설문 문항을 깨뜨린다

`lib/utils/korean-utils.ts` 의 어미 제거 패턴이 일부 입력에서 조사를 남긴다.

```
"초기 설정이 빨랐으면 좋겠다"  ->  "초기 설정이 빨랐으"
```

`/(었|였|했)으면 좋겠다$/` 는 "빨**랐**으면" 의 `랐` 을 잡지 못하고, 다음 패턴인
`/면 좋겠다$/` 가 걸려 `으` 가 남는다. 결과적으로 응답자에게는 이렇게 보인다.

```
만약 "초기 설정이 빨랐으"(이)라면 어떻게 느끼시겠습니까?
```

고객요구사항을 "~면 좋겠다" 로 적는 것은 요구사항 표에서 흔한 표현이라 실사용에서
드러날 가능성이 높다. `korean-utils.ts` 소관이고 이 Task 범위 밖이라 고치지 않았고,
깨진 문자열을 테스트에 고정하면 오히려 굳어지므로 **픽스처는 정상 문구로 잡았다.**

### Q-2. 빠진 답변이 진짜 "무관심" 과 구분되지 않는다

```ts
functional: ANSWER_MAP[functionalAnswer] || 'NEUTRAL',
```

응답에 해당 질문이 없거나 보기 문자열이 매핑에 없으면 `NEUTRAL` 로 채워진다. 그런데
`NEUTRAL`("아무런느낌이 없다")은 응답자가 실제로 고를 수 있는 값이다. 즉 **조회 실패와
진짜 무관심 응답이 결과에서 구분되지 않고**, 그대로 Kano 집계에 들어간다.

질문 수가 홀수인 폼에서도 같은 일이 일어난다. 마지막 쌍의 부정 질문 ID 가 `undefined`
라 조회가 실패하고 `NEUTRAL` 이 채워진다. 현재 동작을 테스트로 고정해 뒀다.

집계 신뢰도에 직접 닿는 문제라 판단을 요청한다. 고친다면 매핑 실패를 `null` 로 두고
호출자가 그 응답을 건너뛰게 하는 방향이 자연스럽지만, `KanoResponse` 스키마와
집계 로직까지 함께 봐야 해서 별도 Task 가 맞다.
