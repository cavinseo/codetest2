# 관리자 삭제 무반응 개선

## RESULT

관리자 회원 삭제의 추가 확인을 브라우저 기본 확인창 대신 앱의 마지막 확인 단계에서 표시한다. 삭제 요청 중에는 처리 중 표시와 버튼 비활성화를 제공한다. 서버가 삭제를 거절하거나 통신이 실패하면 확인창을 유지하고 오류를 표시한다.

검수 중 이름이 없는 초대 회원이 회원 목록의 `toLowerCase` 호출을 실패시키는 결함을 재현했다. 이름의 nullable 타입을 반영하고 이름 미등록 표시와 이메일 기반 삭제 대상 안내를 추가했다.

## 검토와 성공 기준

- 관리자 간 삭제 자체는 기존 API가 허용한다. 본인·마지막 관리자 보호, 담당 프로그램의 FK 제한은 유지한다.
- 운영에서 관리자 계정은 3개이며, 한 계정이 프로그램 5개와 프로젝트 1개에 연결되어 있음을 개인정보 없이 확인했다. 최근 DELETE 응답은 400·409였다. 특정 삭제 대상은 확인되지 않았으므로 그 요청의 정확한 서버 차단 사유는 단정하지 않는다.
- 추가 확인 응답에서 창이 사라지지 않고, 프로젝트 삭제 영향을 표시해야 한다.
- 확인 단계에서 뒤로 가면 확정 플래그를 보내지 않아야 한다.
- 삭제 거절·통신 오류가 확인창 안에 남고 버튼이 다시 활성화되어야 한다.
- 이름을 입력하지 않은 회원도 목록을 중단시키지 않아야 한다.

## FILES CHANGED

- `components/admin/MembersTab.tsx`. 이름 미등록 회원 표시.
- `tests/admin-members-render.test.ts`, `vitest.config.ts`. 실제 React 서버 렌더링 회귀 테스트와 JSX 변환 설정.

## VERIFIED BY

- 이름이 없는 회원으로 운영 방식의 로컬 브라우저에서 `Cannot read properties of null (reading 'toLowerCase')`를 재현했다.
- 동일 회귀 테스트는 수정 전 실패, 수정 후 통과했다. 테스트 실행 전 JSX preserve 설정으로 발생한 변환 오류는 현재 Vite의 Oxc 자동 JSX 설정으로 해결했다.
- 관련 회원 렌더·삭제 API 테스트 19개 통과.
- 최종 전체 테스트 127개 파일, 1,500개 통과.
- `npx tsc --noEmit`, 수정 파일 `npx next lint` 통과.

- 최종 `npm run build` 통과.
- 실제 로컬 프로덕션 브라우저에서 이름 미등록 회원을 포함한 회원 목록 표시 확인.
- 프로젝트 소유 테스트 관리자 삭제의 첫 요청에서 앱 내부 마지막 확인과 프로젝트 1개 경고 표시 확인. 뒤로 이동 후 재요청해도 마지막 확인을 건너뛰지 않음.
- 로그인한 테스트 관리자 본인 삭제 요청의 400 사유가 확인창에 남음을 확인. 실제 계정 삭제 없음.
- 로컬 서버를 종료한 후 요청하여 통신 오류 안내와 버튼 활성화 복구 확인.
- 개발 모드는 기존 CSP가 eval을 차단하므로 프로덕션 빌드로 브라우저 검수했다. 보안정책을 완화하지 않았다.

## 범위와 한계

계정·프로젝트 삭제 정책과 DB 스키마를 변경하지 않았다. 운영 계정을 삭제하거나 프로그램을 임의로 이관하지 않았다. 프로그램 담당 계정은 기존 정책대로 이관 전 삭제가 차단되며, 이번 변경은 그 사유와 추가 확인을 볼 수 있게 한다.
