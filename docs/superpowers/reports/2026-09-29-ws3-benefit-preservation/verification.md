# WS-3 고객니즈 추가 시 제공혜택 보존.

## 원인과 수정.

- 같은 세분시장에서 제공혜택 문구가 같으면 고객니즈와 무관하게 칸이 병합됐다. 위에 추가한 새 니즈의 혜택이 아래 행과 같아지면 아래 입력칸이 숨겨졌다.
- 병합된 제공혜택을 편집할 때 해당 행 전체를 변경하므로, 새 니즈의 혜택을 고치면 기존 니즈의 혜택도 덮어썼다. React DOM 재현 테스트 두 건이 수정 전 이 증상으로 실패했다.
- 같은 세분시장과 같은 고객니즈 안에서 연속된 동일 혜택만 병합하도록 제한했다. 고객니즈가 비어 있는 행은 혜택을 개별 표시한다.
- 같은 고객니즈의 기존 병합, 행 ID, 저장 순서와 API는 유지했다. 데이터 마이그레이션 및 운영 데이터 변경은 없다.

## 검증.

- 재현 테스트 두 건이 수정 후 통과했다. 신규 니즈의 혜택 표시, 기존 행의 값, 저장 요청과 다시 불러온 화면을 확인했다.
- 고객니즈 경계, 미입력 니즈, 같은 니즈의 연속 행 병합에 대한 단위 검증을 추가했다.
- `npm run lint`, `npm run test` 187개 파일·2,800개 테스트, `npm run build`, `git diff --check`가 통과했다.
- 로컬 프로덕션 빌드를 Chrome에서 실행했다. 새 니즈 추가, 혜택 동일 문구 입력, 수정·삭제, 저장·새로고침을 검증했다. 같은 니즈에 속하는 기존 두 행은 병합을 유지했다. 브라우저 오류는 없었다.
- 브라우저의 모든 API 요청에 임시 응답을 제공했다. 임시 저장 1회, 실제 운영 저장 0회이다. 결과는 `temp_files/ws3-benefit-browser/result.json`, 화면은 `temp_files/ws3-benefit-browser/benefits-visible.png`에 있다.

기준 커밋은 운영 배포본 `9ec9d49`이며, 수정 브랜치는 `codex/fix-ws3-benefit-preservation`이다. 이번 작업에서 배포는 수행하지 않았다.
