# 개요 관련이미지 업로드 개선.

## 변경 내용.

- 개요의 `제품 이미지`를 `관련이미지 올리기`로 변경했다.
- `제품 이미지와 BM(비즈니스 모델) 이미지를 최대 3개까지 올려 주세요.` 안내를 추가했다.
- PNG/JPEG 여러 파일 선택, 기존 목록에 추가, 개별 삭제, 현재 개수 표시를 지원한다. 3개가 차면 선택 입력을 비활성화하며 초과 선택은 기존 이미지를 보존하고 안내한다.
- 전체 선택 파일이 최적화와 검증을 통과해야 목록에 반영한다. 처리 중 저장·취소·삭제와 중복 선택을 막는다.
- 개요 API도 최대 3개, 각 이미지 형식·크기·치수를 검증한다. 기존 단일 이미지는 첫 이미지로 읽으며, 새 목록의 첫 이미지를 기존 필드에도 기록한다. 빈 목록으로 삭제한 이미지를 되살리지 않는다.
- 개요의 관련이미지들은 결과보고서에 순서대로 들어간다. 기존 단일 이미지와 중복되지 않는다.

## 저장 구조와 배포 순서.

- `projects.relatedImages` 선택 JSONB 필드를 추가했다. 기존 이미지 필드는 삭제하거나 일괄 변환하지 않는다.
- 프로젝트는 Prisma 마이그레이션을 사용하므로 기존·신규 Prisma 모델의 `migrate diff`로 `20260928180835_overview_related_images` SQL을 생성했다.
- 운영 배포 전에 이 마이그레이션을 적용해야 한다. 이전 WS-3 수정 `effae1e` 위의 `codex/overview-related-images-20260929` 브랜치에 이번 변경을 별도 커밋으로 둔다.
- 운영 DB 마이그레이션과 운영 배포는 이번 작업에서 수행하지 않았다.

## 검증 결과.

- 관련 API·개요 화면·보고서 테스트 53개가 통과했다. 3개 저장·조회, 네 번째 거절, 기존 이미지 호환, 잘못된 이미지, 읽기 권한, 삭제 후 재열기, 보고서 3개 반영을 포함한다.
- 전체 린트, 187개 파일·2,812개 테스트, 프로덕션 빌드, Git diff 공백 검사가 통과했다.
- 로컬 PostgreSQL의 임시 테이블에 생성된 마이그레이션을 실행했다. 기존 단일 이미지가 보존되고 JSONB에 세 이미지를 순서대로 저장·조회하는지 검사한 뒤 롤백했다. 실제 운영 DB에 접속하거나 데이터를 쓰지 않았다.
- 로컬 프로덕션 화면을 Chrome에서 실행하고 실제 PNG 파일 선택 및 Canvas 최적화를 확인했다. 기존 이미지에 두 장 추가, 3개 제한, 저장·새로고침, 개별 삭제·재추가, 전체 삭제·새로고침이 통과했다. 브라우저 오류는 없었다.
- 브라우저 API는 임시 응답으로 검증했다. 임시 저장 3회, 운영 저장 0회이다. `temp_files/overview-images-browser/result.json`과 `three-images.png`에 결과를 남겼다.
- DB 검증 기록은 `temp_files/overview-images-db.log`, 전체 검사 로그는 `temp_files/overview-images-{lint,tests,build}.log`에 있다. 사용한 로컬 웹 서버와 DB 테스트 서버는 종료했다.
