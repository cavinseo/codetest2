# 결과보고서 양식 분석 — 절별 데이터 출처 매핑

원본: `아이템개선 프로그램(KS-QFD)결과 보고서 ver5.pdf` (16쪽, Ⅰ~Ⅴ 5개 절).
사용자가 2026-09-08 첨부. 이 문서는
`docs/superpowers/plans/2026-09-08-final-report.md` 의 **Task 0** 산출물이다.

## 양식의 실체 — 가장 중요한 발견

이 PDF 는 Word 문서가 아니라 **PowerPoint 슬라이드를 인쇄한 것**이다. 각 쪽에 공통으로:

- 좌상단 "CONTENTS" 탭 모양 장식과 우상단 대각선 회색 띠(슬라이드 마스터 장식)
- 로마숫자 절 번호가 든 진회색 알약 배지(Ⅰ~Ⅴ)
- 쪽 하단 중앙에 작은 원 안 페이지 번호
- 표가 페이지 폭 전체를 쓰는 가로형(4:3 또는 16:9) 레이아웃

이런 요소는 Word 의 표준 페이지 서식이 아니라 **파워포인트 슬라이드 마스터의 전형적인
장식**이다(정부·창업지원 프로그램 결과보고서에서 흔한 형태). 계획서 초안은 `docx` 를
가정했지만, 이 양식을 그대로 재현하려면 **`.pptx`** 가 맞을 가능성이 크다.

→ **아래 "결정 필요" 절 1번 참조. 이 결정이 Task 1 이후 기술 스택(라이브러리·좌표계)을
전부 바꾼다.**

## 절별 매핑 표

기호: **DB** = 기존 스키마 필드로 바로 채울 수 있음(표/텍스트, 신규 캡처 불필요) ·
**IMG** = 화면을 그림으로 캡처해야 함(관계·그래프 시각화가 복잡해 표로 재현하기 어려움) ·
**GAP** = 앱에 저장할 자리가 없음, 이번에 새로 만들거나 화면에서만 즉석 입력해야 함

| 1 | 표지 | 제목·기업명·작성일·코치명 | DB | `Project.name`, 사용자 소속 조직/이름, 생성일. "코치명"은 멘토 배정 — `ProjectMember` role=MENTOR 조회 필요(현재 개요 API 에 없음, 추가 조회 필요) |

## 결정 필요 (사용자 확인 대기)

1. **⚠️ 출력 형식: `.pptx` 인가 `.docx` 인가?** 위 "양식의 실체" 참조 — 원본이 파워포인트
   슬라이드 인쇄본이라 그대로 재현하려면 `pptxgenjs` 류로 바꿔야 한다. `.docx` 로 하면
   Kano 설문지 선례를 재사용할 수 있지만 슬라이드 특유의 장식(대각선 띠·배지)은 포기하고
   내용 중심의 보고서로 다시 디자인해야 한다.
2. **속성 적합도(6쪽)·QFD 관계도(10쪽)를 표로 재현할지, 화면 캡처로 넣을지** — 데이터는
   있지만(FitnessMatrix, QFDMatrix) 병합 셀·기호(◎○△)·배지가 있어 표로 완전히 똑같이
   그리려면 손이 많이 간다. 기본안은 **화면 캡처(IMG)**.
3. **"최종 목표 스펙 설명"(11쪽)을 어디서 입력받나** — `TargetSpec` 에 필드를 추가할지,
   보고서 화면에서 그때그때 입력받아 DB 저장 없이 문서에만 넣을지.
4. **KS-QFD 개선 방향성(12쪽)과 WS-13 의 열 이름이 안 맞는다** — WS-13 을 이 절 전용으로
   고칠지, 이 절만 화면 캡처로 대신할지.
5. **자금 비교 그래프(13쪽)를 이번에 만들지** — 만들면 신규 차트 컴포넌트가 하나 늘어난다.
   범위에서 빼고 표만 넣는 안도 있다.
6. **GAP 4개(제품 이미지, 시장정의/목표고객, 개선 제품명/설명)를 어디에 저장하나** — 기본안:
   `Project` 모델에 새 필드 4~5개를 추가(마이그레이션 필요, 사용자가 적용) 하거나, 보고서
   생성 화면에서 즉석 입력받아 **DB 에 저장하지 않고 그 문서에만** 반영(마이그레이션 불필요,
   대신 재생성할 때마다 다시 입력).
7. **"코치명"(멘토)** — `ProjectMember` 에서 role=MENTOR 인 사람을 찾으면 되는지, 프로그램
   매니저(`Program.managerId`)를 쓰는지 확인 필요.
