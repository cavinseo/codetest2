# report.pdf 결과보고서 양식 검토.

## 기준 원본과 검토 범위.

- 원본은 `public/asset/report.pdf`이다. 2026-09-27에 PDF 전체 5면과 진단표의 삽입 이미지를 확인했다.
- A4 가로 5면에 세로 페이지 10쪽이 두 쪽씩 배치되어 있다. 문서 구성은 표지와 Ⅰ~Ⅳ장이다.
- 기존 2026-09-08 양식 정의의 16쪽, Ⅰ~Ⅴ장과 다르다. 새 양식 적용 시 과거 매핑을 그대로 사용하면 항목이 추가되거나 누락된다.
- 출력은 기존 사용자 결정인 Word(.docx)를 유지하는 것을 전제로 한다. PDF와 동일한 2쪽 모아찍기나 장식의 완전한 복제는 아직 확정하지 않았다.
- 이 문서는 원본 검토와 확정된 구성의 적용 기록이다. 신규 진단표는 입력 위치가 미정이며, 새 양식 전체의 구현이나 배포가 완료되었다는 의미가 아니다.

## 신규 진단표의 항목.

원본의 표현을 보존하되 화면에서 띄어쓰기를 정리할 수 있다. 응답하지 않은 문항을 ‘아니요’로 간주하면 안 된다.

| 번호 | 진단항목 | 진단 내용 | 응답 |

| 1 | 인식정도 진단 | 5배 매출 경쟁자를 인식되었는가? | 미응답·예·아니요. |

| 3 | 경쟁자진단 | 5배 매출 경쟁자를 이길 스펙을 가지고 있다고 생각하는가? | 미응답·예·아니요. |

개선 방향의 서술 항목은 다음과 같다.

1. 5배 경쟁자 이름과 전년도 매출액.

3. 경쟁자 대비 우위를 위한 제품개선항목. 경쟁자의 강점 스펙과 창업자 관점에서 제공할 수 있는 스펙을 설명한다.

## 확정된 추가 구성과 남은 선택 사항.

2026-09-27 사용자 지시로 WS-15·16·17을 포함한다. 새 PDF의 Ⅰ~Ⅳ장 뒤에 `Ⅴ. 자산 및 자금계획`을 두고 핵심자산·보완자산·자금소요계획·자금조달계획과 각 멘토 분석을 출력한다. 결과보고서의 워크시트 출처는 총 14개이다.

신규 진단표를 결과보고서의 멘토 입력으로 둘지, 별도 워크시트로 둘지는 아직 답변을 기다린다. 이 선택에 의존하는 입력 기능은 변경하지 않는다.

기존 제품 이미지와 Kano 수치 집계표는 보충 정보로 유지한다. 제품속성표는 새 PDF의 여섯 열을 사용하고, 고객요구사항의 열 순서와 WS-11의 순위 열, WS-12 설명의 위치를 원본에 맞춘다. 워크시트 원본 필드를 삭제하지 않는다.

## 구현 시 데이터 보존과 검증 기준.

1. 저장된 초안과 완료본을 자동 변환하거나 덮어쓰지 않는다. 사용자가 새 양식으로 재생성하는 시점에 새 구성을 적용하고 기존 교정 교체 안내를 유지한다.
2. 보고서 출력 대상에서 제외하더라도 기존 워크시트 원본과 저장된 멘토 분석은 삭제하지 않는다.
3. 진단 입력은 배정 멘토와 실제 멘토로 배정된 프로그램 매니저의 작성 권한을 따른다. 관리자의 초안 열람과 멘티의 완료본 열람도 유지한다.
4. 신규 입력이 없는 기존 초안을 계속 읽고 저장할 수 있어야 한다. 저장 후 재조회, 미응답과 ‘아니요’의 구분, 버전 충돌, 재생성 후 값 보존을 검증한다.
5. 문서 모델과 DOCX에서 Ⅰ~Ⅳ장 및 표의 열·순서·진단 응답이 맞는지 확인한다. 미리보기의 수정·저장·완료 흐름도 검증한다.
6. 페이지 수를 고정하려고 행이나 분석 내용을 잘라내지 않는다. 실제 데이터 길이에 따라 페이지가 늘어날 수 있다.
7. 코드 변경 후 관련 테스트와 전체 lint·test·build를 실행한다. 레이아웃 변경 시 샘플 출력물을 렌더링하여 표 잘림과 페이지 넘김을 확인한다. 운영 DB에 테스트 데이터를 쓰지 않는다.

## 2026-09-27 확정 범위 적용 결과.

- `lib/final-report-document.ts`에 새 표지·장 제목, 제품속성표의 여섯 열, 고객요구사항의 열 순서, 개선포인트의 순위 열을 반영했다. WS-12 항목별 설명을 스펙 표 앞으로 옮겼다.
- WS-15를 `Ⅴ. 자산 및 자금계획`으로 옮겨 WS-16·17과 함께 출력한다. 여덟 워크시트의 기존 멘토 분석은 유지한다.
- 문서 모델과 Word 직렬화 테스트를 수정해 새 순서와 자산·자금 분석의 보존을 확인했다. 저장된 완료본과 초안을 변경하는 DB 작업은 하지 않았다.
- 관련 테스트는 8개 파일, 259개가 통과했다. 전체 `npm run test`는 184개 파일, 2,764개가 통과했다.
- `npm run lint`와 변경 파일의 `git diff --check`가 통과했다.
- `npm run build`는 첫 실행에서 페이지 생성 후 `.next/export` 정리의 EBUSY 파일 잠금 오류가 발생했다. 같은 명령을 다시 실행하여 성공했다. 빌드에는 운영 DB 대신 로컬 더미 접속 주소를 환경 변수로 지정했다.
- Word 검증은 생성된 DOCX 내부 문서 구조와 텍스트 순서를 검사했다. 실제 Word 렌더링의 페이지별 시각 검수는 아직 수행하지 않았다.
- 신규 진단표는 입력 위치 결정 전이며 미구현이다. 운영 배포는 수행하지 않았다.
