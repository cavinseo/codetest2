## 5. 실행 계획 — 독립 디렉터리

BM 계획서 §3 의 결론을 요약한다. 세부 절차와 Task 0 추가 사항은 계획서 Task 0 이 정본이다.

1. **디렉터리.** `E:\Dropbox\coding-1\business plan\bm`(사용자 결정 2026-10-11) 에 origin 의 **독립 clone** 을 두고 `feat/bm-service` 를 `origin/main` 에서 `--no-track`
   으로 딴다. worktree 가 아닌 이유는 `.git` 이 Dropbox 동기화 안에 있기 때문이다(계획서 §3.5).
2. **첫 커밋.** 이 문서를 포함한 계획·설계·프롬프트 문서 6건을 파일 단위로 옮겨 첫 커밋으로 둔다. `CLAUDE.md` 의 BM 디렉터리
   예외 문단(결정 3)도 같은 커밋에 넣는다. push 는 결정 7(공개 저장소에 올릴 내용)·결정 8(Vercel Preview) 뒤에 사용자가 한다.
3. **개발 DB.** 로컬 PostgreSQL 16(설치·실행 확인됨)에 앱용 DB 와 통합테스트용 DB 를 따로 만든다. `.env` 는
   그 둘만 가리키고 `.env.local` 은 두지 않는다. 운영 `.env` 는 복사하지 않는다.
4. **기준선 게이트.** 새 디렉터리에서 `npm ci` → `npx prisma generate` → `npx prisma migrate deploy`(개발 DB) →
   시드 → 게이트 3종 기록.
5. **M1부터.** Task 1(레지스트리·플래그·가드) → Task 2(스키마) → Task 3~6(접점·골격). M1 은 플래그가 꺼진 채
   main 에 병합할 수 있다.
6. **운영 반영.** 마이그레이션 먼저, 코드 다음, 플래그는 마지막(계획서 §9).

위임 프롬프트는 `docs/superpowers/prompts/2026-10-04-bm-service/` 에 둔다. `session-start.md` 가 독립
디렉터리에서 실행 AI 의 첫 세션을 여는 착수 프롬프트(바이브코딩 규약 포함)이고, `task-<번호>.md` 가 Task 별
위임 프롬프트다. 위임 방식은 종전과 같다: Task 단위로 실행 AI 에 위임하고, 보고서는
`docs/superpowers/reports/2026-10-04-bm-service/task-<번호>.md` 에 남기며, 감리자가 게이트와 표본을 직접 확인한다.
