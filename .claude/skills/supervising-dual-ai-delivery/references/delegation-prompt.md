# 위임 프롬프트 템플릿

`<>` 자리는 `CLAUDE.md`(또는 `AGENTS.md`)에서 읽어 **원문 그대로** 채운다.
요약하면 실행 AI 가 자기 판단으로 메운다.

---

## 공통 머리 — 모든 Task 프롬프트 앞에 붙인다

줄이고 싶은 유혹이 들지만 줄이지 마라. 이 네 절 중 하나가 빠질 때마다 반려가 한 번
늘어난다.

```
[환경 제약 — 위반 시 즉시 중단]
<CLAUDE.md 의 환경 제약을 원문 그대로>
- 예: .env 의 <DB URL 변수>는 실데이터가 있는 원격 DB 다.
- 절대 금지: <금지 명령 목록>, dev 서버 기동(신설·수정 라우트라도 실기동 검증하지 않는다).
- 안전: <허용된 명령>
- 실기동 검증이 필요하다고 판단되면 하지 말고 QUESTIONS 에 적어 올린다.
- <비밀정보 취급 규칙>

[저장소 관례]
<CLAUDE.md 의 저장소 관례를 원문 그대로>
- 커밋 메시지 언어와 트레일러
- 들여쓰기, 주석 언어와 문체
- 새 소스 파일의 머리 주석 규칙
- 테스트 배치와 mock 규칙
- 계획서 체크박스를 갱신해 코드와 같은 커밋에 담는다

[게이트 — 전부 통과해야 완료다]
    <게이트 명령>
- <추가 검사가 있으면: 인코딩 검사, mutation 등>
- CI 가 작업 브랜치에서 자동으로 도는지 여부를 적는다. 안 돈다면 게이트를 어떻게
  확인했는지 VERIFIED BY 에 적게 한다.

[산출물·보고]
작업을 마치면 보고서를 채팅이 아니라 저장소 파일로 남긴다.
  <보고서 경로 규칙>
형식은 아래 그대로 쓴다.
  RESULT          — 무엇이 달라졌는가. 표로 이전/이후를 대비시킨다.
  FILES CHANGED   — Add/Modify/Delete 로 구분한 파일 목록
  COMMIT          — 작업 커밋 해시와 제목
  VERIFIED BY     — 각 게이트의 실행 명령과 출력 마지막 줄을 원문 그대로
  DEVIATIONS      — 계획서와 다르게 한 것과 그 이유
  RISKS           — 남은 위험
  QUESTIONS       — 감리자 판단이 필요한 것
보고서는 작업 커밋과 별도의 둘째 커밋으로 남긴다 (<보고서 커밋 제목 규칙>).
작업 커밋 해시가 보고서 본문에 들어가야 하므로 순서를 바꿀 수 없다.
두 커밋 뒤 git status 는 깨끗해야 한다.
```

## Task 블록

```
<계획서 경로> 의 "Task <식별자>" 절을 읽고 그대로 수행하라.
아래는 그 절의 요지와, 반드시 지켜야 할 제약이다.

[문제]
<증상부터 쓴다. 사용자가 무엇을 보는가.>
<그 다음 원인. 파일:줄 을 붙인다.>
<관련 코드를 3~10줄 인용한다. 실행 AI 가 파일을 열기 전에 감이 오게.>

[할 일]
1. <파일> — <무엇을>
   - <판단이 갈리는 지점은 이유까지 적는다>
   - <직접 확인해야 할 것이 있으면 "직접 읽어 확인하라"고 쓴다>
2. <파일> — <무엇을>
3. <테스트 파일> — 최소 아래를 단언한다.
   - <단언 1>
   - <단언 2>
   - <경계·실패 경로도 넣는다>

[하지 말 것]
- <비슷하지만 고치면 안 되는 곳과 그 이유>
- <고치면 안 되는 기존 테스트를 이름까지>
- <지금은 과설계인 추상화>
- <환경 제약이 금지한 검증>

[커밋]
<제목 한 줄>
본문에 왜를 적는다 — <무엇을 적어야 하는지 두세 가지>.
```

## 자주 빠뜨리는 것

**"직접 읽어 확인하라"를 안 썼다.** 프롬프트에 적은 사실이 틀렸을 수 있다. 판단의
전제가 되는 사실은 실행 AI 가 스스로 확인하게 한다. 그러면 감리의 실수도 거기서 걸린다.

**정답 구현을 안 가리켰다.** 같은 문제를 이미 푼 파일이 있으면 설계를 설명하지 말고
그 파일·줄을 주고 "그 구조를 옮겨라"라고 쓴다.

**둘을 함께 넣어야 하는 이유를 안 썼다.** 하나만 하면 더 나빠지는 쌍이면,
"둘 중 하나만 온 커밋은 반려한다"고 명시한다.

**판정 표본을 안 정했다.** 위임할 때 "이 보고서를 받으면 무엇을 먼저 볼 것인가"를
정해 두면, 판정이 인상이 아니라 확인이 된다.

## 판정 표본 표 — 위임과 함께 만든다

Task 별로 한두 줄이면 충분하다.

```
| Task | 1순위 판정 표본 |
| --- | --- |
| A | <함께 넣기로 한 변경이 같은 커밋에 있는가. 없으면 반려> |
| A | <잘못된 입력이 막히고 파괴적 동작이 호출되지 않는 단언이 있는가> |
| B | <금지한 테스트 파일이 수정되지 않았는가. 수정됐다면 범위를 넘긴 것> |
| B | <위험한 경우가 여전히 막히는가> |
| 공통 | VERIFIED BY 에 게이트 출력의 마지막 줄이 원문으로 있는가 |
| 공통 | 작업 커밋과 보고서 커밋이 둘로 나뉘고 git status 가 깨끗한가 |
```
