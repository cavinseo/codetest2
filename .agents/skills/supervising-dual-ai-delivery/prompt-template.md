# 위임 프롬프트 템플릿

실행 AI는 이 프롬프트만 보고 작업한다(감리 대화를 볼 수 없다). 절 제목을 그대로 쓰고,
해당 없는 절은 통째로 빼라 — 절 안의 내용만 비우는 것은 금지(빠진 것이 보이지 않는다).
`{…}`는 감리자가 채우는 슬롯이다.

```
[역할]
너는 {프로젝트}의 {검사|수정|기능 개발|마무리} 담당 엔지니어다.
{읽기 전용 여부: 검사면 "소스·스키마·설정을 수정하지 말고 리포트 1개만 작성한다"}
{선행 문서: 이번 작업의 근거가 되는 SPEC·검사 리포트 경로 — "먼저 정독하라"}

[배경 — 검증된 사실이니 재조사하지 마라]
{감리자가 직접 확인한 좌표: 원인 파일:라인, 참조 구현 위치, 재사용할 기존 계약}
{알려진 잠복 지점: "이 코드는 실행된 적이 없다" 등}

[용어·규칙]
{프로젝트 금지어·불변 계약 — 프로젝트 지침 파일에서 복사}

[확정된 계약 — 감리자 승인, 이 결정을 따르라]
{이미 내린 설계 결정. 실행 AI가 재결정하면 안 되는 것}
{지시와 기존 계약이 충돌하면: 기존 계약을 따르고 이유를 보고하라}

[작업 내용]
{항목별로: 결함ID/기능명 — 원인 — 위치 — 수정 지침. 검사 리포트와 1:1 대응}
{재량 허용 지점은 여기에 명시 ("~는 판단해서 택하고 근거를 보고하라")}

[환경]
{DB·서비스 기동 전제와 확인 명령, 알려진 함정과 복구 명령 — 프로젝트 지침 파일에서}

[브랜치·커밋]
{분기 기준 커밋과 브랜치명 — 감리자가 확정해서 준다}
{건드리면 안 되는 파일 목록(미추적 등)}
완결 단위마다 즉시 커밋하라.

[작업 방식]
RED → GREEN: 실패 테스트를 먼저 작성하라.
{무회귀 목록: 깨지면 안 되는 기존 테스트·시나리오 수치}

[Ask First — 다음이 필요해지면 중단하고 보고하라]
{범위 밖으로 번지는 신호: 스키마 변경, 도메인 계약 수정, 다른 기술로 전환, …}

[완료 판정 — 전부 만족해야 완료]
{번호 목록. 모든 항목은 제3자가 참/거짓 판정 가능해야 한다.
 "가능하면·적절히·필요시" 금지 — 재량은 작업 내용 절로}
1. {게이트 명령 전부 그린}
2. {신설 실행물을 최소 1회 실제 실행}
3. {UI 관련 시: 실화면에서 해당 조작이 동작}
n. {배포는 하지 마라 — 검증·배포는 감리자가 수행한다}

[산출물·보고]
- 코드 + 테스트 {+ 문서} (커밋 완료 상태)
- {보고서 경로} 작성: 항목별 구현 근거(파일:라인), 테스트 결과 원문 요약,
  지시와 다르게 처리한 사항과 그 이유, 남은 리스크
- 마지막에 RESULT / VERIFIED BY / FILES CHANGED / RISKS 형식으로 보고하라.
  VERIFIED BY에는 실행한 명령과 결과 수치를, RISKS에는 검증하지 못한 것을 쓴다 —
  하지 않은 것을 했다고 쓰지 마라.
```

## 절별 존재 이유 (감리자용 — 프롬프트에 넣지 않는다)

| 절 | 막는 실패 |
|---|---|
| 배경(좌표 주입) | 실행 AI의 탐색 실수·추측·중복 조사 |
| 확정된 계약 | 감리 결정의 무단 재결정 |
| Ask First | 조용한 범위 확장; 재량과 일탈의 경계 |
| 완료 판정(판정 가능) | 자의적 완료 선언; soft 조건의 증발 |
| 보고 형식(RISKS 필수) | 과장 보고; "못 한 것"의 은폐 |
| 브랜치·커밋 | 작업트리 오염; 미커밋 유실 |
